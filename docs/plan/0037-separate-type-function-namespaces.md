# Separate Static and Member Function Namespaces

## Task Description
- **Deliverable:** Give every concrete function-bearing type two independent associated-function namespaces: the ordinary/static namespace selected by `Type::name` and the member namespace selected explicitly by `Type::self::name`. A receiverless static function and a receiver-bearing member function may therefore use the same name and the same effective machine signature without redeclaration, overload, lookup, or linker-symbol collision. `Type::name` must never resolve a member function; `Type::self::name` must never resolve a static function.
- **Purpose:** Make the source spelling communicate whether a type-qualified function reference is static or requires a receiver, while allowing an unbound member function pointer to be acquired without constructing an instance solely to name the function. Preserve Omega's no-hidden-behavior model: taking `Type::self::name` captures no receiver, allocates nothing, creates no closure/thunk, and performs no ABI adaptation.
- **Chosen direction:** Treat static/member as an explicit **semantic lookup namespace**, selected from the resolved receiver mode. The parser/HIR grammar does not need a new node: current paths already admit `MyStruct::self::do_thing`, and leading `self::...` remains the unrelated module anchor. Resolve the owner type first, then interpret a two-segment tail `self::<name>` as the member namespace. Keep declaration-order storage where body checking/emission needs it, but centralize namespace classification/lookup so no semantic path searches a mixed set and then rejects the wrong receiver kind after selection.
  - `Type::name` selects only receiverless functions.
  - `Type::self::name` selects only functions whose declaration has `self`, `mut self`, `*self`, or `*mut self`.
  - Instance syntax `value.name(...)` remains member-only and keeps its existing implicit receiver adaptation.
  - An acquired member function is an **unbound ordinary function value**. Its callable value type uses the already-resolved leading receiver parameter as an explicit first parameter, clears declaration-only `self_mode`, and clears the synthetic parameter name `self` so diagnostics/rendering use ordinary function-type syntax rather than pretending the pointer still has an implicit receiver. For example, `do_thing(*self) => void` on `MyStruct` is exposed by `MyStruct::self::do_thing` as `(*MyStruct) => void`. `*mut self` becomes `*mut MyStruct`; by-value receivers become an explicit `MyStruct` parameter. Calling the pointer, or directly calling `MyStruct::self::do_thing(&value)`, supplies that receiver explicitly and performs no auto-borrow/auto-deref receiver adaptation.
  - Namespace separation also participates in generated symbol identity. Under normal Omega mangling, receiver-bearing functions gain a nested value-path segment `::self::` before the function name; receiverless functions keep their existing associated-function path. The signature still carries the real ABI parameter types. This deliberately changes member-function symbols so a static and member function with identical ABI signatures cannot collide across separate compilation.
  - Apply the behavior to concrete implementation owners covered by the existing function rules: structs, unions, named enums, markers, primitive blocks, and concrete conformance implementations reached through a concrete type. Aliases work automatically after resolving to such a type. Anonymous enums have no declaration-owned functions and remain unaffected.
- **Rejected alternatives:**
  - Do not make `Type::name` contextually fall back to a member when no static exists; that recreates the ambiguous contract the feature is intended to remove.
  - Do not encode a bound receiver or synthesize a thunk/adapter for a member pointer. The existing HIR lowering already materializes the receiver as the first real function parameter, so the raw code address is directly callable once that receiver is explicit.
  - Do not split every declaration-order `Vec` into duplicated static/member storage merely to mirror the source namespaces. Preserve one ordered declaration list where source pairing is required and make namespace selection an explicit reusable semantic operation instead.
  - Do not add a new `omega-mangle` grammar tag solely for this distinction. A normal nested value path named `self` is already representable, round-trippable, and source-like; the MIR mangling adapter should construct the new path.

## Technical Details
- **Initial context boundary:**
  - `docs/language/functions.md`, `docs/language/structs-and-unions.md`, `docs/language/strings-casts-arrays-and-slices.md` — normative associated-function, overload, and function-value rules.
  - `docs/architecture/semantic-analysis.md`, `docs/architecture/symbol-mangling.md`, and `docs/architecture/testing-and-validation.md` — semantic ownership, linker identity, and validation boundaries.
  - `compiler/omega-analyzer` owns namespace lookup, overload selection, member/static diagnostics, and the first-class callable type exposed by a path.
  - `compiler/omega-driver` supplies primitive/conformance and generic-owner facts to the analyzer.
  - `compiler/omega-mir::mangle` owns the final associated-function linker path. `omega-codegen` must remain a consumer of the decided function address/signature and should not implement this distinction.
- **Affected files/symbols:**
  - `compiler/omega-analyzer/src/resolved_type.rs` — add one reusable static/member classification vocabulary/helper around `ResolvedMethod` / `ResolvedFunctionType`, and replace the misleading aggregate-only `ResolvedType::declared_methods()` surface with namespace-aware access. Add a single helper for the **function-value view** of a method: statics are unchanged; members retain the resolved leading receiver type as parameter 0, expose `self_mode: None`, and blank the HIR-synthetic `self` parameter name when used as an unbound first-class function value. Parameter names are not type identity, and this keeps `Display`/diagnostics spellable as an ordinary `(*Owner, ...) => R` function type.
  - `compiler/omega-analyzer/src/analysis/items/mod.rs::{check_overload_duplicates, collect_methods}` — compare duplicate/overload candidates only inside the same namespace. Preserve the existing `AmbiguousSelfOverload` rule among member functions: receiver spelling alone must not become an overload selector for ordinary `value.method(...)` calls. Static/member pairs are never compared against each other, even if their parameter lists are identical.
  - `compiler/omega-driver/src/primitives.rs::instantiate_primitive` and `compiler/omega-analyzer/src/analysis/specs.rs::check_conform_block` — both already reuse `check_overload_duplicates`; keep that shared rule so primitive/conformance implementations receive the same namespace independence rather than acquiring a second duplicate checker.
  - `compiler/omega-analyzer/src/analysis/paths.rs::{resolve_type_qualified_value, resolve_generic_args_place, resolve_type_member, unique_overload_signature_match}` — make type-qualified value lookup namespace-aware. Resolve the owner before interpreting the tail; `[name]` is static, `[self, name]` is member, and deeper tails remain invalid. Enum variants are considered only in the ordinary one-segment namespace, never underneath `::self::`. Pass the expected type through explicit-generic-owner lookup as well, and select an uncalled overload using the candidate's first-class function-value type. A member-only name referenced as `Type::name` should diagnose the new spelling (`Type::self::name`) rather than exposing/selecting the method and later rejecting it. Conversely, `Type::self::name` should report a static-only sibling with the ordinary spelling when useful.
  - The `self` segment is contextual, not globally reserved. `Type::self` by itself may still name an existing static function/enum variant literally called `self`; only the shape `Type::self::<member>` activates the member namespace. This also leaves leading module-relative `self::...` paths untouched.
  - `compiler/omega-analyzer/src/analysis/places/mod.rs::find_methods` and `compiler/omega-analyzer/src/analysis/calls/mod.rs` — make ordinary instance lookup request member candidates directly instead of collecting static and member functions together and filtering later. Preserve field shadowing, visibility, bound-conformance scope, implicit receiver adaptation, and the existing `StaticFunctionOnInstance` diagnostic by probing the static namespace only for that diagnostic when no member applies.
  - `compiler/omega-analyzer/src/analysis/calls/overload.rs::resolve_overloaded_static_call` — generalize this interception into type-function call resolution that understands both `[name]` and `[self, name]`. Static calls use static candidates; explicit member-namespace calls use member candidates and the **full function-value signature including the explicit receiver parameter**. No implicit-self path is used for `Type::self::name(...)`.
  - `compiler/omega-analyzer/src/analysis/calls/generic.rs`, `compiler/omega-analyzer/src/resolver.rs::generic_static_function_signature`, `compiler/omega-driver/src/resolver.rs::generic_static_function_signature`, and the resolver test double in `compiler/omega-analyzer/src/analysis/tests.rs` — make the existing generic-owner call query namespace-aware rather than adding a parallel member-only query. This preserves `GenericType::static(...)` inference and permits the analogous `GenericType::self::member(receiver, ...)` inference when the owner can be inferred. For a member query, rewrite the HIR synthetic receiver's raw `Self` type to the nominal owner applied to its owner generics before running generic inference (generalize the existing `rewrite_self_return` helper, which currently performs this substitution only for returned `Self`). Explicit owners such as `GenericType<i32>::self::member` must also work through `resolve_generic_args_place`. Do not invent new generic-function-as-value inference beyond Omega's existing expected-type/call inference rules.
  - `compiler/omega-analyzer/src/analysis/literals.rs` and any other direct aggregate-function name/similarity probes found while changing the above APIs — use the appropriate static namespace for `Type::...` diagnostics so a member-only name is not suggested as though it were a static function. Do a targeted search for direct `.functions` lookups that participate in call/path resolution; declaration-order body checking/emission loops may remain mixed.
  - `compiler/omega-analyzer/src/error/kind.rs` and `error/render.rs` — replace/augment `MemberFunctionWithoutInstance`-style type-qualified diagnostics so they teach the namespace distinction. Keep `StaticFunctionOnInstance` for `value.static_name(...)`. Generalize `AmbiguousConformanceStatic` if necessary so a concrete `Type::self::name` lookup can report multiple conformance-member providers with the correct fully-qualified alternatives rather than pretending they are statics.
  - `compiler/omega-mir/src/mangle.rs::{method_symbol, primitive_method_symbol, conformance_method_symbol, glued_symbol, extern_function_ref_symbol}` — route associated-function path construction through one helper that inserts a `Namespace::Value` segment named `self` exactly when the declaration `fn_type.self_mode.is_some()`. For inherent functions the identity becomes `Owner::self::name`; for primitive functions `<target>::self::name`; for conformance implementations the `self` segment belongs beneath the existing target/spec owner path. `extern_function_ref_symbol` must use the identical helper so separately compiled references and definitions agree. Static symbols remain byte-for-byte on their previous path.
  - `compiler/omega-mir/src/mangle.rs` tests — add adapter/round-trip and inequality coverage proving a static and member function with the same owner/name/ABI signature encode to different symbols, and that member definition/reference construction agrees. The standalone `compiler/omega-mangle` encoder/decoder should not require a grammar change because the new discriminator is an ordinary nested value segment.
  - `docs/language/functions.md` — define the two namespaces, overload domains, `Type::self::name`, and direct/unbound pointer-call semantics. `docs/language/strings-casts-arrays-and-slices.md` should state that taking a member address yields the same one-address code pointer with an explicit receiver parameter and no adapter; this is distinct from declaration receiver metadata used for ordinary method-call adaptation. Update `docs/language/structs-and-unions.md` and `docs/guide/quick-reference.md` only enough to point users at the common rule/examples rather than duplicating it.
  - `docs/architecture/symbol-mangling.md` — replace the current statement that receiver shape is distinguished only by the leading receiver type. Document that member/static namespace is now part of the path **in addition to** the signature's real receiver parameter, and record this as an ABI/separate-compilation symbol migration.
- **Interfaces/invariants:**
  - Namespace selection is semantic and happens only after the prefix is known to be a type; module resolution and leading `root`/`self`/`super` anchors keep their existing meaning.
  - Within each namespace, existing overload rules remain unchanged. An uncalled overloaded reference needs an expected ordinary function type selecting exactly one candidate. A static and member function never participate in the same overload set.
  - Inherent/primitive functions keep their current precedence over conformance-provided functions, but **only inside the selected namespace**. A static inherent `foo` must not hide a conformance member `foo` from `Type::self::foo`, and a member inherent `foo` must not hide a conformance static `foo` from `Type::foo`.
  - Visibility/reveal authorization is checked on the selected declaration exactly as before. The new namespace is not a visibility bypass.
  - Ordinary instance calls continue to adapt `self` according to receiver mode. Type-qualified member pointers do not; their receiver is a normal explicit argument.
  - The member function value is the original code address. No closure object, bound receiver, allocation, hidden copy, trampoline, or calling-convention adapter is introduced. LLVM/codegen requires no namespace-specific behavior.
  - Normal mangling guarantees static/member linker distinction. Explicit forced mangling remains an intentional user override and may still create a collision; do not add a compatibility alias or dual symbol export.
  - This is intentionally an ABI break for normally mangled receiver-bearing functions. Definitions, extern references, generic weak instantiations, and conformance/primitive references must all use the new identity deterministically across processes.
- **Out of scope:**
  - Do not redesign `Spec::function(...)` / `<Type : Spec>::function(...)` dispatch syntax or dynamic spec-object vtable calls. Specs are contracts/dispatch qualifiers, not concrete implementation addresses acquired by this type-function path feature.
  - Do not change gaps/glue source semantics beyond whatever symbol helper reuse is required to keep an existing concrete receiver-bearing glued function's definition/reference identity consistent.
  - Do not redesign function-type syntax containing `self_mode`, receiver adaptation rules, or function-pointer casts generally. The only new type-boundary rule is the ordinary explicit-receiver function-value view exposed when a concrete member implementation is taken by address.
  - Do not change parser/HIR path grammar, add a new AST node for the namespace, or reserve `self` as an identifier globally.
- **Risks/open questions:** None requiring product/design input. If implementation discovers a function-bearing concrete owner whose addressable implementations bypass all of the inherent/primitive/conformance paths above, stop and extend the same namespace abstraction rather than special-casing that owner.

## Implementation Plan
1. In `omega-analyzer`, introduce the explicit static/member namespace classifier and the centralized method-to-function-value conversion. Update aggregate namespace accessors first, while preserving ordered declaration storage for body checking. Add focused Rust tests for classification and for member value normalization (`self_mode` removed, resolved receiver parameter retained).
2. Change `check_overload_duplicates` to ignore cross-namespace pairs while keeping all same-namespace duplicate and `AmbiguousSelfOverload` behavior. Let struct/union/enum/marker, primitive, and conform-block collection continue to consume that single checker. Add analyzer/driver component coverage for the formerly rejected pair whose static explicit `*Type` parameter matches the member's synthetic `*self` parameter exactly.
3. Refactor `resolve_type_member` into namespace-selected candidate lookup rather than first-match lookup. Thread `expected` through `resolve_type_qualified_value` and `resolve_generic_args_place`, admit `Type<...>::self::name`, normalize member candidates to their unbound function-value type, and use expected function type to select uncalled overloads. Preserve enum variant handling only for ordinary `Enum::Variant`; make `::self::` contextual only when another segment follows. Update namespace-specific diagnostics and visibility/conformance ambiguity handling at the same time.
4. Make ordinary `value.method(...)` lookup member-only at its source (`find_methods` / call resolution) so static/member separation is enforced consistently in both directions. Retain a static-namespace probe solely to produce `StaticFunctionOnInstance` when that is the helpful diagnosis; do not feed statics into the member overload set.
5. Generalize `resolve_overloaded_static_call` into namespace-aware type-function call resolution. `Type::name(args...)` considers static overloads; `Type::self::name(receiver, args...)` considers member overloads using the unbound full parameter list and performs an ordinary function call with no implicit receiver. Reuse the same namespace candidate helpers as uncalled path resolution so call and pointer acquisition cannot drift.
6. Generalize the `generic_static_function_signature` resolver contract and `analysis/calls/generic.rs` flow to carry the namespace selector. Preserve the existing static behavior; for member queries, generalize `omega-driver/src/resolver.rs::rewrite_self_return` into a reusable recursive `Self`-to-`Owner<generics...>` rewrite and apply it to the synthetic receiver parameter before argument inference. Then update the driver implementation plus analyzer resolver test double. Ensure explicit generic owner paths can carry the extra `self` segment without the current `GenericPathTooDeep` rejection.
7. Audit the remaining direct `.functions` / `.methods` probes in analyzer path/call diagnostics (including enum literal similar-function reporting) and convert only semantic lookup sites to the shared namespace API. Leave ordered body checking, dead-code walks, extern collection, and emission iteration mixed where namespace selection is not being performed.
8. In `omega-mir::mangle`, add one associated-function path constructor that inserts the nested value `self` segment for receiver-bearing declarations, and make inherent, primitive, conformance, glued, and extern-reference symbol construction reuse it. Do not modify LLVM/codegen or create a second symbol. Add mangling adapter tests before changing expectations elsewhere so the new ABI identity is explicit and round-trips through `omega-mangle`.
9. Update the normative/user-facing documentation and `docs/architecture/symbol-mangling.md` with the settled namespace, pointer, overload, contextual-`self`, and ABI rules. Do not preserve the old `Type::member` behavior as a compatibility fallback: after this change that spelling is statics-only by definition.
10. Add the focused root conformance packages, run them through real compile/link/execute, then run the broader analyzer/driver/MIR tests and full repository gate. Include a separate-compilation symbol test/workflow because the mangled member path is a cross-process contract, not merely a single-invocation semantic change.

## Testing
- **New/changed cases:**
  - Add `tests/t29_type_function_namespaces/` as the positive language-conformance case. At minimum prove on a struct that `static same(other: *Thing)` and `same(*self)` with the same name/effective ABI signature coexist; `Thing::same` captures/calls the static function; `Thing::self::same` captures/calls the member function; `thing.same()` still chooses the member; and direct `Thing::self::same(&thing)` uses an explicit receiver. Give both captured values an explicit ordinary function type so the first-class member value normalization is observable.
  - In the same positive case, cover independent overload sets (static overloads do not affect member overloads and vice versa), expected-type selection for an uncalled overloaded pointer, explicit generic owners such as `Box<i32>::self::method`, and representative union, named-enum, marker, and existing primitive member acquisition (for example an exposed `char` member) so the rule is not accidentally struct-only. Include an alias to one of the nominal types to prove namespace interpretation happens after type resolution.
