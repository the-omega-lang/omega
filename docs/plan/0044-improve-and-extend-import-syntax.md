# Import Trees, Renaming, and Scoped Reveal

## Task Description
- **Deliverable:** Extend Omega imports with local renaming (`as`), recursive brace-group import trees, per-node `reveal` inheritance, and a group-local `self` leaf that imports the module/prefix currently being referenced.
- **Purpose:** Improve import ergonomics while preserving Omega's existing import resolution, visibility, collision, macro, and unused-import semantics. The new syntax must remain compile-time-only structure: it introduces no runtime behavior and no second name-resolution mechanism.
- **Chosen direction:** Model the source syntax as an **import tree**. A tree node may opt into `reveal`; that capability is inherited by every descendant leaf. Terminal leaves become ordinary import bindings, `as` changes only the local bound name, and `self` creates a terminal binding for the current tree prefix. Because macro environments consume imports from raw AST before HIR exists, keep one parser-owned structural traversal/flattening path that both raw macro lookup and HIR lowering can consume. HIR is the stable flat representation: one `HirImport` per terminal binding, carrying the full target path, explicit bound name, effective `reveal`, leaf span, and inherited source-item annotations.
- **Rejected alternatives:** Do not implement rename through declared `alias`; import renaming must not gain alias visibility/re-export semantics. Do not keep brace trees in the driver/analyzer/resolver. Do not make `as` a globally reserved lexer keyword. Do not restrict `reveal` to the whole import statement: it is intentionally scoped to any subtree. Do not introduce a notion of hidden/visible physical modules to justify reveal inheritance; physical modules have no visibility modifier, and inheritance is simply the lexical scope of the import-tree bypass.

- **Interfaces/invariants:**
  - `import thing::Thing as ImportedThing;` resolves `thing::Thing` and claims only `ImportedThing`. `Thing` is not also introduced locally.
  - A grouped import is an ordered tree of prefixes and terminal bindings. For example, `import thing::{ First, Second as Two, sub::{ Third, Fourth as Four } };` is semantically equivalent to four independent imports of `thing::First`, `thing::Second as Two`, `thing::sub::Third`, and `thing::sub::Fourth as Four`, in that textual leaf order.
  - Groups are recursive; a named group entry extends the current prefix. `as` is terminal-only: an interior prefix cannot itself be renamed unless it is also imported through a `self` leaf.
  - Inside a group, `self` means **bind the current prefix itself**. `import thing::{ self, Thing };` therefore imports module/path `thing` under its ordinary final name and also imports `thing::Thing`. `import thing::{ self as TheModule };` binds that same current prefix as `TheModule`. `self` here is an import-tree leaf operation, not a new general `Path` segment or anchor rule.
  - The special `self` leaf is only valid inside a brace group and is terminal (optionally followed by `as <identifier>`). Existing leading `self::` remains the ordinary explicit path anchor. Do not reinterpret standalone `import self;` or change general path grammar.
  - Root/group prefixes continue to use the existing import path rules: unprefixed imports are top-level-by-default, while `root::`, `self::`, and chained `super::` remain explicit anchors. A brace group must attach to a prefix representable by the existing import `Path` shape; this task does not introduce anchor-only zero-segment prefixes such as `import self::{...}`/`import root::{...}`. Anchored grouped forms such as `import self::thing::{...}` remain valid.
  - `reveal` is allowed on the root import tree and on any group entry, including a terminal leaf. Effective reveal for a leaf is the logical OR of every `reveal` written on the path from the root to that leaf. A revealed subtree therefore deliberately “contaminates” all leaves below it until that subtree ends.
  - Example equivalence: `import reveal abc::{ A, sub::{ B, C } };` produces the same effective visibility bypass as separate `import reveal abc::A;`, `import reveal abc::sub::B;`, and `import reveal abc::sub::C;`. `import abc::{ reveal A, B };` reveals only `A`. `import abc::{ reveal sub::{ A, B }, C };` reveals `sub::A`/`sub::B` but not `C`.
  - Intermediate tree nodes do not themselves create imports. `reveal` on an intermediate prefix therefore means only “all descendant leaves inherit the bypass”; it does not imply that the physical module prefix has visibility. Physical modules have no visibility modifier. If a resulting terminal binding names a target for which reveal is semantically unnecessary, the existing semantics simply make the bypass redundant; do not add module-visibility special cases.
  - `reveal self` inside a group is legal and follows the same inheritance rule. Whether that bypass is useful depends on what the completed prefix resolves through; do not special-case it in the parser/HIR.
  - Redundant nested reveal is legal: `import reveal thing::{ reveal A };` still yields one revealed leaf. No new hard error is needed; a future unnecessary-reveal lint may handle redundancy if desired.
  - Every terminal leaf is independent for target resolution, explicit-name collision, failed-import name reservation, unused-import tracking, and diagnostics. A failed leaf still claims its **bound name**, and failure of one sibling must not suppress or merge the others.
  - Source-order collision behavior must be the same as spelling the leaves as separate import statements. HIR leaf order must therefore be deterministic textual depth-first order. Leaf-specific spans should be used so a duplicate alias or failed grouped member points at the relevant entry, not only the entire outer statement.
  - Module-scope claims use the local bound name. `import m::Thing as Other; struct Thing { ... }` is legal; any later explicit declaration/alias/import also claiming `Other` is a redeclaration. Two leaves in one group that bind the same local name collide at the later leaf.
  - Imported modules, module aliases, declared aliases, generic templates, overload sets, functions/types/specs, and macros retain their target identity; `as` only changes the importing module's lookup key.
  - Imported macros follow the same bound-name rule in the separate macro namespace. `import defs::shout as yell;` makes `yell$()` the explicit macro binding and must also let a raw macro alias target resolve through `yell` before HIR exists.
  - Existing `ImportState` identity `(module, local import name)`, use tracking, and resolver capability propagation remain the right semantic model once HIR carries the explicit bound name/effective reveal. Do not teach `omega-driver::resolver` about brace syntax.
  - Import annotations remain attached to the syntactic source import and apply to every flattened leaf because this feature adds no per-leaf annotation syntax. In particular, `@suppress(unused_import)` on a grouped import suppresses the warning for each leaf emitted from that item.
  - `as` remains a contextual word. It is consumed only in the import-tree connector position and remains a valid identifier elsewhere; paths/items actually named `as` and an alias target name spelled `as` must continue to parse where unambiguous.
- **Out of scope:** Glob imports (`*`), prefixless heterogeneous groups such as `import {a::A, b::B};`, per-leaf annotations, import-based re-export, changes to declared `alias`, a visibility model for physical modules, changing ordinary path/anchor resolution, MIR/codegen/runtime/ABI changes, or generalized use of the import-tree `self` marker outside brace groups.
- **Risks/open questions:** No language-design blocker remains. The main implementation risk is semantic drift between the pre-HIR macro environment and HIR/ordinary imports; one shared AST leaf traversal must define path concatenation, local-name derivation, reveal inheritance, and leaf order for both. A second risk is imprecise source spans after one syntax item becomes several HIR imports; preserve per-leaf spans rather than assigning the full statement span to every generated binding.

## Implementation Plan
1. **Specify the import-tree grammar and semantics first.** Update `docs/language/modules-and-imports.md` and `docs/language/grammar.md` with standalone rename, recursive groups, terminal `self`, optional terminal aliases, trailing commas, and inherited subtree `reveal`. State explicitly that physical modules do not gain visibility and that reveal inheritance is lexical scope over produced import leaves. Add `as` to the contextual-keyword documentation in `docs/language/lexical-structure.md`. Keep existing top-level-by-default and anchor semantics unchanged.
2. **Make the parser represent the syntax tree without semantic resolution.** Extend `ImportStmt` and `parse_import` so the root and nested entries preserve `reveal`, relative path pieces, leaf aliases, `self`, source order, and spans. Reuse existing `parse_path`/`PathAnchor` behavior for the root prefix instead of creating a competing import-anchor parser. Parse named nested entries as relative suffixes of the current prefix; reject an `as` followed by a group, a non-terminal `self`, empty groups, and other malformed brace structures through parser diagnostics.
3. **Centralize syntax-only leaf expansion in the parser/AST layer.** Add one traversal on the parsed import syntax that recursively appends nested suffixes to the root `Path`, carries `effective_reveal = inherited || local`, emits `self` as the current prefix, derives the local name from `as` or the terminal target/prefix segment, and yields leaf spans in textual depth-first order. This is a structural view only: it must not resolve packages/modules/items or check visibility. Use this exact traversal from every pre-HIR consumer rather than reimplementing tree walking.
4. **Flatten imports into stable HIR bindings.** Extend `HirImport` with the explicit bound name. In `Lowerer::lower_item`, iterate the shared import leaves and emit one unique `HirImport`/`HirId` per leaf with the full target `Path`, local bound name, effective reveal, leaf span, and cloned/lowered source-item annotations. Add focused HIR tests proving nested ordering, `self`, aliases, and reveal inheritance. Do not carry group nodes past HIR.
5. **Switch ordinary module indexing to explicit local names.** In `compiler/omega-driver/src/modules.rs`, make `claimed_name` return `HirImport`'s bound name and make `index_imports` store the original target under that same local key. Preserve the existing two-phase invariant: all leaves claim names during the shared source-order claim pass before any import target is resolved; only winning leaves are target-resolved afterward. Keep `ImportEntry`, `ImportState`, resolver lookup, visibility capability propagation, and unused-use bookkeeping flat and keyed by the local name.
6. **Teach the raw macro environment the exact same flattened bindings.** Replace the current assumption that one raw `ImportStmt` binds its target's final segment. Raw macro-alias target lookup must search flattened import leaves by local bound name and resolve the leaf's original target/effective reveal. `macro_env` must consider every macro-valued leaf of a group in leaf source order, including renamed leaves, and collision diagnostics must use the leaf binding name/span. Preserve macro definition provenance, body, visibility, and builtin discriminator; only the local invocation binding changes.
7. **Update user/architecture documentation.** Add concise `as`, recursive group, `self`, and scoped-reveal examples to `docs/guide/quick-reference.md`. In `docs/language/visibility.md`, replace/clarify the current `import reveal lib::hidden_module;` example so it does not imply physical modules have visibility; demonstrate a hidden item and explain that reveal on an import tree applies to descendant terminal imports. Record in `docs/architecture/parsing-and-hir.md` that import trees are syntax-shaped/raw-macro-visible but normalize to flat HIR leaves, and in `docs/architecture/module-driver-and-linkage.md` that raw macro import binding uses the same parser-owned leaf traversal as HIR.
