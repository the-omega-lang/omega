# Panic Handler Gap and Builtin Location Macros

## Task Description
- **Deliverable:** Add Omega's portable panic contract to `core`: an exposed allocation-free `PanicInfo`, a `PanicHandler` gap with a `shared` non-returning handler function, an exposed source-defined `panic$` macro as the ordinary source entry point, and compiler-implemented `file$()`, `line$()`, and `column$()` macros declared by `core`.
- **Purpose:** Give invariant failures, deliberately unreachable branches, `unwrap`-style APIs, and other unrecoverable conditions one platform-agnostic handoff that works equally on hosted and freestanding/embedded targets while preserving useful source location and message data. The mechanism must not require libc, allocation, exceptions/unwinding, a runtime registry, or backend-specific lowering.
- **Chosen direction:** Keep panic policy in the existing `gap`/`glue` model. `PanicInfo` contains `source_file: *str`, `line: u32`, `column: u32`, and `message: *str`; `PanicHandler::panic` receives `*PanicInfo` and returns `never`, avoiding an aggregate-by-value ABI/copy and allowing the macro to pass a stack-local record whose lifetime is sufficient because the call cannot return. `panic$()` uses `""`; `panic$(message)` stores the caller's `*str`. Do not add formatting or allocation in this task.
- **Chosen direction:** Treat `file$`, `line$`, and `column$` as ordinary exposed macro declarations in a new `core::builtins` module whose empty bodies are compiler-recognized implementations. Only those canonical declarations are builtin; a same-named user macro remains an ordinary macro, and aliases of a canonical builtin preserve builtin behavior. Builtins expand during the existing parser macro phase to ordinary literals, so HIR/MIR/codegen never need intrinsic cases.
- **Chosen direction:** Extend gap **function** declarations to carry visibility. Existing gap functions default to `exposed` so current gaps remain source-compatible; `shared` means callable from the same top-level package, and `hidden` means the exact declaring module. Glue matching is not a call and ignores this call-site visibility, so an external platform/application may still implement a `shared` core gap function.
- **Chosen direction:** Preserve the existing rule that an exposed macro cannot accidentally leak a narrower dependency, but allow a macro to make that transfer deliberately with a definition-authored `reveal`. The analyzer must require the `reveal` and the narrower path to carry the **same macro-expansion origin**. Thus `reveal` written inside `core`'s `panic$` can intentionally wrap `PanicHandler::panic`, while caller-side `reveal panic$()` still cannot authorize a macro's private dependency.
- **Chosen direction:** No default `PanicHandler` glue belongs in `runtime/plat/libc`. The final application/platform chooses panic behavior (print-and-exit, trap, reset MCU, blink LED, etc.). As with existing gaps, a program that emits no reference to the panic symbol must not need panic glue.
- **Rejected alternatives:** Do not expose the raw panic gap function merely to make the macro compile; that defeats the API boundary. Do not globally weaken macro dependency visibility or hardcode a one-off "panic macro may access private things" exception; use origin-checked definition-site `reveal`. Do not make the whole `panic$` macro compiler intrinsic; only the source-location primitives need compiler knowledge. Do not add optional macro-parameter grammar solely for this feature: use the existing trailing variadic capture to encode zero-or-one message and add a compile-time/no-runtime arity guard so two or more messages are rejected rather than silently using the last one.

## Technical Details
- **Initial context boundary:** Start with `runtime/core/`, `compiler/omega-parser`, `compiler/omega-hir`, `compiler/omega-analyzer`, and the macro/module integration in `compiler/omega-driver`. Normative docs are `docs/language/gaps-and-glue.md`, `docs/language/macros.md`, and `docs/language/visibility.md`; implementation invariants are in `docs/architecture/parsing-and-hir.md` and `docs/architecture/runtime-and-platform.md`; Omega source syntax is in `docs/guide/quick-reference.md`. `omega-diagnostics::SourceFile` is an existing consumed interface for source names and line/column calculation, not a second location algorithm to duplicate.
- **Affected parser/macro sites:** `compiler/omega-parser/src/parser/item/definitions.rs::{SpecMemberVisibility, parse_spec_function, parse_gap_def}` currently rejects visibility on gap functions. `compiler/omega-parser/src/ast/item.rs::MacroDefinitionStmt`, `compiler/omega-parser/src/macros.rs::{ExpansionState, expand_with_origins, collect_definitions}`, and `compiler/omega-parser/src/macros/expander.rs::Expander` own macro definition metadata and expansion. Extend macro-definition metadata with a template-vs-builtin discriminator and bind the builtin kind from the canonical `(defining module, declared name)`, using one shared binding path for both `collect_definitions` and `Driver::module_macros` so raw own definitions cannot overwrite a differently classified cached definition.
- **Builtin declaration contract:** The canonical compiler-backed declarations are exactly `core::builtins::{file,line,column}` and must be `exposed`, zero-argument macros with empty template bodies; report a focused macro/declaration error if the runtime source violates that compiler/core contract. `file$()` expands to `TokenKind::Str(SourceFile::name())`. `line$()` and `column$()` expand to explicitly typed `u32` numeric literals from `SourceFile::line_col(call_span.start)`, with checked `usize -> u32` conversion rather than truncation. The location is 1-based and uses the same Unicode/tab display-column semantics as diagnostics. The file string is exactly the compiler's existing source name; path remapping/reproducible-build rewriting is separate work.
- **Call-site invariant for nested macros:** `Expander::substitute_invocation` already assigns the outer invocation span to macro-authored generated tokens while origin metadata separately preserves definition-site lookup. Keep that invariant. A `file$`/`line$`/`column$` invocation written inside `panic$` must therefore observe the `panic$` invocation's span, not the byte position of the builtin invocation in `runtime/core/panic.omg`. Direct builtin calls observe their own invocation span.
- **Source context plumbing:** `Driver::ensure_ast` already stores `Rc<SourceFile>` per module in `ModuleStore::sources`, and `Driver::parse_module` calls `omega_parser::macros::expand_with_origins`. Pass the current module's `SourceFile` into macro expansion rather than teaching `Span` file identity or recomputing file/line data elsewhere. The parser-only convenience expansion path may carry no source context for ordinary template tests; invoking a compiler-backed builtin without source context must fail explicitly rather than fabricate a location.
- **Macro aliases/shadowing:** `Driver::module_macros` / `bind_macro_aliases` clone macro definitions; preserve the builtin discriminator through aliases so an alias of `file$` still expands at the alias invocation site. Keep existing lookup precedence: a local/imported same-named ordinary macro may shadow the ambient core builtin because builtins are core declarations, not unparented reserved compiler names.
- **Reveal-origin sites:** `compiler/omega-parser/src/ast/expression.rs::RevealExpr` and `parser/expression.rs::parse_unary` currently discard the `reveal` token's origin; `compiler/omega-hir/src/hir.rs::HirExpr::Reveal` and `lower/expression.rs` likewise keep only the operand. Preserve the reveal keyword's `Origin` through AST and HIR. In `compiler/omega-analyzer/src/analysis/visibility.rs::RevealState`, track `(origin, used)` per frame; update `strip_reveal`, `with_reveal_bypass`, and `with_reveal_operand` so place-analysis bypasses retain the exact origins rather than only a nesting depth. Ordinary visibility bypass keeps current behavior; macro dependency transfer may consume only a reveal frame whose origin equals the dependency path's macro origin.
- **Macro dependency rule:** `compiler/omega-analyzer/src/analysis/mod.rs::check_macro_dependency_visibility` currently rejects dependencies narrower than the effective macro visibility independent of `reveal`. Refactor the check so a known declaration visibility can be checked directly, then reuse it for gap members. A narrower dependency is legal only when an active definition-site reveal has the same expansion origin as the path; caller-origin reveals never satisfy this rule. Preserve the existing negative coverage in `compiler/omega-driver/tests/macro_hygiene.rs`.
- **Gap representation/resolution:** Add visibility to `compiler/omega-hir/src/hir.rs::HirGapFunction` and populate it in `compiler/omega-hir/src/lower/item.rs`. Add the same fact to `compiler/omega-analyzer/src/resolved_type.rs::GapFunction` in `analysis/items/mod.rs::signature_of_gap`. `analysis/paths.rs::resolve_gap_member` must receive enough written-path/accessor provenance to check the selected function against `path_module(path)` (important for definition-site macro hygiene), honor an active ordinary `reveal`, and apply the macro dependency rule using the function's own visibility. Do not treat a gap function's visibility as part of its ABI/signature or glue conformance identity.
- **Runtime source:** Add `runtime/core/builtins.omg` with only the three empty exposed builtin declarations. Add `runtime/core/panic.omg` with exposed `PanicInfo`, `gap PanicHandler { shared panic(info: *PanicInfo) => never; }`, and exposed `panic$`. The macro initializes `message` to empty, fills it once when one variadic message argument is present, and tail-calls the gap through a definition-authored `reveal` so the macro expression itself has type `never`. Use a hygienic `comp` binding inside the repetition as a zero-runtime arity guard: zero/one message compiles; a second repetition redeclares the guard and is rejected. Document this as a temporary consequence of Omega not having optional macro parameters; do not narrate it in a source comment.
- **Interfaces/invariants:** `PanicInfo` and all fields must be exposed because glue may live in a different package. The handler pointer is read-only. Panic never unwinds and never returns. The compiler does not allocate, format, print, abort, trap, or choose a platform policy. No new backend intrinsic, runtime registry, global mutable state, libc symbol, or mandatory object is introduced. Existing gap symbols/linkage and separate-compilation behavior stay unchanged.
- **Out of scope:** Do not add `unwrap`/`expect`, formatting support, backtraces, function-name metadata, panic recovery/unwinding, or a default hosted handler. Do not rewrite existing compiler-generated invariant sites in this task. In particular, `compiler/omega-mir/src/lower/function/control_flow.rs::lower_match_chain` currently terminates the impossible remainder of an exhaustive `match` with `MirTerminator::Unreachable`; routing that to the new handler is a follow-up because it would introduce an implicit `PanicHandler` link dependency for every emitted exhaustive match and needs a deliberate compiler-generated source-location path rather than duplicating `panic$`'s construction logic in MIR.
- **Risks/open questions:** The requested `shared` boundary is an Omega visibility boundary, not an unforgeable security boundary: source code can explicitly use `reveal` to call a shared declaration. This plan interprets "`panic$` is the only entry" as "the only ordinary/non-`reveal` source API." If raw `PanicHandler::panic` must remain impossible even under explicit `reveal`, stop before implementation and design a stronger compiler-private visibility/capability concept; do not special-case panic. Likewise, if the exhaustive-match invariant fallback is intended to be part of this same task rather than the first follow-up consumer, revise the plan before implementation so its implicit capability/link semantics are designed explicitly.

## Implementation Plan
1. Extend gap-function visibility at the syntax/HIR boundary. In `parser/item/definitions.rs`, give gap functions the ordinary explicit `exposed`/`shared`/`hidden` modifiers but default them to `exposed`; continue rejecting visibility on the gap item itself and on glue declarations/implementations. Thread the parsed visibility through `HirGapFunction`, and update parser/HIR tests before touching semantic lookup.
2. Make gap-member visibility a semantic fact. Store it in `resolved_type::GapFunction` during `signature_of_gap`, then update every `resolve_gap_member` entry path to use the written path's definition-site-aware accessor, reject inaccessible functions with the normal visibility diagnostic, and leave glue signature matching/symbol emission unchanged. Confirm existing unmodified gaps remain effectively exposed.
3. Make `reveal` origin-aware from parser through analyzer. Capture the reveal token origin in `RevealExpr`, preserve it in HIR, replace depth-only reveal tracking with origin-bearing frames, and update place-expression helpers without changing current ordinary bypass/warning behavior.
4. Extend the macro dependency check to support deliberate definition-site capability transfer. Keep the default error when a macro references a declaration narrower than itself; permit it only when the dependency path and an active reveal frame have the same macro-expansion origin. Add the gap-member call to this same visibility-level check so gap functions cannot become a new macro-leak loophole. Verify caller-side reveal still cannot make an otherwise-invalid exposed macro valid.
5. Add generic compiler-backed macro metadata and canonical core binding in `omega-parser`. Classify only the exact `core::builtins` declarations as `file`, `line`, or `column` builtins, validate their zero-argument/empty/exposed declaration shape, preserve the discriminator through macro aliases, and keep all other macros on the existing token-template path.
6. Plumb `omega_diagnostics::SourceFile` into driver-driven macro expansion and implement builtin substitution in `macros/expander.rs`. Emit ordinary string/u32 literal tokens at the invocation span; obtain line/column only through `SourceFile::line_col`. Preserve existing expansion-origin behavior so a builtin nested in `panic$` sees the outer panic call site. Do not add HIR/analyzer/MIR/codegen builtin cases.
7. Add `runtime/core/builtins.omg` and `runtime/core/panic.omg`. Define the exposed panic data contract, the `shared` `PanicHandler::panic(*PanicInfo) => never` requirement, and the exposed hygienic `panic$` wrapper. Use the existing variadic repetition only as zero-or-one optional-message encoding, include the compile-time redeclaration guard for `>1`, and make the revealed handler call the macro's tail expression. Do not add a `runtime/plat/libc` glue.
8. Update the owning documentation with the new behavior: builtin core macros and exact call-site/source-name semantics in `docs/language/macros.md`; gap-function visibility/defaults and glue independence in `docs/language/gaps-and-glue.md`; same-origin definition-site `reveal` capability transfer (and caller-side non-transfer) in `docs/language/visibility.md`; macro source-context/origin plumbing in `docs/architecture/parsing-and-hir.md`; panic as an optional portable gap with no default platform policy in `docs/architecture/runtime-and-platform.md`; and `PanicInfo`/`PanicHandler`/`panic$` usage plus the optional-message macro limitation in `docs/guide/core-library.md`. Update the core layout shown there for the two new modules.

## Testing
- **New/changed parser tests:** Prove gap functions default to exposed and accept all three explicit visibilities while the gap item/glue visibility restrictions remain. Prove canonical builtin declarations validate their required shape, direct `file$`/`line$`/`column$` substitution produces the expected literal kinds, and noncanonical same-named macros remain normal templates. Include invalid builtin arity at invocation.
- **Builtin source-location tests:** Use a synthetic `SourceFile` containing tabs and multibyte text to prove the builtins reuse `SourceFile::line_col`'s 1-based display semantics. Add a wrapper macro whose body invokes `line$`/`column$` and assert the result is the wrapper invocation position, then a nested wrapper equivalent to `panic$` to guard the outer-call-site requirement. Check aliases of a builtin retain builtin behavior at the alias call site.
- **HIR/analyzer/component tests:** Verify gap-member visibility survives lowering/signature resolution; same-package access to `shared` succeeds, cross-package ordinary access fails, default gap members preserve current exposed behavior, and external glue can still satisfy a shared gap function. Extend reveal-state tests for origin-bearing nested frames. In `compiler/omega-driver/tests/macro_hygiene.rs`, keep the existing exposed-macro/private-dependency rejection, add a definition-authored same-origin `reveal` case that succeeds, and add a caller-side `reveal macro$()` case that still fails.
- **Root conformance:** Add `tests/t33_panic_handler/` as an application that supplies `glue core::panic::PanicHandler`, reads the exposed `PanicInfo`, exercises `panic$("...")` as a diverging expression, and terminates from the handler. Keep exact file-path assertions out of the portable output; location precision belongs in the component tests. Ensure `panic$()` with no message also compiles in the package (it need not execute in the same run because the first panic is `never`).
- **Negative conformance:** Add `tests/t33b_panic_handler_errors/` covering an ordinary cross-package direct call to the shared raw handler and `panic$` with more than one message; assert the intended diagnostics rather than merely requiring compilation failure. If non-`*str` panic messages are rejected through the normal assignment/type diagnostic, cover that without adding panic-specific type machinery.
- **Specification trace:** `t33`/`t33b` prove the new `docs/language/gaps-and-glue.md` gap-member visibility rule, `docs/language/macros.md` core builtin/call-site rule, and `docs/language/visibility.md` deliberate definition-site macro transfer rule as exercised by the core panic wrapper.
- **Regression coverage:** Re-run `compiler/omega-driver/tests/macro_hygiene.rs`, parser macro tests, analyzer visibility/path tests, and `tests/t17_gaps_and_glue` to prove existing gap syntax/ABI remains compatible. The existing root suite also proves that merely adding `PanicHandler` to core does not make a panic glue mandatory for programs that never reference it.
- **Commands/target coverage:** Run focused `cargo test` for `omega-parser`, `omega-hir`, `omega-analyzer`, and the relevant `omega-driver` tests; build the core runtime; run `./bin/test-runner t33_panic_handler t33b_panic_handler_errors t17_gaps_and_glue` once artifacts exist; finish with `just test-all`. No backend-specific matrix is required because builtin macros disappear to literals before HIR and the handler remains an ordinary gap call, but the full gate must still prove hosted linking and the no-unused-gap requirement.
