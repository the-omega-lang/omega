# Optional Function-Type Parameter Descriptors

## Task Description
- **Deliverable:** Allow function types to spell each ordinary parameter either as `Type` or `name: Type`, including mixed lists, while keeping parameter names as optional descriptive metadata only. `(i32) => void`, `(a: i32) => void`, and `(b: i32) => void` must have the same function-type identity and be mutually assignable/usable anywhere the same parameter types are required.
- **Purpose:** Remove a non-semantic distinction from function types, support concise function-pointer signatures, and retain optional parameter descriptions for diagnostics/tooling/LSP use without letting those descriptions affect the type system, overload selection, conformance, generic/query identity, ABI, or symbols.
- **Chosen direction:** Separate declaration parameters from function-type parameters instead of overloading the existing required-name `Param` representation. Add a function-type parameter representation with an optional descriptor/name, and carry that metadata through resolution in a dedicated resolved parameter shape whose `PartialEq`/`Eq`/`Hash` depend only on the parameter type. This makes “names are not identity” a representation invariant rather than a collection of compatibility exceptions. Do not use an empty `Ident` sentinel for source-level unnamed parameters.
- **Rejected alternatives:** Do not make declaration parameters optional; function/method/spec/gap/glue parameters are bindings and still require names. Do not solve this only in `ResolvedFunctionType::accepts`; equality/hash/canonical structural keys must agree that renamed/unnamed parameters are the same type. Do not erase names at parse time: a written descriptor remains useful metadata even though it is not identity.

## Technical Details
- **Initial context boundary:** Start in `compiler/omega-parser` (`src/ast/type.rs`, `src/parser/type.rs`, shared declaration-parameter parsing in `src/parser/mod.rs`) and `compiler/omega-analyzer` (`src/resolved_type.rs`, `src/context.rs`, `src/type_key.rs`). Consult `docs/language/functions.md`, `docs/language/grammar.md`, `docs/architecture/parsing-and-hir.md`, and `docs/architecture/types-layout-and-const-eval.md`. `docs/issues/known-issues.md` currently records both limitations this task resolves.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/ast/type.rs`: keep `Param` as the required-name declaration/binding parameter shape; add a distinct function-type parameter shape with optional descriptor metadata and make its structural equality ignore the descriptor. `FunctionType::params` should use this new shape.
  - `compiler/omega-parser/src/parser/type.rs`: `parse_function_type` must parse function-type parameters itself instead of calling declaration-oriented `parse_param_list`. A parameter is named only when the current identifier is followed by `:`; otherwise parse a normal `type`. Preserve receiver syntax and variadic tails.
  - `compiler/omega-parser/src/parser/mod.rs`: declaration `parse_param_decls` / `parse_param_list` remain strict. If receiver recognition needs factoring, use lookahead that commits only to the exact `self` / `mut self` / `*self` / `*mut self` forms; once unnamed type parameters exist, leading `*` may instead begin a pointer type such as `*Thing`.
  - `compiler/omega-parser/src/ast/item.rs`, `src/ast/statement.rs`, `compiler/omega-hir/src/hir.rs`: `function_type()` constructors for declarations must convert binding parameters into function-type parameters with `Some(name)` descriptors. Update `omega-parser::prelude` exports for the new syntax type.
  - `compiler/omega-analyzer/src/aliases.rs` and `src/generics.rs`: alias substitution/normalization and generic unification must recurse through the parameter's type while preserving its optional descriptor unchanged.
  - `compiler/omega-analyzer/src/context.rs`: `Context::resolve_function_type` must resolve each parameter type and carry only the optional descriptor as metadata.
  - `compiler/omega-analyzer/src/resolved_type.rs`: introduce a resolved function-parameter shape (for example `ResolvedFunctionParam { name: Option<Ident>, type: ResolvedType }`) whose equality/hash ignore `name`; let `ResolvedFunctionType` equality/hash therefore depend on parameter types, return type, variadic flag, receiver metadata, and calling convention, never descriptors. `unbound_value` should clear the receiver descriptor to `None` rather than manufacture an empty identifier. `Display` may still show `name: Type` when metadata exists and plain `Type` when it does not. The current unnamed-only exception in `ResolvedFunctionType::accepts` becomes unnecessary; function-type compatibility remains invariant equality under the new identity rule.
  - `compiler/omega-analyzer/src/type_key.rs`: `write_function` must omit parameter descriptors so `type_key::structural_key` continues to distinguish exactly what `ResolvedType::PartialEq` distinguishes. This is important for structural types such as anonymous enums that may contain function types.
  - Analyzer consumers that currently destructure `(Ident, ResolvedType)` parameters (`analysis/items`, `analysis/calls`, `analysis/paths.rs`, `analysis/specs.rs`, `analysis/abi`, `checked.rs`, `error/mod.rs`, and tests) must read the new parameter object's type/name fields. Existing comparisons such as spec requirement matching must inherit the descriptor-insensitive parameter equality rather than reintroduce name comparison manually.
  - `docs/language/functions.md`: state normatively that a function-type parameter name is optional descriptive metadata and that renamed/named-vs-unnamed signatures are one type. Update the unbound-member wording so it no longer describes unnamed receiver compatibility as a special exception.
  - `docs/language/grammar.md`: split declaration `parameter = identifier ":" type` from a function-type parameter production such as `function-type-parameter = [ identifier, ":" ], type`; declarations/specs/gaps/glue keep required names. Preserve existing receiver and variadic grammar.
  - `docs/architecture/types-layout-and-const-eval.md`: record the durable invariant that function parameter descriptors may be carried for presentation/tooling but are excluded from resolved type identity/hash/structural keys.
  - `docs/issues/known-issues.md`: remove the two resolved entries about function-type equality comparing names and function types requiring names; do not retain a historical “fixed” caveat in normative/current docs.
- **Interfaces/invariants:**
  - Parameter *types*, order, return type, variadicness, receiver/declaration mode where applicable, and calling convention keep their existing identity semantics. In particular, `foreign(c) (i32) => i32` remains different from `(i32) => i32`.
  - Descriptor presence/spelling must never affect assignment/coercion, expected-type overload selection, conformance, generic inference/instantiation keys, `ResolvedType` hashing, anonymous-enum/spec structural keys, layout, ABI, or mangling.
  - Equal function types are allowed to render differently if they carry different optional descriptors; `Display` is presentation, not canonical identity.
  - Function declarations remain named bindings. This feature applies only to parameters *inside a function type*.
  - Preserve descriptors through source-level type transforms such as aliases/generic substitution; do not synthesize a name for an unnamed parameter and do not select one name as “canonical” when two equal types differ only by descriptors.
  - Keep the existing member-value rule: an unbound receiver becomes an explicit first parameter with no receiver descriptor and no adapter/thunk. Under the new general identity rule this needs no compatibility carve-out.
  - ABI and symbol grammar do not change. `compiler/omega-mir/src/mangle/semantic.rs::signature` already maps `ResolvedFunctionType` parameters to `MangleType` using only their types, so the implementation should continue consuming the new semantic shape without adding names to mangling. No LLVM/codegen policy change is required.
- **Out of scope:** Optional names in actual function/method/spec/gap/glue declarations; keyword-argument semantics; named-argument calls; changing overload identity beyond removing function-type descriptors from type identity; LSP implementation; calling-convention or variadic redesign; ABI/mangling format changes.
- **Risks/open questions:** No language-design question remains. The implementation must avoid one parser regression: after unnamed type parameters are legal, `(*Thing) => void` and `(*mut Thing) => void` start with the same tokens previously used to commit to pointer-`self`; receiver parsing must use exact lookahead and leave ordinary pointer types untouched. If any semantic consumer is found branching on a function parameter's name rather than using it only for display/diagnostics, stop and surface that dependency instead of preserving name-sensitive behavior silently.

## Implementation Plan
1. **Separate the parser representations.** In `compiler/omega-parser/src/ast/type.rs`, add the optional-descriptor function-type parameter shape and switch `FunctionType::params` to it. Keep declaration `Param` unchanged. Give the function-type parameter custom structural equality that compares only its nested `Type`; spans, macro provenance, and descriptor text remain metadata. Export the new type from `prelude.rs`.
2. **Give function types their own parameter grammar.** Rewrite `parser/type.rs::parse_function_type` to recognize an optional exact receiver first, then parse a comma-separated list where `ident : type` is the named form and any valid `type` is the unnamed form, with the existing trailing `, ...` behavior. Do not route this through `parse_param_decls`. Ensure exact receiver lookahead means `*self` / `*mut self` still work while `*Thing` / `*mut Thing` are parsed as unnamed pointer-typed parameters. Leave declaration parsers unchanged so `f(i32) => void { ... }` is still invalid.
3. **Adapt source/HIR signature constructors and structural transforms.** Update `ForeignFunctionItem::function_type`, `FunctionDefinitionStmt::function_type`, `HirForeignFunction::function_type`, and `HirFunctionDef::function_type` to wrap real binding names as descriptors. Update alias substitution/normalization to preserve descriptors while transforming parameter types, and generic unification to inspect only the nested type.
4. **Make semantic identity descriptor-independent by construction.** Add the resolved function-parameter representation in `resolved_type.rs`; its equality/hash must use only the resolved parameter type. Update `Context::resolve_function_type` and all `ResolvedFunctionType` constructors to populate it. Remove the empty-name convention from `unbound_value`; clear the unbound receiver descriptor explicitly. Simplify function compatibility so renamed, unnamed, and differently named descriptors compare/accept identically, while all existing non-name identity fields remain strict.
5. **Audit every semantic identity path once.** Update analyzer consumers of function params to the new fields. In particular, ensure `analysis/specs.rs::fn_satisfies_requirement`, expected-type overload matching in `analysis/paths.rs`, redeclaration/overload checks in `analysis/items/mod.rs`, call checking/inference, ABI validation, raw/resolved diagnostic display, and checked-signature reconstruction use parameter types for semantics and names only for presentation. Update `type_key::write_function` to encode parameter types only. Do not add a second “ignore names” helper beside the parameter's own equality/hash unless a call site intentionally compares descriptors for presentation.
6. **Keep downstream representation stable.** Adjust MIR/analyzer compile errors caused by the resolved parameter shape, but keep `omega-mir`'s mangling signature and codegen ABI inputs type-only. No symbol encoding version or backend behavior should change; use this step only to adapt field access and confirm that names never cross into ABI/mangling decisions.
7. **Update the specification and remove resolved debt.** Amend `functions.md` and `grammar.md` with optional function-type descriptors and explicit descriptor-independent identity, revise the unbound-member wording, add the concise architecture invariant in `types-layout-and-const-eval.md`, and delete the two now-resolved entries from `known-issues.md`.
