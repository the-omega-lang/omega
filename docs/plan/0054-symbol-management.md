# Unified symbol management

## Task Description

- **Deliverable:** Replace `@mangling` completely with `@symbol(mangle = enabled|disabled, name = "…", export[ = enabled|disabled])`, including semantic validation, metadata propagation, LLVM visibility, documentation, runtime sources, and tests. This is a breaking annotation migration; there is no compatibility alias.
- **Purpose:** Give linker naming and binary visibility one explicit interface while preserving Omega's independent source visibility, separate compilation, weak instantiation linkage, and freestanding model.
- **Chosen direction:** Resolve one symbol policy during semantic analysis; carry it through checked items and driver caches; let MIR decide final names and binary visibility; LLVM translates those decisions. Use LLVM Hidden/Default visibility only, with no object-format branches.
- **Rejected alternatives:** Do not derive binary visibility from `exposed`/`shared`/`hidden` or `reveal`; do not use internal/private linkage for hidden definitions; do not introduce export tables, linker flags/scripts, DLL storage classes, retention lists, or compatibility aliases.

## Technical Details

### Semantics

| Parameter | Accepted values | Omitted behavior |
|---|---|---|
| `mangle` | Identifier `enabled` or `disabled` | Existing naming default: enabled for ordinary items, disabled for foreign items |
| `name` | Nonempty string without embedded NUL | No exact-name override |
| `export` | Identifier `enabled` or `disabled`; bare `export` means enabled | Disabled: LLVM Hidden visibility |

- `name` and any explicitly supplied `mangle` conflict, regardless of value or argument order. `export` combines with either naming parameter and never changes the name. Only bare `export` has shorthand semantics; bare `mangle`, `enabled`, `disabled`, or `name` are errors.
- Reject empty `@symbol`/`@symbol()`, unknown keys, duplicate keys (including `export, export = enabled`), wrong value kinds, invalid mode identifiers, and duplicate `@symbol` annotations. Remove recognition of `@mangling`; an old invocation gets the existing unknown-annotation diagnostic. Validate unused declarations too.
- Preserve existing naming applicability: ordinary functions/methods, module-level storage bindings, and foreign bindings/functions. Storage remains data even when its type is a function type. Locals, parameters, fields, `comp` bindings, aliases, types, imports, and other unsupported targets acquire no symbol annotation semantics.
- Preserve restrictions: disabled mangling is invalid on methods or generic functions; exact names are invalid on generic functions and allowed on nongeneric methods. Include generic owner parameters when validating methods. `export` alone is valid on methods and generics when their effective naming policy is valid; it applies to emitted instantiations and does not instantiate an otherwise unused generic.
- All ordinary and foreign definitions default to Hidden, including globals, methods, and root `main`. `export = enabled` selects Default. Existing strong external versus weak-ODR linkage remains independent. Thus ordinary ELF definitions become GLOBAL HIDDEN/DEFAULT; generic/generated weak definitions remain WEAK HIDDEN/DEFAULT rather than being strengthened.
- Apply the same Hidden default to bodyless foreign functions and foreign bindings. On such declarations, `export` describes the referenced symbol's visibility; it does not create a definition. A foreign reference resolved from a different shared image must explicitly use `export`/`export = enabled`. References to known Omega definitions, including extern-package functions, carry the definition's resolved visibility rather than acquiring a reference-site default.
- Compiler-generated gap/glue symbols, vtables, and content-addressed constants are Hidden while retaining current identity/linkage. Do not expand gap/glue annotation support in this task. Preserve `_omg_main` and existing explicit naming overrides; changing visibility alone never selects a different entry symbol.
- Hidden symbols remain linkable across source files and separately compiled objects in the same linked image. `reveal` bypasses Omega access checks only; it cannot bypass binary visibility across shared images. Conversely, an exported language-hidden function remains language-hidden.

**Portability contract:** `export` means LLVM Default versus Hidden visibility, not guaranteed final-binary retention or membership in every platform's dynamic export table. In particular, LLVM has a separate DLL storage class mechanism; this task does not use it. Leave target lowering and final link decisions to LLVM/the linker. See [LLVM visibility styles](https://llvm.org/docs/LangRef.html#visibility-styles) and [DLL storage classes](https://llvm.org/docs/LangRef.html#dll-storage-classes). The uniform Hidden default for foreign declarations deliberately requires migrating shared-library imports; do not silently preserve Default for those declarations as a special case.

### Current implementation and affected contracts

**Initial context boundary:** Start with `compiler/omega-analyzer/src/annotations.rs`, `docs/language/annotations-and-sizeof.md`, and `docs/architecture/symbol-mangling.md`. Then follow the concrete parser/HIR, driver, MIR, and codegen sites below. The symbol encoding grammar in `omega-mangle` does not need to change.

- **Visibility is not currently Hidden.** `omega-codegen/src/llvm/function.rs` maps `MirLinkage::Export` to LLVM External and `Weak` to WeakODR. `llvm/item.rs` uses External for data. `llvm/constant.rs` and `llvm/vtable.rs` use WeakODR. None sets LLVM visibility; current output uses Default. This task establishes the requested invariant rather than preserving an existing one.
- **Parser/HIR:** `omega-parser/src/parser/item/annotations.rs::parse_annotation_arg` currently lacks identifier-valued key/value arguments. Add an identifier variant to `omega-parser/src/ast/annotation.rs::AnnotationValue` and `omega-hir/src/hir.rs::HirAnnotationValue`, and propagate it in `omega-hir/src/lower/item.rs`. Preserve the existing `sizeof<Type>` special form before matching a plain identifier. Identifier values are annotation syntax, not expressions or name lookup.
- **Analyzer:** In `annotations.rs`, introduce `SymbolPolicy { mangling: ManglingMode, visibility: SymbolVisibility }` with `SymbolVisibility::{Hidden, Default}` and replace `ResolvedAnnotations.mangling` with the unified policy. Keep `ManglingMode` as the internal naming mechanism, including `Glued`; removing an annotation does not require renaming the mangling algorithm. Replace `resolve_mangling` with `resolve_symbol`, including duplicate-key tracking and final-policy validation. Keep explicit-key presence while parsing so an omitted `mangle` does not conflict with `name`.
- Update `annotations::resolve` to receive deliberate item defaults. Ordinary defaults are Enabled/Hidden; foreign defaults are Disabled/Hidden. Other annotation resolvers, especially `resolve_size_value`, must reject the new identifier value where inappropriate. Update affected diagnostics in `error/` without adding a second diagnostic mechanism.
- Carry the policy in `checked.rs` through `CheckedDeclaration`, `CheckedForeignBinding`, `CheckedForeignFunctionDef`, `CheckedFunctionDef`, and `ExternFunctionRef`. Update creation sites in `analysis/items/mod.rs`, `analysis/items/bodies.rs`, and affected constructors. Keep the checked-global cache authoritative; do not re-resolve annotations during body construction.
- **Driver:** Preserve policy in `items/resolution.rs`, `items/methods.rs`, `bodies.rs`, and the existing `items.function_annotations` map. Replace the naming-only readback in `compile/output.rs::mangling_of` and propagate visibility through every branch of `collect_extern_functions` (free functions, overloads, methods, primitive/conformance methods, and gaps). Update synthesized gap/glue policies in `compile/bodies.rs`. Cached instantiations must retain both naming and visibility.
- **MIR:** In `mir.rs` and `lower/item.rs`, carry decided visibility alongside final symbol strings for declarations, foreign bindings/functions, and function definitions. Rename `MirLinkage::Export` to `External` to remove its misleading export implication; keep `Weak`. Adapt `mangle.rs::extern_function_ref_symbol` to the unified policy without changing encoding. Do not put visibility into mangled identity.
- **Codegen:** Add decided visibility to `catalog.rs::FunctionDecl` and `GlobalDecl`, including declarations synthesized for references across emission units or extern packages. Map it consistently in `llvm/function.rs` and `llvm/item.rs` for references and owners. Function declaration reuse must not reset a definition's policy; the gap/glue shared-symbol path must remain deterministic. Set Hidden explicitly at all generated constant/vtable creation sites in `llvm/constant.rs` and `llvm/vtable.rs`. Update `symbol.rs` collision help to the new syntax.

**Out of scope:** No calling-convention, layout, mangled grammar, source access-control, emission ownership, or linker-driver redesign. No automatic generic instantiation or keep-alive semantics for `export`. The missing extern-package *data-global* reference channel is already tracked in `docs/issues/known-issues.md`; do not fix it here. Cross-package data tests should use explicit foreign bindings, as existing tests do. Preserve historical `docs/plan/` records.

**Escalation conditions:** Stop if implementation requires actual DLL export/retention guarantees or a different foreign-import default; those change the contract above. Report any LLVM target that cannot emit the selected visibility honestly, rather than adding a format-specific workaround. Do not silently broaden method/generic naming support to get a test passing.

## Implementation Plan

1. **Extend annotation syntax.** Add the AST/HIR identifier-value representation and parser branch. Update diagnostic expectations for malformed values and rejection by unrelated annotations. Add parser/HIR round-trip coverage for `@symbol(mangle = disabled, export)` and identifier values emitted through a macro.
2. **Resolve and carry symbol policy.** Implement the semantics above in the analyzer; propagate policy through checked constructors, driver caches, synthesized items, external references, and MIR. Rename the misleading linkage variant. Update component fixtures alongside this change so compilation remains coherent. Preserve existing mangled names and collision checks.
3. **Apply visibility in LLVM.** Extend the declaration catalog and configure all function/data references and definitions, plus generated constants/vtables. Ensure declaration reuse and owner configuration agree. Verify both Hidden and Default at ordinary and weak linkage without changing source visibility or ABI.
4. **Migrate active callers in bounded batches.** Apply `@mangling(enabled)` → `@symbol(mangle = enabled)`, `disabled` → `mangle = disabled`, and `force = "…"` → `name = "…"`. Work separately through compiler tests, root tests, runtime, then examples/checks/current docs found by `rg`. Replace old negative cases with equivalent new failures and retain a dedicated old-annotation rejection case. Do not add `export` merely because a declaration is `exposed`, foreign, unmangled, or named explicitly.
   - Runtime entry annotations are in `runtime/plat/libc/libc.omg`, `runtime/plat/os/windows/entry.omg`, and `runtime/plat/os/linux/arch/{x86_64,aarch64}/entry.omg`. Preserve exact entry names; native entry selection alone does not require Default visibility.
   - Audit actual external shared-library imports in the runtime/check fixtures. In particular, annotate the libc imports in `runtime/plat/libc/libc.omg` with `@symbol(export)`; retain Hidden for `_omg_main`, whose definition is in the same image. Review Windows OS imports under the same contract without introducing DLL storage classes.
5. **Update the owning documentation.** Replace the annotation grammar/table/chapter in `docs/language/annotations-and-sizeof.md`; update naming, foreign declaration visibility, and entry examples in `foreign-function-interface.md`; update `bindings-and-mutability.md` and explain the binary/source distinction in `visibility.md`. Update current policy/data-flow documentation in `docs/architecture/symbol-mangling.md` and affected statements in `ARCHITECTURE.md`; migrate guide examples in `docs/guide/quick-reference.md`. Avoid calling an ordinary external-linkage definition an automatic binary export. Search active documentation for stale annotation spellings and section links, excluding historical plans.
6. **Validate and review the final diff.** Run focused component/conformance tests, then the full gate and targeted linking/platform coverage below. Audit active `@mangling` occurrences: only intentional rejection fixtures may remain. Review default propagation, all LLVM global creation sites, and reference/definition consistency before handoff.
