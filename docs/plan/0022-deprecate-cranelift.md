# Remove the Cranelift Backend

## Task Description
- **Deliverable:** remove Cranelift completely from the active Omega compiler/toolchain and make LLVM the single unconditional native codegen backend. Delete Cranelift source/dependencies/configuration, remove backend-selection plumbing that no longer represents a real choice, update stale architecture/user/development documentation, and leave the workspace building and testing through LLVM only.
- **Purpose:** maintaining two native backends currently duplicates implementation and review burden while Cranelift provides neither a compile-speed advantage nor target/feature coverage that justifies that cost. A single LLVM backend reduces `omega-codegen` surface area, removes backend-parity maintenance, and makes backend-only capabilities such as inline assembly part of the normal supported implementation path.
- **Chosen direction:** treat this as a simplification, not as “LLVM selected from a one-element backend list.” `omega-codegen` should expose `generate(CodegenRequest)` and invoke LLVM directly; `BackendKind`, `--backend`, the `cranelift`/`llvm` Cargo feature split, and the `justfile` backend selector should disappear. Make `inkwell` a normal `omega-codegen` dependency. Preserve shared MIR, ABI, layout, preflight, symbol, storage, and linkage ownership: those are sound phase boundaries even with one backend and must not be folded into LLVM merely because parity is no longer required.
- **Rejected alternatives:** keeping Cranelift as disabled/deprecated source is rejected because it preserves the maintenance/context burden this change is meant to remove. Keeping `BackendKind`/`--backend=llvm` or an LLVM feature solely for hypothetical future backends is rejected as speculative abstraction; a backend seam can be reintroduced if Omega actually gains a second backend again. Do not rewrite history under `docs/plan/` to pretend Cranelift never existed.

## Technical Details
- **Initial context boundary:** start with `compiler/omega-codegen/`, `compiler/omgc/src/{cli.rs,app.rs}`, `compiler/omega-codegen/Cargo.toml`, root `justfile`, and the current codegen docs `ARCHITECTURE.md`, `docs/architecture/mir-and-codegen.md`, `docs/architecture/abi-and-representation.md`, `docs/architecture/testing-and-validation.md`, and `docs/guide/compiler-cli.md`. Cross into the additional files listed below only to remove verified stale backend-parity/Cranelift wording.
- **Affected files/symbols:** delete `compiler/omega-codegen/src/cranelift/` and `compiler/omega-codegen/src/backend.rs`; simplify `compiler/omega-codegen/src/lib.rs` and `omega_codegen::generate`; remove `BackendKind` from `compiler/omgc/src/cli.rs`/`app.rs` and their CLI tests/help text; remove Cranelift/`target-lexicon` dependencies and backend features from `compiler/omega-codegen/Cargo.toml`; refresh `Cargo.lock`; remove backend feature selection from `justfile`. Update current documentation/comments that explicitly assume Cranelift, two backends, backend selection/parity, or mixed-backend testing, including verified references in `AGENTS.md`/`ARCHITECTURE.md`, `compiler/omega-mir/Cargo.toml`, `docker/{Dockerfile,README.md}`, `docs/architecture/{README.md,compiler-overview.md,mir-and-codegen.md,abi-and-representation.md,symbol-mangling.md,testing-and-validation.md,types-layout-and-const-eval.md}`, `docs/guide/compiler-cli.md`, and relevant `docs/issues/` entries.
- **Interfaces/invariants:** LLVM remains a translator of already-decided MIR semantics. `omega-analyzer::layout` remains the sole layout owner; `omega-codegen::abi` remains the shared/native-call ABI owner; MIR remains responsible for final symbols/linkage and backend-independent CFG; `preflight` remains the common place for codegen-wide unsupported constructs. Target support should still fail cleanly before emission, but with one backend that check should be expressed as LLVM/codegen target capability rather than a `BackendKind` method. `--emit=obj|ir|asm`, optimization levels, target selection, separate compilation, C interoperability, and freestanding/embedded target support must retain their behavior.
- **Out of scope:** do not redesign MIR or the ABI, opportunistically move shared code into `llvm/`, change Omega language semantics, add a replacement backend abstraction, or edit historical `docs/plan/*`. Do not treat unrelated existing codegen/issues debt as part of the removal except where an issue is specifically Cranelift-only or its wording becomes false after removal.
- **Risks/open questions:** Cranelift-specific issue entries may become resolved rather than merely needing a rename. In particular, the documented x86-64 variadic-float failure is explicitly a Cranelift limitation; re-run/verify that shape through LLVM before deleting the issue. Likewise, re-evaluate code-quality issue wording that cites Cranelift's optimizer rather than mechanically replacing the backend name. If a supposedly shared helper is discovered to exist only to normalize differences between the two backends, remove it only after proving LLVM does not need the contract; otherwise keep the ownership boundary intact.

## Implementation Plan
1. **Collapse `omega-codegen` to LLVM-only dependencies and module wiring.** In `compiler/omega-codegen/Cargo.toml`, delete `target-lexicon`, all `cranelift*` crates, the `[features]` backend matrix, and the now-stale explanatory comments; make `inkwell` unconditional with the current LLVM 21 binding feature. Delete `src/cranelift/` and `src/backend.rs`. In `src/lib.rs`, make `llvm` unconditional, stop exporting `BackendKind`, and change `generate` to accept only `CodegenRequest`, run shared preflight/target validation, then call `llvm::generate`.
2. **Replace backend-enum target capability plumbing with the smallest LLVM-only form.** Reuse the verified support logic already owned by `compiler/omega-codegen/src/llvm/mod.rs`; keep the current user-facing unsupported-target diagnostic quality, but remove wording/indirection that refers to a selected backend or a list of backends. Do not move target semantics out of `omega-analyzer::Target`.
3. **Remove backend selection from `omgc`.** In `compiler/omgc/src/cli.rs`, remove `Args.backend`, `--backend=<name>` parsing/help, `BackendKind` imports, and backend-specific parser tests; keep an invalid `--backend=...` invocation behaving like any other removed/unknown flag. In `app.rs`, remove backend destructuring/verbose formatting and call `omega_codegen::generate(request)` directly. Verbose output may say LLVM explicitly only if that information is useful; it should not imply a configurable backend.
4. **Simplify build orchestration.** In the root `justfile`, remove `backend`, `omgc-features`, and conditional Cargo feature selection so the normal `cargo build` always builds the LLVM-backed compiler. Refresh `Cargo.lock` so Cranelift/target-lexicon packages disappear when no other dependency requires them. Preserve existing runtime/test task structure.
5. **Update current architecture and contributor guidance.** Rewrite active docs so `omega-codegen` is described as the LLVM emitter rather than a backend dispatcher. Remove “both backends,” parity, mixed-backend, selected-backend, and two-backend routing rules while preserving the deeper one-owner invariants that those rules previously enforced. At minimum update the verified current references in root `ARCHITECTURE.md`, `AGENTS.md` (and therefore the `CLAUDE.md` symlink target), and `docs/architecture/{README.md,compiler-overview.md,mir-and-codegen.md,abi-and-representation.md,symbol-mangling.md,testing-and-validation.md,types-layout-and-const-eval.md}`. Rename/reframe “cross-backend” sections as backend-independent representation/separate-compilation contracts where the invariant still matters.
6. **Update CLI/container/user documentation and stale source comments.** Remove backend selection from `docs/guide/compiler-cli.md`; reword `docker/Dockerfile` and `docker/README.md` so LLVM is the compiler's required codegen toolchain, not the optional second backend; clean verified “both backends” comments such as `compiler/omega-mir/Cargo.toml` without deleting the actual rationale for deterministic/content-addressed symbols.
7. **Reconcile issue documentation instead of doing a blind text replacement.** Audit the verified Cranelift/parity references in `docs/issues/{compiler-limitations.md,design-debt.md,known-issues.md,language-limitations.md}`. Delete issue entries whose only cause was Cranelift once LLVM validation proves them resolved (especially variadic floating-point calls); reword entries that remain genuine Omega/MIR/ABI limitations; collapse design-debt entries that existed solely because constant/storage logic was duplicated across two backend implementations. Keep unrelated issue content untouched.
8. **Finish with a repository-wide stale-reference sweep.** Search active source/docs/build files for `cranelift`, `BackendKind`, `--backend`, `both backends`, `two backends`, `backend parity`, `cross-backend`, and `mixed-backend`. Remaining hits should be either intentional historical material under `docs/plan/` or terminology whose meaning is genuinely backend-agnostic (for example generic discussion of a codegen backend). Do not edit historical plans solely to make the search empty.

## Testing
- **New/changed cases:** update the existing `omgc` CLI unit tests to prove the backend flag is gone and normal target/emit/optimization parsing still works. No new language-conformance package is required because this change is intended to preserve Omega semantics. If the Cranelift-only variadic-float limitation is removed from issue docs, add or retain a focused root `tests/<case>/` regression that calls a C variadic function with a floating-point argument and proves LLVM emits the correct runnable call on the supported hosted target.
- **Specification trace:** no normative `docs/language/` rule changes are planned. Existing language tests remain the conformance evidence; any added variadic regression should trace the existing FFI/primitive rules rather than introduce new semantics.
- **Negative/diagnostic cases:** verify an unsupported `--target` still produces a clear compiler error before LLVM emission. Verify `--backend=cranelift` (and `--backend=llvm`) is now rejected as an unknown flag rather than accepted as a backend choice.
- **Regression coverage:** run the `omega-codegen`/`omgc` Rust tests, then the normal root language suite through LLVM. Pay particular attention to extern/C calls, globals/constants, vtables/dynamic calls, aggregate ABI, separate-package linking, `--emit=ir`, `--emit=asm`, and optimization-sensitive code because those are areas formerly protected by backend-parity reasoning.
- **Commands/target coverage:** run `cargo check --workspace`, `cargo test --workspace`, and `just test-all` in the LLVM-equipped development environment. Also exercise LLVM at `-O0` and `-O3` on the primary hosted target, plus at least one currently supported freestanding/embedded target that can emit an object without host execution. Confirm `Cargo.lock` contains no Cranelift crates after the workspace build unless an unrelated dependency independently requires one.
