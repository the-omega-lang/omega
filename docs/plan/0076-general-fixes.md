# Sound nested-pattern refinement and header resolution

## Task Description
- **Deliverable:** fix both correctness findings from the nested-pattern review: mutable aliases must not resurrect outer field proofs, and pattern headers must select resolved nominal types rather than names. Add conformance regressions and remove the two resolved known-issue entries.
- **Purpose:** prevent variant payload reads after their proof was invalidated and prevent anonymous-enum dispatch to the wrong nominal/generic member.
- **Chosen direction:** invalidate matching declaration IDs across all active refinement shadows, conservatively across analyzed branches; reuse the existing aggregate header resolver used by construction for struct/variant pattern headers.
- **Rejected alternatives:** restoring saved proofs on scope exit; selecting the first same-named anonymous member; constructing fake value expressions to resolve a pattern; a second pattern-specific implementation of imports/aliases/generic resolution.

## Technical Details
- **Initial context boundary:** `compiler/omega-analyzer`, `tests/t53*`, the targeted regression cases below, and `docs/architecture/semantic-analysis.md` section Pattern matching and exhaustiveness. Language authority: `docs/language/bindings-and-mutability.md` section Mutable places, `docs/language/enums-and-pattern-matching.md` sections Field patterns/Anonymous-enum matching, and `docs/language/aliases.md` section Resolution and identity. Read `docs/guide/quick-reference.md` before new Omega source.
- **Affected files/symbols:**
  - `context.rs`: `drop_refinements`, `widen_variable`, declaration lookup and `context/tests.rs`. An alias invalidates the prefix in every active binding with the same `HirId`; a genuinely distinct same-named local must be unaffected. Root widening must likewise survive refinement shadows. A pointer scrutinee's proved pointee must widen when a root alias invalidates it, without recursively changing unrelated pointer types.
  - `analysis/places/mod.rs`: `widen_place`, `refinable_path`; route root/prefix invalidation consistently for explicit address-of and mutable receiver calls. Explicit dereference of a pointer root must not keep its pointee proof.
  - `analysis/calls/mod.rs`: `adapt_self_argument` must also invalidate a place used as an already-pointer mutable receiver; handing out the pointer to the callee can replace its pointee just as an explicit mutable alias can.
  - `analysis/literals.rs`: factor `resolve_literal_target`'s existing header logic into a shared aggregate path resolver accepting an `ExprPath`, initializer fields and `Expected`. Keep literal field inference as-is; patterns pass an empty field list, so pattern leaves are never checked as value initializers. Expose only analyzer-internal interfaces as needed; use an aggregate-oriented result name if the existing `LiteralTarget` becomes shared. Do not duplicate path resolution or fabricate `HirStructLiteral` values.
    Use the existing `module_headed_path` fallback when `module_qualified_path` declines a module alias followed by a type and variant (`module::Enum::Variant`); ordinary aggregate construction must retain the same canonical resolution.
    Definition-site syntax must use existing `path_module`/`resolve_path_alias_or_error` origin-aware resolution. Remove directly superseded private alias wrappers in `analysis/paths.rs` only after verifying they have no callers.
  - `analysis/patterns/resolve.rs`: `resolve_struct_subpattern`, `resolve_variant_path`, `resolve_anonymous_member`, `anonymous_member_for_path`, `variant_shaped_path`. Resolve struct and variant headers with the shared resolver, then compare semantic types/cells and generic arguments. Anonymous members are selected with `shape.index_of` on the widened resolved type, never by declaration-name scanning. Keep anonymous member **type** patterns using ordinary type resolution, distinct from variant paths; an enum type such as `Button` remains a member type pattern. Allow explicit generic owner arguments on variant patterns. Preserve omitted owner arguments for a known matched generic enum (`Maybe::Just` on `Maybe<i32>`) using the existing expected-type inference. Ambiguous unresolved generic headers on anonymous enums must receive ordinary inference errors, not choose a member by name.
  - Diagnostics in `error/` only if needed to report a genuine resolved mismatch; ordinary malformed/unknown/invisible paths should retain normal resolver diagnostics. Update old expectations only where ordinary path resolution intentionally changes them.
  - `docs/architecture/semantic-analysis.md`: document that mutation invalidates every active shadow of the declaration conservatively across branches, and aggregate headers share ordinary resolution. `docs/issues/known-issues.md`: remove exactly the two reviewed issue entries once verified.
- **Interfaces/invariants:** no parser/HIR representation changes, no MIR/codegen/ABI changes, no runtime overhead. Field prefix invalidation preserves sibling field proofs and allows a later match to establish a fresh proof. Literal construction behavior and generic inference stay unchanged. Root and nested enum tag conditions remain ordered before payload projections. Existing specificity, coverage and invalid-tag semantics stay unchanged.
- **Out of scope:** alias tracking through unrelated preexisting aliases, general control-flow dataflow/borrow checking, new inference rules, new pattern syntax, unrelated compiler debt.
- **Risks/open questions:** stop and report if shared resolution requires driver/public resolver changes or language-policy decisions. Conservative invalidation may reject a proof following a branch that might mutate it; this is intentional soundness, not path-sensitive re-proving.

## Implementation Plan
1. Implement declaration-ID-wide prefix/root invalidation and component tests proving persistence after nested scopes, correct handling of ordinary same-name shadows, and preservation of unrelated prefixes.
2. Factor aggregate header resolution without changing literal behavior. Replace pattern name matching with the shared resolution and semantic identity checks. Handle anonymous member type and variant/struct-shape readings separately.
3. Add positive root conformance for exact generic anonymous-member dispatch (both `Box<i32>` and `Box<u8>` with different outputs), struct aliases at root/nested positions, enum aliases/qualified paths, same-named types from different modules, preserved known-owner generic shorthand, sibling proof preservation and fresh proof after invalidation.
4. Add negative conformance with exact expected diagnostics for outer refined access after a mutable alias in a nested match, conditional nested mutation, mutable receiver/prefix invalidation, and malformed/mismatched/unknown or invisible headers (including ignored generic arguments and nonexistent qualifiers). Add pointer-root coverage appropriate to the widening change.
5. Update the architecture paragraph, remove the resolved issue entries, run focused validation, then the full gate. Keep this plan read-only during implementation.
