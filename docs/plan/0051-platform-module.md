# Native `plat` targets without libc-by-default

## Task Description
- **Deliverable:** Replace the current libc-only default platform setup with a composable `runtime/plat/` tree and implement five concrete platform package roots: `x86_64-linux`, `aarch64-linux`, `x86_64-windows`, `aarch64-windows`, and `avr-none`. The four hosted targets must provide entry, allocator, standard byte I/O, panic, and all supported atomic-width glues without using libc; `avr-none` must provide only capabilities that are honest for a generic AVR target.
- **Purpose:** Make `plat` reflect Omega's target model instead of treating libc as the platform, preserve the language/core guarantee that libc is optional, reuse architecture-only and OS-only implementation where those boundaries are real, and keep embedded/freestanding targets partial rather than fabricating unavailable facilities.
- **Chosen direction:** Keep target composition entirely in the filesystem. `runtime/plat/arch/`, `os/`, and `common/` contain reusable source fragments; only `runtime/plat/target/<target>/` is compiled as the `plat` package. Target roots compose fragments with committed relative symlinks, using file-level symlinks where an OS/architecture intersection needs a different implementation. The compiler continues to see an ordinary package rooted at the selected target directory; no target-composition/cfg mechanism is added.
- **Chosen direction:** Treat OS×architecture details as a real third boundary rather than forcing them into a falsely pure `arch` or `os` layer. Linux's syscall instruction ABI, syscall numbers, and process entry sequence live under `os/linux/arch/<arch>/`; Linux policy shared across architectures lives under `os/linux/common/`. Windows uses the stable Win32/Kernel32 API surface rather than raw NT syscalls, so its OS implementation can be shared by both 64-bit architectures.
- **Chosen direction:** `avr-none` is deliberately partial. It does not fill `GlobalAllocator`, `StandardInput`, `StandardOutput`, or `StandardError`, and it does not ship a universal reset/vector entry point. A generic AVR compiler target does not identify an MCU, USART instance/register map, clock/baud policy, RAM region, vector table, or board wiring. It does fill `PanicHandler` with a non-returning loop and fills atomic widths with interrupt-masked implementations where the AVR architecture contract is sufficient. A future MCU/board platform can omit/override the generic panic file and add startup/Serial glue without compiler changes.
- **Chosen direction:** Retain `runtime/plat/libc/` as an explicit compatibility/fallback platform, but remove it from the normal build/test/playground path. Do not speculatively redesign it into a universal portability layer in this task; split it later when a real libc-required target needs selective reuse.
- **Rejected alternatives:** No compiler-selected platform package, no target `cfg`, no generated copy tree, no duplicated full target directories, no raw Windows syscall numbers, no generic AVR Serial implementation, and no fake allocator/filesystem/socket support on `avr-none`.

## Technical Details
- **Initial context boundary:** `runtime/core/platform.omg`, `runtime/core/panic.omg`, `runtime/core/atomic.omg`; `runtime/plat/`; `docs/architecture/runtime-and-platform.md`; `docs/guide/platform-glue.md`, `console-io.md`, `core-library.md`, and `standard-library.md`; `justfile`; `bin/test-runner`; `tests/t22_program_entry_point`, `t33_panic_handler`, `t35_atomics`; target parsing/emission only for verification in `compiler/omega-analyzer/src/target.rs` and `compiler/omega-codegen/src/llvm/mod.rs`/`tests/target.rs`.
- **Compiler boundary:** `Target` already accepts all five requested pairs and LLVM already maps Linux/Windows/AVR to native triples. `fs_resolve` discovers files/directories through the selected package root and preserves their logical path relative to that root, so committed symlinks are sufficient. Do not modify parser/analyzer/driver/codegen unless a concrete target compile exposes an existing backend bug.
- **Target tree:** use this logical shape (exact helper filenames may be adjusted during implementation, but keep the ownership boundaries):
  ```text
  runtime/plat/
    arch/
      x86_64/
        atomic.omg
      aarch64/
        atomic.omg
      avr/
        atomic.omg
    os/
      linux/
        common/
          allocator.omg
          io.omg
          process.omg
        arch/
          x86_64/
            syscall.omg
            entry.omg
          aarch64/
            syscall.omg
            entry.omg
      windows/
        api.omg
        allocator.omg
        io.omg
        process.omg
        entry.omg
    common/
      hosted/
        panic.omg
    libc/
      libc.omg
    target/
      x86_64-linux/
      aarch64-linux/
      x86_64-windows/
      aarch64-windows/
      avr-none/
  ```
- **Target composition:**
  - `x86_64-linux` / `aarch64-linux`: `arch -> ../../arch/<arch>`, `common -> ../../common/hosted`; make `os/` a real directory whose common Linux files are symlinked from `os/linux/common/` and whose `syscall.omg`/`entry.omg` are symlinked from `os/linux/arch/<arch>/`. This is the intended file-level override/composition case.
  - `x86_64-windows` / `aarch64-windows`: `arch -> ../../arch/<arch>`, `common -> ../../common/hosted`, `os -> ../../os/windows`.
  - `avr-none`: `arch -> ../../arch/avr` plus a real target-local `panic.omg`; no `os/` or hosted `common/` subtree.
  - Add a repository/build validation that the committed target links are actual symlinks resolving inside `runtime/plat/`; a checkout that materializes symlinks as plain text must fail loudly rather than silently compiling an incomplete platform.
- **Hosted panic reuse:** `common/hosted/panic.omg` owns the shared `PanicHandler` glue and panic-line formatting. It writes through `core::platform::StandardError`, not through libc or an OS-private formatter, then calls a uniform target-private `root::os::process::panic_exit()` (or equivalent verified path). Linux and Windows each implement that process primitive. Preserve the current observable message shape unless a platform API forces a documented difference.
- **Linux low-level boundary:** `os/linux/arch/<arch>/syscall.omg` exposes only the small normalized syscall operations the Linux common layer needs (read, write, anonymous read/write mapping, unmap, process termination; add another only if implementation proves necessary). It owns syscall numbers, register placement, clobbers, raw negative-error handling, and architecture-specific inline assembly. Do not leak raw syscall-number knowledge into `os/linux/common/`.
- **Linux entry:** provide a real no-CRT process entry in `os/linux/arch/<arch>/entry.omg`, forced to the ELF entry symbol (normally `_start`). Use `@naked` assembly where needed so process-entry stack state is not misinterpreted as an ordinary called Omega/C function. It calls the fixed Omega `_omg_main` symbol, then terminates the process with status 0 if `main() => void` returns. The x86-64 and AArch64 sequences are OS×arch details and therefore belong beside the syscall ABI, not in top-level `arch/`.
- **Linux allocator:** implement `GlobalAllocator` directly over anonymous private mappings. Store implementation metadata immediately before the user block so `free(ptr)` can unmap without a size argument. `realloc` should allocate the replacement first, copy `min(old_size, new_size)` bytes, then release the old mapping; on allocation failure, return null and leave the old allocation intact. Handle null/zero cases sanely but do not turn implementation choices not promised by `GlobalAllocator` into new portable language guarantees. Preserve at least the alignment required for every ordinary Omega allocation currently supported on these targets.
- **Linux I/O:** implement the three console gaps with direct `read`/`write` syscalls on descriptors 0/1/2. Preserve the gap contract exactly: kernel error -> `None`; non-negative result, including zero and short transfers -> `Some(count)`. Do not retry automatically in the gap; callers already own retry/short-transfer policy.
- **Linux panic termination:** after the hosted formatter writes stderr, terminate all threads deterministically without libc. An `exit_group(134)`-style policy is sufficient and preserves the current test-visible status without promising libc `abort`/signal/core-dump semantics.
- **Windows API boundary:** `os/windows/api.omg` declares only scalar/pointer `foreign(c)` bindings and aliases/constants required by the other Windows modules. Use documented Kernel32 APIs: process heap (`GetProcessHeap`, `HeapAlloc`, `HeapReAlloc`, `HeapFree`), standard handles (`GetStdHandle`), byte I/O (`ReadFile`, `WriteFile`), and process termination (`ExitProcess`, plus `GetCurrentProcess`/`TerminateProcess` for panic if chosen). These are Windows platform dependencies, not libc/CRT dependencies. Do not use unstable NT syscall numbers.
- **Windows allocator:** implement `GlobalAllocator` with the process heap and zero flags. Normalize null handling around the gap contract as needed; do not expose Win32 handles or flags publicly.
- **Windows I/O:** obtain the process's current standard handle on each call so redirection through `SetStdHandle` remains observable; use `ReadFile`/`WriteFile` so redirected files/pipes work as well as console handles. Chunk a `usize` slice if necessary because Win32 transfer counts are `DWORD`; return the number transferred by the single gap call according to the existing short-transfer contract rather than hiding repeated blocking writes. Invalid/null standard handles or API failure become `None`.
- **Windows entry:** provide a custom CRT-free console executable entry symbol and document/link it with `/ENTRY` plus `/SUBSYSTEM:CONSOLE` and `/NODEFAULTLIB`, linking only the required Windows import library. The entry uses the target C ABI, calls `_omg_main`, then `ExitProcess(0)`. Do not name or structure it as if the Microsoft CRT were present unless the linker contract genuinely requires that symbol.
- **Windows panic termination:** format through the shared hosted panic glue, then terminate the current process with status 134 without running a C runtime cleanup path. If `TerminateProcess` is used, include a non-returning fallback loop after an unexpected failure so `PanicHandler::panic` remains `never`.
- **x86-64 atomics:** `arch/x86_64/atomic.omg` fills `Atomicity8/16/32/64` for both Linux and Windows. Use native atomic instructions/CAS loops; do not call OS/libc. Loads/stores may exploit x86-64 ordering, SeqConsistent stores must use a sequence that participates correctly in the global order, and locked RMW/CAS operations may legally strengthen weaker requested orderings. `compare_exchange_weak` may equal strong. `fetch_min/max` use CAS loops. If an address accepted by ordinary Omega access cannot safely use the native locked primitive (for example because of a stricter atomic alignment constraint), route it through a static, allocation-free lock fallback rather than narrowing the documented atomic contract.
- **AArch64 atomics:** `arch/aarch64/atomic.omg` fills all four widths using baseline exclusive-load/store instructions, not optional LSE, so the implementation works on generic AArch64 CPUs. Map Relaxed/Acquire/Release/AcquireRelease with the corresponding ordinary/acquire/release exclusive forms; use barriers where needed for the documented SeqConsistent minimum. Strong CAS retries store-exclusive failure while the compared value still matches; weak CAS may report that failure. Min/max are CAS/LL-SC loops. Provide the same alignment fallback rule as x86-64 if ordinary Omega access permits addresses the exclusive instructions cannot accept.
- **AVR atomics:** `arch/avr/atomic.omg` may strengthen every ordering to one interrupt-masked critical section. Save whether the global interrupt-enable bit was set, disable interrupts, perform the ordinary load/store/RMW, and re-enable only when it was previously enabled. This is allocation-free and gives a valid single-core bare-metal implementation for 8/16/32/64 widths; weak CAS may be strong. Keep the compiler barrier property of the inline-asm boundaries. Do not claim lock-freedom.
- **AVR panic:** target-local `panic.omg` fills `PanicHandler` with an infinite loop and no console dependency. Do not call `StandardError` conditionally: Omega's static gap linkage has no notion of an optional glue. A later MCU/board target that has Serial can compose its own panic implementation instead.
- **AVR omissions:** no generic allocator, stdio, filesystem/network placeholders, or process entry/startup. These depend on a concrete MCU/board memory map and startup policy and must remain unfilled until such a platform layer exists.
- **libc fallback:** keep `runtime/plat/libc/` standalone-compilable as `plat` for explicit compatibility/FFI workflows, but no normal recipe or documentation may describe it as the default platform after this task.
- **Build/link selection:** update `justfile` so the normal host runtime/playground build selects `runtime/plat/target/x86_64-linux` and passes the same explicit `--target=x86_64-linux` to `core`, `plat`, `std`, and application compilation. Add a target-parameterized runtime compile recipe for the other four targets; place artifacts under target-specific directories so `.o`/`.obj` outputs cannot collide. `omgc` still only emits objects; target-specific final linker commands remain build/toolchain responsibility.
- **No-libc proof:** the normal x86-64 Linux playground/runtime smoke link must use the platform `_start` and link without libc/CRT startup objects. Existing tests whose purpose is C ABI interoperability must use an explicit native helper or an explicit libc-only test path; they must not force the default runtime back onto libc.
- **Documentation:** rewrite `docs/architecture/runtime-and-platform.md` and `docs/guide/platform-glue.md` around reusable fragments + concrete target roots; update `docs/guide/console-io.md`, `core-library.md`, and `standard-library.md` where they currently state that the hosted/default platform is libc-backed or that default plat has no atomics. Do not change `docs/language/gaps-and-glue.md` or `docs/language/atomics.md` unless implementation uncovers an actual semantic ambiguity; the language contracts already describe platform-independent behavior correctly.
- **Out of scope:** filesystem/socket/process APIs not yet represented by core gaps; MCU-specific AVR startup, USART, clocks, linker scripts, vector tables, or board definitions; macOS/BSD targets; automatic platform selection inside `omgc`; a general Omega build system; libc decomposition beyond what is required to keep the explicit fallback working.
- **Risks/open questions:** no design question remains for implementation. If a target cannot compile because Omega inline asm cannot express a required register/result transfer, stop and escalate that backend limitation rather than introducing compiler magic or an external runtime dependency. Likewise, if Windows `foreign(c)` cannot express the required 64-bit platform ABI on either requested target, treat that as a compiler ABI bug, not a reason to fall back to libc.

## Implementation Plan
1. **Create and validate the platform composition skeleton.** Add `arch/`, `os/`, `common/`, and `target/` under `runtime/plat/`; create the five target roots and committed relative symlinks described above. Add a focused repository/build check for broken/non-symlink target composition. Compile empty/minimal target roots with their matching `--target` to prove module discovery and object-path ownership work without compiler changes.
2. **Implement architecture atomics first.** Add x86-64, AArch64, and AVR `Atomicity8/16/32/64` glue with shared per-architecture helpers/macros where that reduces duplication without hiding the instruction-level mechanism. Cover load/store/exchange/CAS/all fetch operations, signed/unsigned min/max, ordering strengthening, weak-CAS behavior, and any required alignment fallback. This makes the same `arch/` subtree reusable immediately by both hosted OSes.
3. **Implement the Linux OS layer.** Add common allocator/I/O/process modules plus x86-64 and AArch64 syscall/entry intersection modules. Keep syscall numbers/register ABI entirely in the arch-specific Linux fragments. Verify `x86_64-linux` and `aarch64-linux` platform packages compile with no foreign libc declarations or unresolved libc symbols.
4. **Implement shared hosted panic.** Move the current reusable formatting behavior into `common/hosted/panic.omg`, rewrite its output path through `StandardError`, and connect Linux `panic_exit`. Confirm the x86-64 Linux panic still prints the expected site/message and terminates with the selected status.
5. **Implement the Windows OS layer.** Add the Kernel32 FFI surface, heap allocator, standard-handle byte I/O, panic/normal termination, and custom entry module. Because all declarations are scalar/pointer `foreign(c)`, use the same physical Windows source for x86-64 and AArch64 and let the target C ABI/codegen choose the machine convention. Verify both Windows target packages emit COFF objects and contain no libc/CRT imports.
6. **Finish `avr-none` honestly.** Add the target-local infinite-loop panic glue and compose AVR atomics. Do not add console/allocator/entry glue. Add a small freestanding compile/link fixture only if the repository already has a concrete AVR linker-script/device fixture available; otherwise limit the generic platform test to object emission plus the atomic/panic surface and document that final MCU startup belongs to a board/device layer.
7. **Switch the default host build from libc to `x86_64-linux`.** Update `justfile`, playground registration, and runtime artifact layout/target arguments. Add an explicit libc-free x86-64 Linux link/run smoke path using the new `_start`. Keep `runtime/plat/libc` available only through an explicitly named compatibility recipe if one is still useful.
8. **Untangle conformance tests from accidental libc dependence.** Remove `tests/t35_atomics/glue.omg` (the default platform now supplies real atomics) and run the case against the x86-64 target glue. Rewrite `t22_program_entry_point` so its `never` entry test does not call libc `exit`. For `t19_foreign_function_interface`, preserve actual C-ABI/variadic coverage with an explicit small native helper object or a dedicated explicit-libc test path; do not link libc into every conformance executable merely for this one case.
9. **Add target-matrix verification.** Compile `core`, the selected `plat/target/<target>`, and `std` with the same explicit `--target` for all five targets. Add/extend codegen target coverage for `aarch64-windows` if it is not already exercised. Where toolchains are available, link/run x86-64 Linux natively, AArch64 Linux under a real cross environment/emulator, and Windows with the appropriate import library/linker; otherwise require object/undefined-symbol inspection for the cross targets and keep the exact manual link commands documented.
10. **Update runtime/platform documentation and remove stale libc-default claims.** Document the ownership rule (`arch`, `os`, OS×arch intersection, `common`, concrete `target`), the symlink composition model, the capability matrix (including AVR omissions), target-specific linking responsibilities, and libc as an explicit fallback rather than the platform model. Then run the focused runtime tests followed by the full gate.

## Testing
- **New/changed cases:**
  - `tests/t35_atomics`: remove local fake glue and exercise the real `x86_64-linux` `Atomicity8/32` implementations already used by the case; extend to 16/64 if needed so every filled width is reached.
  - Add a focused platform atomic stress workflow for native x86-64 Linux: multiple host threads repeatedly call exported Omega atomic operations and assert final values/CAS behavior. A tiny C/Rust thread harness is acceptable test infrastructure; it may use host pthread/std because the assertion is that the *platform implementation* itself has no such dependency.
  - Add focused ordering/code-shape checks for x86-64/AArch64 assembly/IR where runtime concurrency cannot prove the specific instruction contract, especially SeqConsistent store/RMW and AArch64 acquire/release selection.
  - `tests/t33_panic_handler`: keep exact panic text and update only the status expectation if the chosen direct Linux termination policy intentionally differs; preferred plan preserves 134.
  - `tests/t22_program_entry_point`: preserve both `void` and `never` entry semantics without calling libc.
  - Add a libc-free x86-64 Linux hello/stdio/allocation smoke link that uses the new `_start` and verifies no dynamic libc dependency (`readelf`/`nm`/link command as appropriate).
  - Add Windows object/link smoke tests for entry, stdio, allocator, and panic imports against Kernel32 only; cover both `x86_64-windows` and `aarch64-windows` at least at compile/object level.
  - Add `avr-none` compile coverage proving panic + all chosen atomic widths resolve while allocator/console remain intentionally unfilled when referenced.
- **Specification trace:** `docs/language/gaps-and-glue.md` for exact console/allocator/panic glue linkage and partial-platform legality; `docs/language/atomics.md` for width completeness, ordering minimums/strengthening, weak CAS, no allocation, and address/alignment obligations. No new language semantic rule is introduced.
- **Negative/diagnostic cases:** intentionally referencing `Stdout`/`Stdin`/`GlobalAllocator` under the generic `avr-none` platform should fail at final capability/link resolution rather than silently selecting a stub. Do not add fake runtime `None`/null implementations merely to make such programs link.
- **Regression coverage:** existing `t17_gaps_and_glue`, `t19_foreign_function_interface`, `t22_program_entry_point`, `t33_panic_handler`, `t35_atomics`, `t36_multi_object`; `compiler/omega-codegen/tests/target.rs`; `compiler/omgc/tests/output_layout.rs`; platform/runtime docs consistency.
- **Commands/target coverage:** focused `./bin/test-runner t22_program_entry_point t33_panic_handler t35_atomics`; native libc-free `x86_64-linux` playground/smoke; target-parameterized runtime compile for all five requested targets; then `just test-all`. Cross-link/run commands for AArch64 Linux and Windows should be part of the target validation recipe when the matching linker/sysroot/import libraries are installed, but normal compiler correctness must not silently depend on their presence.
