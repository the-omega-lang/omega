# Replace source `extern` with `foreign` and typed calling conventions

## Task Description
- **Deliverable:** Replace Omega's source-level `extern` declaration syntax with `foreign`, and use the change to establish calling convention as a first-class function-type property. Support foreign bindings, foreign function declarations/definitions, `foreign(<calling-convention>)` function types, and module-level foreign blocks. Initial named conventions are `c` and `sysv64`; ordinary Omega function types keep the implicit Omega convention.
- **Purpose:** `extern` currently conflates external symbol binding with the special C/variadic path and cannot accurately represent function pointers or definitions that use non-Omega calling conventions. `foreign` should mean that a declaration/type intentionally leaves Omega's default linkage/ABI assumptions, without abusing annotations or backend-only metadata. This lays a clean foundation for future calling conventions while preserving explicit ABI costs and freestanding viability.
- **Chosen direction:** Keep two independent facts throughout the compiler: (1) whether a source item is a foreign binding/definition, which controls default symbol mangling/linkage semantics, and (2) the function type's calling convention, which controls type identity and ABI lowering. `foreign name : (...) => T;` therefore binds an external symbol whose function type still uses the Omega convention; `foreign(c) name(...) => T;` and `foreign(c) (...) => T` explicitly select C. Foreign items default to unmangled symbols, with `@mangling(enabled)` opting back into normal Omega mangling. A `foreign(cc) { ... }` block only supplies `cc` to direct function-signature entries; an explicit `name : Type` keeps exactly the convention written in that type. The new syntax is module-level; do not preserve the currently parsed-but-unimplemented function-local `extern` form.
- **Rejected alternatives:** Do not model calling conventions as annotations, call-site flags, or a codegen inference from `foreign`/variadic syntax; those cannot make function-pointer types sound. Do not introduce `foreign::...` imports or touch the new ordinary dependency-import model: source imports and compiler `--import` registration are unrelated to FFI. Do not silently apply a block convention inside an explicit type. Do not let `foreign(c) name : Type` silently ignore or overwrite the type's convention; write `foreign name : foreign(c) (...) => T;` instead. Do not add a full platform ABI classifier in this task; non-Omega aggregate-by-value support remains outside the currently documented interoperability guarantee.

## Technical Details
- **Initial context boundary:** Start with `docs/language/foreign-function-interface.md`, `docs/language/functions.md`, `docs/language/grammar.md`, `docs/language/lexical-structure.md`, and `docs/language/annotations-and-sizeof.md`. Use `docs/architecture/parsing-and-hir.md`, `semantic-analysis.md`, `types-layout-and-const-eval.md`, `abi-and-representation.md`, `mir-and-codegen.md`, `symbol-mangling.md`, and `testing-and-validation.md` only for the corresponding implementation boundary. `docs/language/modules-and-imports.md` is context only to preserve the just-landed rule that dependency imports are ordinary paths; do not redesign resolution.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/lexer.rs`, `ast/type.rs`, `ast/item.rs`, `ast/statement.rs`, `parser/type.rs`, `parser/item.rs`, `parser/item/functions.rs`, `parser/statement.rs`, macro expansion/recovery/highlighting sites: replace the keyword/AST shape, parse type-level conventions and foreign blocks, and remove local-statement `extern` parsing.
  - `compiler/omega-hir/src/hir.rs`, `lower.rs`, `lower/item.rs` and type-rewrite helpers: carry the raw convention on function types/items and syntax-only flatten foreign blocks before semantic analysis. Block lowering must never rewrite an explicit `: Type`.
  - `compiler/omega-analyzer/src/resolved_type.rs`, `context.rs`, `checked.rs`, `annotations.rs`, `analysis/items/`, `analysis/paths.rs`, `analysis/specs.rs`, `analysis/stmts.rs`, `target.rs`: introduce the semantic calling-convention vocabulary, make it part of `ResolvedFunctionType`, validate convention/target/variadic rules, remove the local extern statement path, and make foreign mangling defaults explicit rather than post-hoc.
  - `compiler/omega-driver/src/compile/signatures.rs`, `compiler/omega-driver/src/bodies.rs`, `compiler/omega-driver/src/resolver.rs`: preserve the convention when reconstructing function types and include it in function-type/signature compatibility where type identity matters. Keep dependency-package concepts such as `ExternRoot`/`ExternFunctionRef` semantically separate; they describe ownership from another compiled package, not the new source `foreign` construct.
  - `compiler/omega-mangle/src/symbol.rs` and encoder/decoder/display modules, plus `compiler/omega-mir/src/mangle.rs`, `mangle/semantic.rs`, `mir.rs`, `lower/item.rs`, `lower/function.rs`: encode convention and variadic identity in function-type/symbol identity, assign symbols for mangled foreign functions/data, and delete the local extern MIR `todo!` by removing that source form upstream.
  - `compiler/omega-codegen/src/abi.rs`, `preflight.rs`, `symbol.rs`, and `llvm/function.rs`, `llvm/expr.rs`, `llvm/item.rs`, `llvm/place.rs`: select ABI lowering from the resolved convention, set matching LLVM convention on declarations/definitions/call sites, scope C vararg promotion correctly, and implement external global declarations instead of rejecting non-function foreign bindings.
  - `runtime/plat/libc/libc.omg`, relevant `docs/language/`, `docs/issues/`, and root conformance cases including `tests/t01_lexical_structure`, `tests/t15_annotations_and_sizeof`, `tests/t19_foreign_function_interface`, and `tests/t22_program_entry_point`.
- **Interfaces/invariants:**
  - Define one shared semantic `CallingConvention` value (at minimum `Omega`, `C`, `SysV64`) owned at the analyzer/type boundary; later phases consume it rather than infer it. Parser/HIR may retain a raw identifier until target-aware semantic resolution.
  - Calling convention is part of function-type equality, hashing, expected-type matching, indirect-call typing, and mangled type identity. `foreign(c) (i32) => i32` and `(i32) => i32` are different types even on a target where both currently lower to the same machine convention. `c` and `sysv64` remain semantically distinct as well.
  - Do not make calling convention a way to create otherwise-indistinguishable overloads. Same-name functions with the same callable parameter types remain duplicate/redeclaration candidates because direct call syntax has no convention selector; convention participates when comparing complete function types/signatures.
  - Source forms are intentionally explicit:
    - `foreign name : Type;` declares a foreign data/function binding; any function convention comes from `Type` and defaults to Omega for an ordinary function type.
    - `foreign name(args) => T;` is the direct Omega-convention foreign-function declaration.
    - `foreign(c) name(args, ...) => T;` / `foreign(sysv64) name(args) => T;` select a non-Omega convention.
    - A direct foreign function may have a body, e.g. `@mangling(enabled) foreign(c) callback(...) => T { ... }`; it is still a foreign-definition item and defaults to unmangled unless explicitly enabled/forced.
    - `foreign(c) (...) => T` is type syntax. Bare `foreign (...) => T` is unnecessary/invalid at type level because the ordinary type already denotes Omega convention.
    - `foreign(cc) name : Type` is rejected; the unambiguous explicit form is `foreign name : foreign(cc) (...) => T;`.
    - `foreign(cc) { ... }` is module-level syntactic grouping. Direct `name(...) => T;`/definitions inherit `cc`. Data entries do not use it. `name : (...) => T;` stays Omega because the explicit type is authoritative; `name : foreign(c) (...) => T;` is C. Do not create an ambient convention state beyond HIR lowering, and do not allow nested foreign blocks in this phase.
  - `foreign` becomes a hard keyword. Remove source `extern` as a keyword/syntax rather than keeping a compatibility alias; after the break it may tokenize as an ordinary identifier where identifiers are legal. This does not rename internal dependency-package APIs or add any import syntax.
  - Foreign declarations/definitions default to `ManglingMode::Disabled`; `@mangling(enabled)` uses normal Omega symbol construction and `@mangling(force = "...")` retains exact-symbol semantics. Extend annotation resolution so the default is supplied deliberately; do not mutate an already-resolved default because explicit `enabled` must remain distinguishable. Apply the same policy to foreign data. Generic foreign definitions therefore need a mangling mode compatible with generic instantiation (normally explicit `enabled`); do not invent generic external-prototype semantics.
  - Preserve byte-for-byte symbol encoding for existing ordinary Omega non-variadic functions where practical. Extend the standalone `omega-mangle` vocabulary so both nested function types and top-level function signatures encode convention and variadic identity; the current top-level signature representation must not continue dropping variadic identity. Enabled foreign functions of different conventions must not collide.
  - Variadic-ness remains a function-type fact because parsing/type checking and LLVM function-type construction must know whether a tail exists, but Omega must not own target ABI placement/classification for that tail. Ordinary Omega-convention functions are never variadic. Foreign conventions may be variadic when the selected convention/target/backend supports it: `foreign(c)` is variadic-capable, and `foreign(sysv64)` is variadic-capable on its supported x86-64 targets. Future conventions should declare this capability centrally rather than being rejected by a blanket frontend rule. Variadic foreign definitions remain unsupported until Omega has body-side variadic parameter-access semantics.
  - Keep only source-language-required vararg transformations in Omega. In particular, C default argument promotions are required at calls through a variadic `foreign(c)` type because LLVM lowers the IR argument types it is given and does not invent C language promotions. Apply those promotions only to the variadic tail. Do not treat `is_variadic` itself as meaning C, and do not automatically apply C promotions to `foreign(sysv64)` merely because it is variadic; absent convention-specific language rules, pass the tail using its actual lowered Omega types and let LLVM perform register/stack/hidden-ABI classification.
  - `sysv64` is accepted only on compatible `x86_64` targets and must fail semantically elsewhere; never silently fall back. Keep convention-to-LLVM mapping centralized rather than scattering backend numeric IDs.
  - Do not widen C/SysV ABI promises. For non-Omega conventions, consistently accept the currently supportable scalar/pointer/function-pointer boundary and reject by-value values that need an unimplemented platform aggregate classifier. Pointers to such data remain fine. Validation belongs before LLVM emission and must cover declarations, definitions, function types used for calls, and variadic arguments where applicable.
  - External data declarations must become real linker-visible globals with no initializer/storage allocation in the current object; normal place/address/load/store lowering should then use that declaration. Generalize symbol collision tracking as needed so LLVM cannot silently rename conflicting user linker symbols.
  - `_omg_main` demonstrates the binding/convention separation: its runtime declaration should become `foreign _omg_main : () => void;` (Omega ABI). Conversely, the hosted platform adapter exported as native `main` should be a `foreign(c)` definition with its forced `main` symbol, making its C-facing ABI explicit.
- **Out of scope:** Import/path resolution, `--import`, renaming internal dependency-package `Extern*` implementation types, user-defined calling conventions, Windows/vector/interrupt conventions, full C/SysV aggregate classification, variadic function bodies, foreign spec/method/gap/glue syntax, nested/function-local foreign blocks/declarations, or a broad ABI redesign of ordinary Omega functions.
- **Risks/open questions:** If the LLVM version/backend cannot express an explicit SysV64 convention uniformly for every currently supported x86-64 target, stop and tighten the accepted target set rather than approximating it. If preserving old ordinary-function mangles conflicts with making the standalone symbol grammar unambiguous/round-trippable, document the exact compatibility break and escalate before changing the stable symbol grammar more broadly. Otherwise the language semantics above are settled and should not be delegated to implementation guesswork.

## Implementation Plan
1. **Introduce the source syntax without backend semantics.** In `omega-parser`, replace `TokenKind::Extern` with `Foreign`, update keyword/highlighting/recovery handling, and define AST shapes that distinguish a foreign binding, a direct foreign function declaration/definition with optional raw convention, and a foreign block. Extend `FunctionType` with an optional/raw convention only for explicit type-level `foreign(cc)` syntax; ordinary function types remain the default Omega form. Parse `foreign(cc) (...) => T`, reject malformed/unknown syntactic shapes cleanly, reject `foreign(cc) name : Type`, and remove `extern`/foreign declarations from function-statement parsing. Keep ordinary imports untouched.
2. **Normalize grouping in HIR.** Extend HIR function/type/item representations with the raw convention/foreign-definition facts required downstream. Change module lowering so a foreign block expands deterministically into ordinary foreign HIR items, applying the block convention only to direct function-signature entries. Preserve explicit type nodes byte-for-byte semantically, including ordinary Omega function-pointer types inside a `foreign(c)` block. Ensure macro expansion traverses any function bodies/items contained by the source block before this flattening, and update every HIR type reconstruction helper to preserve the new function-type field.
3. **Make convention a semantic type fact.** Add `CallingConvention::{Omega,C,SysV64}` to `omega-analyzer` and `ResolvedFunctionType`, including display/equality/hash. Resolve raw convention names centrally in `context.rs` with target-aware diagnostics; ordinary functions/types resolve to `Omega`. Keep `is_variadic` as part of the resolved function type, forbid it for `Omega`, and validate it through a centralized convention/target capability query rather than a blanket C-only rule (`C` supports it; supported x86-64 `SysV64` supports it). Enforce the conservative non-Omega ABI-safe value subset before codegen. Update checked foreign/function representations and every reconstruction/manual signature comparison that means full function-type compatibility. Keep duplicate-overload detection parameter-based so changing convention alone cannot create an overload set. Remove checked/local-statement extern machinery that no longer has a source form.
4. **Make foreign mangling/linkage policy explicit.** Extend parser/HIR foreign items to retain annotations and adjust `annotations.rs` so annotation resolution receives the correct default mangling mode: enabled for ordinary functions, disabled for foreign items. Preserve `force`/generic restrictions and extend legal mangling handling to foreign data. In analyzer/MIR lowering, stop hardcoding extern symbols: disabled uses the source symbol, forced uses the forced symbol, enabled builds the ordinary Omega function/global symbol from module identity and the fully resolved type. Keep dependency-package ownership/reference structures unchanged.
5. **Extend MIR and the stable mangling vocabulary.** Add calling convention to `MirFunctionDef`/function-type reconstruction and preserve it through direct/indirect call MIR. Refactor `omega-mangle`'s function signature/type representation as needed so top-level signatures and nested function types both carry convention plus variadic identity, with optional encoding markers that leave existing default Omega/non-variadic encodings unchanged where possible. Update `omega-mir::mangle::semantic`, decoder/demangler/round-trip paths, and glue/signature comparisons. Verify enabled `c`/`sysv64` definitions and function-pointer types get distinct identities. Delete the obsolete local extern MIR branch/todo rather than adding a hoisting mechanism.
6. **Split ABI lowering by resolved convention and implement foreign globals.** In `omega-codegen::abi`, keep the existing Omega ABI builder as the Omega path, but do not recreate a frontend vararg ABI classifier. Add centralized convention mapping/capability dispatch for supported foreign signatures, construct LLVM variadic function types with the resolved fixed parameters plus `is_variadic`, and set the selected LLVM convention consistently on `FunctionValue`s and every direct/indirect `CallSiteValue`. Let LLVM perform convention/target-specific variadic placement, register counting, stack layout, and hidden ABI bookkeeping. Retain only C default argument promotion in Omega (`CallingConvention::C && is_variadic`, variadic tail only), since that is C source-language interoperability semantics rather than backend ABI placement. Do not run that promotion merely for `SysV64`. Replace preflight's non-function extern rejection with external-global declaration emission that registers the global under the foreign item's `HirId` without initializer/local section allocation. Extend `SymbolRegistry` to protect the relevant function/global linker namespace so duplicate exact foreign symbols diagnose instead of being auto-renamed by LLVM.
7. **Migrate runtime-facing declarations and exercise the new distinction.** In `runtime/plat/libc/libc.omg`, convert libc declarations to direct `foreign(c)` declarations. Keep `_omg_main` explicitly Omega-convention via `foreign _omg_main : () => void;`, and mark the native `main` adapter definition `foreign(c)` while retaining `@mangling(force = "main")`. Search runtime/tests for remaining source `extern` declarations and migrate each based on the actual ABI rather than mechanically assuming C.
8. **Update normative docs and issue tracking.** Rewrite the FFI/functions/grammar/lexical/annotation chapters to specify the exact forms, mangling default, block non-propagation rule, type identity, foreign-only variadics, convention/target vararg capability, and target/ABI limits above. Make clear that Omega-convention functions cannot be variadic, while supported foreign conventions may be; document C default argument promotions as a `foreign(c)` interoperability rule rather than generic variadic behavior. Remove wording that treats variadic syntax as an implicit C marker. Update `docs/issues/known-issues.md`, `compiler-limitations.md`, and `language-limitations.md` entries touched by the old extern-data/local-extern/calling-convention state: external data and the local-statement `todo!` should no longer be listed as supported syntax gaps; full aggregate ABI and additional conventions remain explicit limitations. Do not alter the new module/import documentation except to remove any stale statement that source `extern` participates in imports, if one remains.
