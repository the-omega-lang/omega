# Enforce Valid Omega Module Identities

## Task Description
- **Deliverable:** Make every Omega module identity directly spellable by Omega's identifier grammar, reject invalid filesystem/CLI module names without normalization, and migrate the root language-conformance packages to valid identifier-compatible names.
- **Purpose:** Eliminate impossible-to-spell module paths and silent filesystem omissions. A module that exists in the compilation tree must have an identity source code can name exactly; Omega must never hide invalid names behind `-` -> `_` or other sanitization.
- **Chosen direction:** Treat invalid module identities as hard errors. Filesystem discovery must reject any `.omg` file stem or source-bearing directory path segment that is not a valid Omega identifier. Explicit declared identities (`--name=<name>`, `--extern=<name>:<dir>`) remain the visible relabeling mechanism for package roots, but the supplied identity itself must be valid. Derive validity from the parser/lexer identifier rules so keywords and other non-`Ident` spellings are rejected consistently with source syntax.
- **Rejected alternatives:** Do not warn-and-ignore malformed module candidates; that would compile a different module graph from the one present on disk. Do not normalize names (`foo-bar` -> `foo_bar`, prefixing numeric names, case rewriting, etc.). Do not maintain an independent driver-only approximation of identifier syntax.

## Technical Details
- **Initial context boundary:** Start with `compiler/omega-driver/src/fs_resolve.rs`, `compiler/omega-driver/src/roots.rs`, `compiler/omgc/src/cli.rs`, and the identifier/token rules in `compiler/omega-parser/src/lexer.rs` / parser identifier handling. Read `docs/language/modules-and-imports.md`, `docs/architecture/module-driver-and-linkage.md`, and `docs/architecture/testing-and-validation.md`. The root conformance packages under `tests/` are directly affected because their current kebab-case package names are invalid under the new rule.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/lexer.rs`: expose or factor a canonical identifier-spelling predicate/classifier that agrees with actual tokenization (`Ident`, not a keyword or malformed spelling).
  - `compiler/omega-driver/src/fs_resolve.rs`: replace `is_module_segment_name` filtering with validated discovery that can report malformed file/directory module identities instead of silently omitting them; ensure invalid source-bearing ancestor directories are detected recursively.
  - `compiler/omega-driver/src/roots.rs`: propagate discovery/name-validation failures while preserving declared-root relabeling and duplicate-identity behavior.
  - `compiler/omgc/src/cli.rs` / `compiler/omgc/src/app.rs`: validate `--name`, explicit `--extern=<name>:<dir>`, and inferred package/extern basenames at the appropriate boundary; do not construct trusted module `Ident`s from unchecked strings.
  - Driver/CLI error definitions/rendering as required to produce a clear invalid-module-name diagnostic that identifies the offending spelling/path and states that module names must be valid Omega identifiers.
  - `docs/language/modules-and-imports.md`: make the identifier requirement and no-normalization rule normative, including filesystem-discovered modules and declared identities.
  - `docs/architecture/testing-and-validation.md`: replace invalid kebab-case test-package examples/commands with identifier-compatible examples.
  - `tests/t00-hello-world` through `tests/t20-operators`: rename every direct test package directory and its same-named root `.omg` file to an identifier-safe spelling while preserving ordering/readability, e.g. `t00_hello_world/t00_hello_world.omg`, `t01_lexical_structure/t01_lexical_structure.omg`, ..., `t20_operators/t20_operators.omg`. Keep auxiliary valid child modules and expectation files unchanged unless a path reference must follow the package rename.
- **Interfaces/invariants:**
  - Every `ModulePath` segment admitted into driver/module inventory is a spelling the Omega parser accepts as an identifier token in a source path.
  - Keywords are not valid module identifiers if the parser would tokenize them as keywords rather than `Ident`.
  - A direct `.omg` child such as `foo-bar.omg` is an invalid module candidate and must error, not disappear from discovery.
  - A directory path segment such as `foo-bar/` that contains or leads to `.omg` source is invalid and must error even if the `.omg` file is only in a deeper descendant. Directories that do not participate in any Omega-source path remain irrelevant.
  - A package root may be deliberately relabeled with a valid explicit `--name`; an extern root may be deliberately relabeled with a valid explicit extern identity. This is visible identity selection, not sanitization. Nested filesystem path segments have no implicit aliasing mechanism.
  - Root physical-file lookup remains based on the physical directory basename as documented; declared identity relabeling changes logical module paths, not filesystem naming conventions.
  - No change to import-resolution semantics, module ambiguity rules, eager local-module compilation, mangling, ABI, or backend behavior beyond receiving only valid module identities.
- **Out of scope:** Do not redesign `Ident` globally, module import syntax, package manifests, aliasing, or source-layout conventions. If making `Ident` intrinsically validated would require broad API churn, keep this task at the parser/driver/CLI boundaries and record the larger type-safety cleanup separately if warranted. Do not refactor the test runner beyond path/name updates needed for renamed cases.
- **Risks/open questions:** No semantic decision is currently open. If implementation discovers an existing documented source-layout case that requires a non-identifier nested module segment, stop and escalate rather than introducing an exception or normalization rule.

## Implementation Plan
1. In `omega-parser`, factor/expose one canonical check for whether a string is a legal source-level identifier spelling. It must use the same start/continue and keyword classification as lexing so callers cannot accept names the parser cannot spell in a module path. Add focused parser tests for valid identifiers, numeric-leading/special-character names, and keyword spellings.
2. Rework `omega-driver::fs_resolve` discovery so invalid module candidates are represented as errors rather than filtered out. Detect invalid `.omg` file stems and invalid source-bearing directory path segments, including ancestors whose Omega source exists only deeper in the subtree. Preserve existing file-vs-directory ambiguity detection and deterministic inventory behavior.
3. Thread invalid-name discovery failures through `ModuleRoots::new`/driver diagnostics so local and extern package discovery fails clearly before semantic compilation. Keep explicit root relabeling behavior intact after physical discovery has been validated.
4. Validate CLI-created declared identities before constructing/handing them to the driver: `--name=<name>`, explicit `--extern=<name>:<dir>`, and inferred root/extern basenames when no valid override applies. Diagnostics should quote the offending name and path/flag context; never suggest or perform a normalized replacement.
5. Update `docs/language/modules-and-imports.md` with the settled rule: module identities are Omega identifiers; source-bearing filesystem path segments and module-file stems must be identifier-compatible; malformed candidates are errors; no implicit normalization occurs; valid explicit root identities are the only deliberate relabeling mechanism.
6. Atomically migrate the language-conformance package names from kebab case to identifier-safe snake case. Rename each `tests/tNN-.../` directory and its same-named root `.omg` file to `tNN_...`; adjust any intra-test text/path references only where they encode the root package name. Update `docs/architecture/testing-and-validation.md` examples and focused-run commands to use valid names such as `t00_hello_world`/`hello_world`.
7. Add focused regression coverage for filesystem and CLI entry points, then run the component and root conformance suites to ensure the newly enforced invariant does not change valid module/import behavior.

## Testing
- **New/changed cases:**
  - Parser/component tests: accepted spellings such as `foo`, `_foo`, `foo123`, `foo_bar`; rejected spellings such as `0123`, `foo-bar`, `foo.bar`, `$foo`, whitespace-containing names, and reserved keywords.
  - Driver filesystem tests: invalid direct module file (`foo-bar.omg`), invalid directory-shaped module, invalid source-bearing ancestor with only deeper `.omg` content, valid non-source asset directory ignored, valid nested module tree preserved, existing ambiguous file/directory layouts still rejected.
  - CLI tests: invalid `--name`, invalid explicit extern identity, invalid inferred basename without an override, and valid explicit relabeling of a package root whose physical basename is not its logical identity where the existing documented override semantics permit it. Assert the intended diagnostic reason, not merely failure.
  - Root language-conformance suite: rename all current `t00-...` through `t20-...` packages/root files to `t00_...` through `t20_...` and verify their expected stdout/stderr remain unchanged.
  - Add a focused root conformance/CLI-oriented negative case only if the current runner can express the required invalid filesystem layout cleanly without weakening test isolation; otherwise keep malformed-layout coverage in `omega-driver`/`omgc` integration tests, where the filesystem shape can be constructed directly.
- **Specification trace:** `docs/language/modules-and-imports.md` is normative for package/module identity and filesystem source layout. The new tests prove that every admitted module path is source-spellable and that Omega does not normalize invalid names.
- **Negative/diagnostic cases:** Invalid module names must fail with a clear invalid-module-name diagnostic. Invalid discovered modules must not be silently omitted, and `foo-bar` must never be accepted as or rewritten to `foo_bar`.
- **Regression coverage:** Existing `omega-driver` filesystem/module tests, `omgc` CLI tests, the modules/imports conformance package (renamed from `t12-modules-and-imports`), visibility/import-related conformance cases, and the full root language suite.
- **Commands/target coverage:** Run focused crate tests for `omega-parser`, `omega-driver`, and `omgc`; run the renamed module/import conformance case directly with `./bin/test-runner t12_modules_and_imports` once artifacts exist; finish with `just test-all`. This change is frontend/driver-only, so backend-specific parity beyond the repository's normal full gate is not required unless the test configuration selects backends separately.
