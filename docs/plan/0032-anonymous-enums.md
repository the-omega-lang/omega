# Anonymous enums

## Task Description
- **Deliverable:** add a structural anonymous-enum type form, written `enum T | U | ...`, whose variants are the member types themselves. Anonymous enums must work anywhere an ordinary value type is legal (including aliases, generic arguments, function parameters/returns, locals, fields, globals, `sizeof`, and compile-time values), support implicit packing of an exact member value at ordinary expected-type coercion sites, and support exhaustive `match` arms written as member types. They use a `u16` discriminant and the existing enum tag/payload representation model.
- **Purpose:** remove the need for nominal wrapper enums when a function only needs to transport one of several existing types, especially error values. Preserve Omega's zero-runtime, freestanding model: the feature must require no allocator/runtime service and must reuse the compiler's existing tagged-union machinery rather than introduce a second union representation.
- **Chosen direction:**
  - Treat an anonymous enum as a **structural type**, not a synthesized declaration. Add a value-semantic anonymous-enum shape to `ResolvedType`; do not allocate a fake `ResolvedEnumType`, `HirId`, name, module, or driver-owned type cell. Aliases remain transparent because alias expansion resolves to the same structural shape.
  - Parse one or more members (`enum A` is valid; `|` adds members). Resolve every member to its final type, sort members by one deterministic structural type-identity key, and remove exact duplicates. Therefore `enum A | B == enum B | A` and `enum A | A == enum A`. A nested anonymous enum remains an immediate member type rather than being recursively flattened; this keeps “variants are types” literal and avoids silently changing representation/cost through aliases.
  - Introduce a **single stable structural type key** in `omega-analyzer` and use it both for anonymous-enum canonicalization and `ResolvedSpecApplication::canonical_key`. Do not copy the current `ResolvedType::to_string()` tie-break: nominal `Display` omits generic arguments, so it is not injective enough for deterministic canonical ordering. The key must use fully-qualified nominal identity plus normalized generic arguments recursively, must not depend on `HirId`/discovery order, and must distinguish every identity-relevant structural modifier (mutability, array length, calling convention, named-enum variant, etc.).
  - Assign anonymous-enum tags from canonical member order: member index `0..n-1`, represented as `u16`. Reject a canonical shape with more than 65,536 distinct members. Reordered spellings therefore have identical member indices, layout, match behavior, ABI, and mangling.
  - Implement member-to-anonymous-enum conversion as a **real checked construction**, not `ResolvedType::accepts(member)`. If an expected anonymous-enum parent contains the value's exact resolved type, `Analyzer::coerce_to_expected` packs the value with the corresponding canonical tag. The constructed expression may carry an internal refined member index, while `ResolvedType::accepts` only provides representation-preserving refined-shape -> parent-shape widening.
  - Member injection is deliberately post-type-check and exact. The compiler does not solve an anonymous enum as a disjunction of expected types. Unsuffixed literals keep ordinary default inference (`i32`/`f32`) and can then inject if that exact type is a member; expressions that need member-specific generic inference/context must be explicitly typed by the programmer.
  - Overload resolution treats anonymous-enum injection as a conversion: exact parameter acceptance ranks ahead of a candidate that requires packing into an anonymous enum. After a winner is selected, arguments must pass through the same `coerce_to_expected` path used by ordinary calls.
  - Matching keeps the existing enum model: tag comparison, exact non-overlapping coverage, exhaustiveness, `..`, `else`, pointer-to-enum matching, and lexical refinement of a directly nameable binding. For an anonymous enum, a non-catch-all arm names a type rather than `Enum::Variant`.
  - Keep refined anonymous values in the **full anonymous-enum storage layout** internally, just as named refined variants retain full enum storage. When a refined anonymous binding is used as its matched member, analyzer place resolution adds the existing enum-body projection concept for body field `0`, exposing the member's type without changing the local's physical representation. Whole-enum operations must continue to use/widen the root anonymous-enum type so refinement never changes ABI/layout.
  - Reuse the existing enum checked/MIR/constant representation wherever possible: `CheckedExpr::EnumConstruct` / `MirExpr::EnumConstruct`, `CheckedProjection::EnumBody` / `MirProjection::EnumBody`, and `ConstValue::Enum` can represent an anonymous variant as “no header/shared fields, one body field containing the member value.” Generalize shared layout/codegen helpers to understand both named and anonymous enum-like `ResolvedType`s instead of adding parallel anonymous-enum lowering code.
  - Anonymous enum tags are a representation/matching discriminant in v1; do not synthesize a declaration/header namespace or methods for the anonymous enum itself. Member methods/fields are reached through the refined member view inside a matching arm.
- **Rejected alternatives:**
  - Do not synthesize hidden nominal enums or hidden wrapper variant types. That would make aliases/source order affect identity, create driver/query lifetime machinery for a structural type, and reintroduce the wrapper concept this feature is meant to remove.
  - Do not make `ResolvedType::accepts` say that `A` is already an `enum A | B`; the representations differ and codegen must materialize a tag/payload value.
  - Do not add a second “anonymous tagged union” checked/MIR/codegen representation if the existing enum construct/body/constant nodes can carry the case after shared layout queries are generalized.
  - Do not implicitly widen `enum A | B` to `enum A | B | C` in this feature. Canonical member indices and maximum payload layout can change, so widening can require runtime retagging/repacking and possibly control flow; that violates the representation-preserving widening model and Omega's no-surprise-cost rule. A future explicit propagation/widening feature can define that cost deliberately.
  - Do not recursively flatten nested anonymous-enum members. `enum (enum A | B) | C` and an alias that resolves to that shape have a nested tagged-union member; flattening would silently alter layout and conversion behavior.

## Technical Details
- **Initial context boundary:**
  - Normative semantics: `docs/language/enums-and-pattern-matching.md`, `docs/language/grammar.md`, `docs/language/aliases.md`, and `docs/language/bindings-and-mutability.md`.
  - Representation: `docs/architecture/types-layout-and-const-eval.md`, `docs/architecture/abi-and-representation.md`, `docs/architecture/mir-and-codegen.md`, and `docs/architecture/symbol-mangling.md`.
  - Validation: `docs/architecture/testing-and-validation.md`, existing root cases `tests/t07_enums_and_pattern_matching`, `tests/t25_spec_type_syntax`, and `tests/t26_aliases`.
  - Start implementation in `compiler/omega-parser`, `compiler/omega-hir`, and `compiler/omega-analyzer`; cross into MIR/codegen/mangling only after the resolved type/layout contract is fixed.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/ast/type.rs::Type` and `compiler/omega-parser/src/parser/type.rs::parse_type`: add the anonymous-enum type node/parser. `TokenKind::Enum` and `TokenKind::Pipe` already exist, so no lexer feature is required.
  - `compiler/omega-parser/src/ast/expression.rs::{Pattern, MatchArm}` and `compiler/omega-parser/src/parser/expression.rs::{parse_match_arm, parse_pattern}`: preserve a type interpretation for match patterns without stealing existing value/range patterns. Use parser `mark`/`reset` as a non-diagnostic probe: a pattern may carry an optional `Type` candidate only when a complete type parse reaches the arm `=>`. The analyzer chooses that candidate only for an anonymous-enum scrutinee; named enum and integer/bool/char matches keep their current value interpretation. This is important for ambiguous path-shaped patterns such as `A` and avoids globally reclassifying constants or `Enum::Variant` paths as types.
  - `compiler/omega-hir/src/hir.rs::HirPattern` and `compiler/omega-hir/src/lower/expression.rs::lower_pattern`: preserve the optional raw type candidate and span through syntax-only lowering. HIR already reuses parser `Type` for declarations/signatures, so no second HIR type vocabulary is needed.
  - `compiler/omega-analyzer/src/resolved_type.rs`: add a structural anonymous-enum shape and `ResolvedType` case with optional internal refined member index; update `Hash`, `Display`, `widened`, `lookup_key`, `accepts`, and other type classification helpers. Add the deterministic structural key/canonicalizer here (or a tightly-owned sibling module) and migrate spec conjunction ordering to it. Equality/hash of the anonymous shape must be canonical-member based and source-order independent.
  - `compiler/omega-analyzer/src/context.rs::resolve_type`: resolve anonymous member types after alias expansion, reject non-value type forms under the same rules as other stored aggregate members, canonicalize/deduplicate, and enforce the `u16` member-count limit. No driver cell/query should be created.
  - `compiler/omega-analyzer/src/aliases.rs::{substitute_type_params, normalize_type}` and `analysis/mod.rs::generic_refs_resolvable`: recurse through anonymous-enum member syntax so aliases/defaults/substitutions see it structurally. An alias such as `alias Errors = enum A | B;` must be indistinguishable from spelling the target directly.
  - `compiler/omega-analyzer/src/generics.rs` and `analysis/mod.rs::{infer_generic_args, expected_for_generic_param}`: allow anonymous enums after generic members are known, but do not invent disjunctive/set-based generic inference. A parameter like `enum T | Error` may be resolved and used once `T` was inferred elsewhere/defaulted/seeded; a bare `A` argument alone does not infer which anonymous-enum member contains `T`.
  - `compiler/omega-analyzer/src/analysis/mod.rs::coerce_to_expected`: add exact-member injection before/alongside dynamic-spec coercion using one helper that returns the canonical member index. Keep parent-shape/refined-shape acceptance representation-preserving.
  - `compiler/omega-analyzer/src/analysis/calls/overload.rs::resolve_overload`: make exact acceptance cost `0` and anonymous-enum injection a worse viable conversion; for adaptable numeric literals use their ordinary default type when testing anonymous-enum membership. Run final winner arguments through `coerce_to_expected`.
  - `compiler/omega-analyzer/src/analysis/calls/generic.rs` (both final argument-validation paths): after concrete `fn_type` resolution, coerce checked arguments to concrete parameter types before `accepts`, so already-resolved anonymous-enum parameters behave like ordinary calls. Existing spec/dynamic call paths already use `coerce_to_expected` and should be regression-checked, not forked.
  - `compiler/omega-analyzer/src/checked.rs`: keep `CheckedEnumConstruct` and `CheckedProjection::EnumBody` as the shared tagged-union construction/body vocabulary. Anonymous injection uses one body initializer at index `0`; a refined anonymous member place uses `EnumBody { variant_index, field_index: 0, type: member }`.
  - `compiler/omega-analyzer/src/analysis/patterns.rs`: recognize named and anonymous enum-like scrutinees separately but share tag-condition/coverage machinery. Anonymous arms resolve their saved type candidate in the current module, apply aliases, require exact membership, use canonical index as the `u16` tag, diagnose duplicate/non-member/missing types, and narrow a directly nameable binding to the same structural shape with `variant: Some(index)`. Do not route anonymous matching through source `.tag` field lookup; construct the internal `EnumTag` projection directly from the enum-like type.
  - `compiler/omega-analyzer/src/analysis/places/{mod.rs,fields.rs}`, `analysis/exprs/mod.rs`, and `analysis/calls/mod.rs`: make ordinary use of a refined anonymous binding project body field `0` before user field/index/method resolution, while retaining the anonymous-enum root for storage/widening. Audit assignment, address-of, mutable receiver adaptation, and `places_provably_equal` so payload operations do not accidentally reinterpret the whole tagged storage and whole-binding de-assumption remains explicit. Named-enum refinement behavior must not regress.
  - `compiler/omega-analyzer/src/layout.rs`: generalize enum layout queries from `&ResolvedEnumType`-only assumptions to an enum-like resolved type/view. Anonymous layout is the same default packed enum model with `u16` tag, zero header/shared fields, and one payload field per variant whose type is that member. `leaves_of`, `type_alignment`, payload size/alignment/offset, and body-field offset must work identically for parent and refined anonymous types; refinement never changes size/alignment/leaves.
  - `compiler/omega-analyzer/src/comp_eval.rs` and `analysis/exprs/mod.rs::apply_comp_projection`: generalize `ConstValue::Enum` construction/tag/body projection to anonymous enums. Keep one constant tagged-union representation rather than adding `ConstValue::AnonymousEnum` unless an invariant makes reuse impossible.
  - `compiler/omega-analyzer/src/error/{mod.rs,kind.rs,render.rs}`: add/adjust diagnostics for too many anonymous members, non-member injection, invalid anonymous-enum type pattern, and non-exhaustive anonymous matching. Diagnostics should render canonical member types, not synthetic variant names.
  - Exhaustive `Type`/`ResolvedType` consumers such as `analysis/specs.rs`, `analysis/items/mod.rs`, `analysis/paths.rs`, `annotations.rs`, and `dead_code.rs` must be classified deliberately when the new variant makes matches non-exhaustive: anonymous enums are aggregate value types with no nominal declaration owner/method table. Let compiler exhaustiveness identify mechanical sites, but do not add fake nominal behavior merely to satisfy matches.
  - `compiler/omega-mir/src/body.rs`, `lower/function/expr.rs`, `lower/place.rs`, and `lower/function/defer.rs`: keep `MirEnumConstruct`/`MirProjection::EnumBody` shared and lower the generalized checked nodes without a second MIR feature. Defer/dead traversal must recurse through the anonymous construction's body value exactly as for named enum construction.
  - `compiler/omega-mir/src/mangle/semantic.rs::mangle_type` and `compiler/omega-mangle/src/{symbol.rs,grammar.rs,encode.rs,decode.rs,display.rs}`: add a structural anonymous-enum `MangleType` encoding containing canonical members in analyzer-provided order. Do not re-sort in MIR/mangle. Add a new grammar tag/list encoding and preserve old encodings byte-for-byte for types that do not contain anonymous enums; the spec canonical-key correction may intentionally change only previously non-deterministic/incorrect generic-conjunction ordering cases.
  - `compiler/omega-codegen/src/abi.rs` should need no anonymous-enum policy of its own because it consumes `layout::leaves_of`. `compiler/omega-codegen/src/llvm/{expr.rs,place.rs,constant.rs}` must stop assuming every `EnumConstruct`/`EnumBody`/enum constant contains `ResolvedType::Enum { cell, .. }`; obtain tag/prefix/payload facts through the shared analyzer layout/type view and emit the already-decided representation.
  - No change to `omega-driver` query ownership is expected. Its item keys already contain `ResolvedType`; structural equality/hash and stable mangling are sufficient. Add driver coverage only where anonymous enums in generic/signature identities need cross-module proof.
- **Interfaces/invariants:**
  - Canonicalization happens after alias expansion/name resolution and before equality/hash/layout/mangling. No later phase may derive member order from source text or hash-map iteration.
  - The canonical ordering key must be deterministic across processes/modules/targets for the same semantic types and must not use `HirId`, pointer addresses, debug formatting, or short `Display` names.
  - Anonymous enum parent/refined forms have identical representation. Only parent <- same-shape refined widening is implicit and representation-preserving.
  - An exact member value is not layout-compatible with the anonymous enum until `EnumConstruct` is present in the checked tree. Every successful implicit injection site must therefore leave an explicit construction for MIR/codegen/const-eval.
  - The tag is always `u16`; canonical index is the tag. Shape cardinality must fit that domain before MIR/codegen.
  - No allocation, RTTI registry, global type table, libc call, or runtime helper may be introduced.
  - ABI/layout is shared through `omega_analyzer::layout`; LLVM must not duplicate member-size/tag-offset logic. Anonymous enums follow Omega's existing aggregate ABI, including the repository's already-documented limitation that by-value aggregates do not yet implement platform C aggregate classification.
  - Symbol identity for a written anonymous enum is structural and source-order independent. `enum A | B` in one separately compiled package and `enum B | A` in another must produce the same ABI shape and mangled type.
  - Existing named enums, spec conjunctions, value matches, and alias semantics must remain source-compatible. In particular, the pattern type probe must not change how `Enum::Variant`, literal, range, or constant-value patterns are parsed/analyzed when the scrutinee is not an anonymous enum.
- **Out of scope:** implicit anonymous-enum subset/superset widening; recursive flattening of nested anonymous enum members; anonymous-enum declarations/method blocks/headers/dynamic fields/custom tags/layout annotations; a propagation operator such as Rust `?`; new borrow/lifetime rules; C-platform aggregate ABI work; disjunctive generic inference or trying every anonymous member as an expected type.
- **Risks/open questions:** if the new structural identity key exposes another existing mismatch between semantic type equality and mangled type identity, do not add an anonymous-enum-only workaround. Stop and make that shared identity inconsistency explicit before shipping, because anonymous-enum order/equality and separate-compilation symbols must be derived from one coherent semantic identity.

## Implementation Plan
1. **Specify the source semantics first.** Update `docs/language/enums-and-pattern-matching.md` with structural identity, canonical ordering/deduplication, `u16` canonical tags, exact member injection, member-type matching/refinement, nested-member behavior, catch-all/exhaustiveness, and the explicit absence of subset widening. Add the type production to `docs/language/grammar.md`; add an anonymous-enum alias example/identity statement to `docs/language/aliases.md`; extend `docs/language/bindings-and-mutability.md` only as needed to describe refined anonymous member access versus whole-enum widening. Keep restrictions normative rather than recording them as accidental issues.
2. **Add syntax/HIR support without changing existing match meaning.** Add `Type::AnonymousEnum` (name as appropriate) and parsing in `compiler/omega-parser/src/parser/type.rs`. Extend match-pattern AST/HIR to retain an optional complete type candidate via mark/reset probing, and lower it in `omega-hir`. Add parser tests before semantic work to prove `enum i32 | *str`, nested/generic member types, aliases/signature positions, `*str =>` type-pattern candidates, and unchanged `Enum::Variant`/value/range patterns.
3. **Establish canonical semantic identity.** In `resolved_type.rs`, add the structural anonymous shape/refinement and the stable recursive type key. Canonicalize anonymous members by key + exact deduplication; migrate `ResolvedSpecApplication::canonical_key` to the same key and add a regression with generic nominal arguments that previously shared the same short display. Implement `Display`, `Hash`, `widened`, `lookup_key`, and parent/refined acceptance. Add analyzer unit tests for reorder equality/hash, duplicate collapse, singleton shape, nested-anonymous-as-one-member, canonical tag indices, and determinism independent of declaration `HirId` order.
4. **Resolve anonymous type syntax everywhere aliases/generics can carry it.** Teach `context.rs::resolve_type` to resolve/canonicalize the shape and enforce the `u16` count/value-type restrictions. Recurse through it in alias substitution/normalization and generic-reference checks. Keep generic inference conservative: anonymous members become an expected type only after their generic references are already resolvable; do not add set/disjunctive inference.
5. **Implement exact member injection as the one semantic construction path.** Generalize `coerce_to_expected` with a helper that finds an exact canonical member and produces `CheckedExpr::EnumConstruct` with the member as body field `0`. Extend overload viability/ranking and both generic-call final-validation paths to use the same conversion semantics. Audit declarations, assignments, returns, ordinary calls, spec/dynamic calls, aggregate fields, and array elements through their existing `coerce_to_expected` call sites rather than adding site-specific packers.
6. **Generalize enum layout before matching/codegen.** Refactor `layout.rs` so tag/prefix/payload/body offset queries can consume either a named enum or anonymous shape. Preserve existing named results exactly. Add focused Rust layout tests for anonymous enums containing differently-sized/aligned members, zero-sized members, reordered shapes, and refined-vs-parent identity. Update `docs/architecture/types-layout-and-const-eval.md` and `docs/architecture/abi-and-representation.md` to record the shared named/anonymous enum-like representation owner; routing in root `ARCHITECTURE.md` does not change.
7. **Add anonymous matching/refined member views.** In `analysis/patterns.rs`, share enum tag/coverage control flow but resolve anonymous arms from their type candidates. Produce canonical-index tag comparisons, exact overlap/exhaustiveness diagnostics, pointer refinement, and narrowed bindings. In place/method analysis, turn a refined anonymous binding into the matched member by adding `EnumBody(variant, field 0)` for ordinary user access while preserving the full anonymous root type. Audit address-of, assignment, mutable receiver adaptation, and comp-place projection so no operation confuses payload address/type with whole enum storage.
8. **Carry the generalized existing enum nodes through const-eval and MIR.** Teach `comp_eval.rs`/`apply_comp_projection` to use `ConstValue::Enum` for anonymous values, then make MIR lowering/defer traversal accept the generalized checked `EnumConstruct`/`EnumBody`. Avoid introducing anonymous-only control-flow or storage nodes unless an existing invariant genuinely cannot represent the case.
9. **Make LLVM consume shared enum-like facts.** Update `llvm/expr.rs`, `llvm/place.rs`, and `llvm/constant.rs` so enum construction, body projection, and enum constants branch through shared semantic/layout queries rather than destructuring a named enum cell. `omega-codegen::abi` should continue to work from `leaves_of`; add/adjust ABI tests only if an anonymous aggregate exposes a transport regression.
10. **Extend stable symbol identity.** Add the anonymous structural type to `omega-mangle`'s model/grammar/encoder/decoder/demangler and the MIR semantic adapter. Encode already-canonical members in order, with no source-order recovery downstream. Update `docs/architecture/symbol-mangling.md` and add round-trip/symbol-equality tests proving reordered/duplicate spellings map to one type identity while materially different member sets do not collide.
11. **Finish diagnostics/docs and mechanical exhaustiveness audit.** Let Rust exhaustiveness errors surface every remaining `Type`/`ResolvedType` consumer and classify anonymous enums consistently as structural aggregate values with no nominal owner. Add precise diagnostics/rendering rather than generic `NotAStruct`/`UnresolvedType` fallbacks where user intent is anonymous-enum-specific. Do not broaden unrelated compiler behavior while touching those matches.
12. **Add end-to-end conformance and separate-compilation coverage.** Add `tests/t27_anonymous_enums` for successful runtime semantics and `tests/t27b_anonymous_enum_errors` for focused diagnostics. Add component/driver/mangling coverage for structural signature identity across modules/extern ownership; where practical, include a two-package/separate-object check because anonymous enums can occur in public function/generic signatures and therefore affect cross-process ABI/symbol identity.

## Testing
- **New/changed cases:**
  - Parser/component tests: anonymous type parsing in declarations, returns, aliases, generic arguments, pointer/function/array members; match-pattern type candidates for bare named, generic, pointer, and anonymous member types; regression that named enum/value/range patterns keep their old interpretation.
  - `compiler/omega-analyzer/src/resolved_type/tests.rs`: structural key determinism, reorder equality/hash, duplicate collapse, generic nominal-argument tie-breaks, nested anonymous member not flattened, refined->parent widening, and spec-conjunction canonicalization using the shared key.
  - Analyzer/layout tests: canonical index -> `u16` tag, maximum-member rejection at the semantic boundary, exact payload size/offset for multiple member shapes, and parent/refined identical leaves/size/alignment.
  - Call-analysis tests: exact overload beats anonymous-enum injection; an anonymous-enum-only overload accepts an exact member; default numeric literal injection uses normal default type; no union subset widening; generic calls coerce once the concrete anonymous parameter is resolved but do not infer an unresolved member generic disjunctively.
  - `compiler/omega-mangle/tests/roundtrip.rs` and MIR mangling tests: anonymous enum encode/decode/demangle; canonical member order; reorder/duplicate identity; different member-set non-collision; anonymous enums nested in function/generic signatures.
  - Root `tests/t27_anonymous_enums`: direct member injection in local initialization, function argument, return, aggregate field/array element where applicable; alias `MyErrors`; reordered and duplicate spellings behaving as one type; matching every member by type; `..`/`else`; member field/method use after refinement; pointer-to-anonymous-enum match/refinement; at least one non-path member such as `*str` to prove type-pattern parsing; `sizeof`/runtime behavior sufficient to exercise the generalized layout/codegen path.
  - Root `tests/t27b_anonymous_enum_errors`: injecting a non-member, matching a type not present in the shape, duplicate/overlapping member arms, non-exhaustive match, redundant/multiple catch-all behavior where relevant, rejected anonymous-enum-to-superset conversion, and any explicit invalid-member-type rule added by resolution.
- **Specification trace:** `tests/t27_anonymous_enums` and `t27b_anonymous_enum_errors` are executable evidence for the new rules in `docs/language/enums-and-pattern-matching.md`; alias cases additionally trace to `docs/language/aliases.md`, and source acceptance traces to `docs/language/grammar.md`.
- **Negative/diagnostic cases:** assert the intended reason/text, not merely compilation failure. Missing anonymous variants should be rendered as member types; non-member match/injection diagnostics should show the canonical anonymous-enum type; member-count overflow should explicitly mention the fixed `u16` tag capacity.
- **Regression coverage:** run existing `t07_enums_and_pattern_matching`, `t25_spec_type_syntax`, `t26_aliases`, relevant parser tests, analyzer `resolved_type` tests, `omega-mangle` round trips, MIR mangling tests, and codegen ABI/convention tests. The shared canonical-key change specifically needs a spec-conjunction regression with generic arguments so the old short-`Display` collision cannot return.
- **Commands/target coverage:** during implementation use focused `cargo test -p omega-parser`, `cargo test -p omega-analyzer`, `cargo test -p omega-mangle`, `cargo test -p omega-mir`, and `cargo test -p omega-codegen` filters for the new tests; with runtime artifacts built, run `./bin/test-runner t27_anonymous_enums t27b_anonymous_enum_errors t07_enums_and_pattern_matching t25_spec_type_syntax t26_aliases`; finish with `just test-all`. Add the separate-compilation/symbol check on the same supported target matrix used by existing mangling/extern tests; no extra hosted runtime capability is required because the feature is allocation/OS independent.
