# Upgrade spec type syntax and dynamic spec shapes

## Task Description
- **Deliverable:** Replace Omega's current spec-alias/dynamic-object surface model with first-class spec conjunctions in type syntax. `spec A + B` must work anywhere the existing static `spec S` form is semantically valid; dynamic objects are written by applying the ordinary pointer constructor, e.g. `*spec A`, `*mut spec A`, and `*spec A + B`. Remove `spec Name = A + B;` and the old `spec *A` / `spec *mut A` spellings.
- **Purpose:** Make spec syntax structurally honest and composable. A source-level `*spec A` must mean “pointer applied to a static spec type” until semantic type resolution recognizes that immediate combination as a dynamic spec object. The parser must not manufacture a fat-pointer type. This keeps syntax, semantic normalization, and runtime representation in their proper layers while removing the fake-spec alias mechanism that would conflict with the future general `alias` feature.
- **Chosen direction:**
  - Parse one static spec type form containing a non-empty source-order list of spec members: `spec A + B + ...`. Keep `pointer-type = "*", ["mut"], type`, so `*spec ...` and `*mut spec ...` arise naturally as `Pointer(SpecStatic(...))`. The raw AST may preserve source order, but source order is not semantic. Remove the parser/HIR `SpecObject` type variant rather than recognizing dynamic-object syntax specially.
  - HIR desugars a `spec ...` **only when it is the parameter's top-level type** into one fresh anonymous generic whose bounds are all conjunction members. It must stop recursively replacing `SpecStatic` behind pointers or other type constructors.
  - `omega-analyzer` is the semantic boundary that recognizes an immediate `Pointer(SpecStatic(shape), mutable)` and resolves it to `ResolvedType::SpecObject { shape, mutable }`. This belongs in/under `Context::resolve_pointer_type`: the analyzer has name resolution and object-safety information, and this function already turns structural pointer syntax such as pointer-to-unsized-array/string into semantic slice/string types. HIR is too early; MIR/codegen are too late because type checking, coercions, member lookup, casts, and layout already need to know this is a dynamic object.
  - Keep “becomes a fat pointer” as a representation/lowering fact, not a parser/analyzer AST trick. The analyzer's semantic `SpecObject` remains a dynamic-object type; `omega-analyzer::layout` continues to give it two pointer leaves, checked/MIR nodes carry the canonical semantic shape and deterministic vtable slots, and codegen continues to materialize `[data pointer, vtable pointer]` with statically emitted vtables. No allocation, runtime registry, or hidden table construction is introduced.
  - Replace named spec-alias dependencies with a first-class resolved **spec shape**: a canonical list of resolved spec applications `(spec declaration, resolved type arguments)`. A conjunction is commutative and idempotent at the semantic type level: resolve every member to its final declaration first, normalize transparent aliases/type arguments when that machinery exists, collapse exact duplicate applications, then sort the remaining applications by fully qualified final spec name with a canonical normalized-argument key as the deterministic tie-breaker. Therefore `*spec B + A` normalizes to the same shape as `*spec A + B`, and a given concrete type emits/reuses one compile-time vtable for that canonical shape rather than one table per source spelling. Source order must never participate in semantic equality, mangling, vtable cache identity, or ABI layout.
  - Preserve current zero-hidden-work narrowing semantics: a conjunction object may narrow to one member already represented by a canonical vtable section (with mutability only becoming less permissive), using a compile-time slot offset. Reordering is not a conversion at all because reordered conjunctions normalize to the same semantic shape. Do not add widening or arbitrary multi-member sub-conjunction reconstruction in this task.
- **Rejected alternatives:**
  - Do not parse `*spec A` directly into a dynamic/fat-pointer AST node; that would conflate grammar with semantic representation and repeat the current awkward special case in reverse.
  - Do not perform `Pointer(SpecStatic) -> SpecObject` in HIR. HIR is syntax-only and cannot correctly resolve spec identity, generic arguments, object safety, or semantic shape equality.
  - Do not leave an ordinary resolved `Pointer { pointee: Spec..., ... }` until MIR/codegen. Ordinary pointers are currently one-word pointer-like types and participate in pointer arithmetic/casts/layout; allowing this form to survive semantic analysis would give the dynamic object the wrong type semantics and representation.
  - Do not retain `spec Name = ...` internally as an undocumented alias mechanism. Remove the spec-specific alias/dependency path now; a future transparent `alias` feature should alias a spec-conjunction type through the general alias machinery instead of reviving pseudo-spec declarations.

## Technical Details
- **Initial context boundary:** Start with `docs/language/specs-and-conformance.md`, `docs/language/grammar.md`, `docs/architecture/parsing-and-hir.md`, `docs/architecture/semantic-analysis.md`, `docs/architecture/abi-and-representation.md`, and `docs/architecture/testing-and-validation.md`; then the parser/HIR/analyzer type pipeline and the mangling/vtable consumers listed below. Root conformance coverage currently lives mainly in `tests/t11_specs_and_conformance/`, with old dynamic spelling also used by `t13_visibility` and `t16_marker_types`.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/ast/type.rs`: make `Type::SpecStatic` carry the conjunction members (or an equivalent dedicated raw shape) and remove `Type::SpecObject`.
  - `compiler/omega-parser/src/parser/type.rs`: replace `parse_spec_object_type` with static-spec conjunction parsing; leave `parse_pointer_type` recursive so the new dynamic syntax has the ordinary structural AST.
  - `compiler/omega-parser/src/parser/item/definitions.rs` and `compiler/omega-parser/src/ast/item.rs`: delete the `spec Name = ...` branch and the spec `dependencies` / `is_alias` state. The `=` form must now fail as invalid spec-declaration syntax.
  - `compiler/omega-hir/src/hir.rs` and `compiler/omega-hir/src/lower/item.rs`: remove spec-alias fields; change `desugar_spec_static_params` so only a parameter whose outermost type is `SpecStatic` becomes a fresh generic, transferring the entire member list to that generic's bounds. Delete the recursive behavior in `replace_spec_static` that currently finds `spec` behind `Pointer`, arrays, generic arguments, and function types.
  - Raw-`Type` visitors such as `compiler/omega-driver/src/resolver.rs` and `compiler/omega-analyzer/src/analysis/mod.rs` must traverse every member of the new static shape and stop handling the removed `SpecObject` AST variant.
  - `compiler/omega-analyzer/src/context.rs`: add one reusable raw-shape resolver and make `resolve_pointer_type` intercept an immediate `Type::SpecStatic(...)`; resolve every member to its final spec application, reject non-spec members, resolve/normalize generic arguments, enforce object safety for every dynamic member, collapse exact duplicate applications, sort by the canonical fully qualified final spec name plus canonical normalized-argument key, and only then produce semantic `ResolvedType::SpecObject`. Bare `SpecStatic` in unsupported semantic positions must continue to produce the existing “not allowed here” class of error.
  - `compiler/omega-analyzer/src/resolved_type.rs`: introduce a resolved spec-application/shape abstraction and change `ResolvedType::SpecObject` to carry it plus mutability. Equality/hash/display must operate on the canonical resolved members, so source permutations compare equal and display in canonical final-name order. Remove `ResolvedSpecType::{is_alias, dependencies}`.
  - `compiler/omega-analyzer/src/analysis/specs.rs`: separate “requirements of one named spec” from “requirements/slots of a canonical dynamic shape”. Remove `resolve_spec_dependencies`, alias recursion, `alias_member_ids`, and alias fallback in `type_implements_spec`; shape conformance should instead require each canonical member independently and concatenate each member's method slots in canonical shape order. Simplify bound-set expansion to the existing explicit bound list rather than expanding named spec aliases. Update static spec-requirement returns from one optional `(spec, args)` bound to a resolved conjunction and require an implementation return type to satisfy every member.
  - `compiler/omega-driver/src/items/resolution.rs`, `compiler/omega-driver/src/conformances/registration.rs`, `compiler/omega-driver/src/conformances/solver.rs`, and analyzer resolver/error definitions: remove alias dependency resolution, alias object-safety propagation, `ConformToAliasSpec`, and the spec-dependency-cycle path that exists only for `spec ... = ...`. A named spec is again only a real conformable declaration.
  - `compiler/omega-analyzer/src/analysis/mod.rs`, `analysis/calls/mod.rs`, and `analysis/exprs/operators.rs`: make implicit pointer-to-object coercion, dynamic call lookup, explicit concrete-pointer casts, and object narrowing consume a canonical resolved shape. Compute vtable sections explicitly: each canonical member has its own established slot list and cumulative start offset. Do not infer a member's section start by searching for its first flattened method, because an object-safe spec may legally have zero methods. Same-name requirements from distinct shape members remain distinct and therefore can remain dynamically ambiguous just as current alias conjunctions are.
  - `compiler/omega-analyzer/src/analysis/places/fields.rs` and `compiler/omega-analyzer/src/layout.rs`: retain `.ptr`/`.vtable` behavior and the two-pointer layout; only adapt patterns/helpers to the new shape field where necessary.
  - `compiler/omega-mir/src/mangle/semantic.rs`, `compiler/omega-mir/src/mangle.rs`, and `compiler/omega-mangle/src/{symbol,encode,decode,display}.rs`: give a dynamic spec-object type a mangled canonical-shape identity and render the new `*spec ...` / `*mut spec ...` spelling in canonical final-name order. Preserve the current single-spec wire/symbol identity where possible so a pure source spelling migration does not gratuitously break existing singleton ABI; use a distinct list/shape encoding for multi-member objects rather than string concatenation. Vtable symbols must identify the whole canonical shape, not a synthetic alias name, so source permutations reuse the same symbol/table.
  - `compiler/omega-codegen/src/llvm/{expr,vtable,mod}.rs`: derive vtable emission from the target object's full resolved shape. Change the vtable cache key from `Vec<HirId>` slots alone to the concrete type + resolved shape (or the resulting stable symbol identity); slot-only caching can collide for different shapes, especially marker/zero-method specs. Keep static weak-ODR vtable emission and the two-word object construction unchanged.
  - Documentation examples using the old spelling occur in `docs/language/{specs-and-conformance,types-and-primitives,compile-time-evaluation,marker-types,iteration-and-ranges,visibility}.md`, `docs/architecture/{abi-and-representation,semantic-analysis}.md`, and `docs/guide/{quick-reference,console-io,standard-library}.md`; update only examples/contracts actually affected.
- **Interfaces/invariants:**
  - `spec A + B` denotes one anonymous/static spec constraint requiring all listed members. In function parameter position it creates one fresh anonymous generic with both bounds, not one generic per member; two separate `spec ...` parameters remain independent concrete types.
  - `*spec A + B` is parsed structurally as pointer-to-static-spec, but after semantic type resolution callers see a dynamic spec-object type, never an ordinary one-word pointer to a spec declaration.
  - `*mut spec ...` controls the mutability of the dynamic object's data pointer exactly as current `spec *mut ...` does. An immutable concrete pointer cannot form a mutable object; mutability cannot be gained by object-to-object casts.
  - Every member of a dynamic shape must be object-safe. A static parameter conjunction need not be object-safe. A spec requirement returning `spec A + B` remains implementation-selected/static and makes the declaring spec non-object-safe; an ordinary function returning `spec A + B` remains invalid.
  - Dynamic object runtime layout remains exactly two machine pointers regardless of conjunction size. Member count affects only the static vtable contents/identity, not object size. No allocator, libc, runtime registration, or target-specific machinery is added.
  - Vtable method order is deterministic: resolve and deduplicate exact spec applications, sort members by fully qualified final spec name plus a canonical normalized-argument key, then use each member's established requirement order within its section. Requirement identity remains `(declaring spec, spec arguments, requirement)` rather than name/signature alone. Thus `*spec B + A` canonicalizes to the same semantic shape as `*spec A + B`, while `*spec A + A` canonicalizes to `*spec A`; for any concrete type these spellings converge on one section order, one vtable symbol, and one statically emitted/reused vtable.
  - Narrowing to a single existing member adjusts only the vtable pointer by that member's compile-time canonical section offset and preserves the data pointer. Widening remains rejected rather than synthesizing metadata; source reordering requires no conversion because both spellings resolve to the same canonical shape.
  - `**spec A` remains structurally meaningful: the inner immediate pointer resolves to a dynamic spec object, while the outer pointer is an ordinary pointer to that two-word object. Do not globally reinterpret every pointer that merely contains a spec object somewhere below it.
- **Out of scope:** Implementing the future general `alias` keyword; preserving source compatibility with `spec Name = ...` or `spec *...`; widening or arbitrary multi-member sub-conjunction reconstruction; changing the two-word object ABI; changing conformance coherence; fixing the separately documented same-named cross-module conformance/vtable symbol identity issue unless the new canonical shape encoding strictly requires touching that contract; introducing spec inheritance/dependency declarations.
- **Risks/open questions:** No language-design question should be decided ad hoc during implementation. The canonical ordering key must be based on the fully resolved semantic name, never declaration/discovery IDs whose order can vary by compilation; generic spec applications with the same final spec name must include a deterministic canonical representation of normalized type arguments in the key. If the existing mangling format cannot preserve singleton dynamic-object encoding while adding an unambiguous canonical multi-member shape, stop and surface the exact ABI conflict rather than silently changing all singleton symbols. Likewise, if any non-alias feature is discovered to depend on `ResolvedSpecType.dependencies`, escalate it before deleting that path rather than recreating spec aliases under another name.

## Implementation Plan
1. **Change the raw grammar and AST without changing runtime semantics yet.** In `omega-parser`, make `spec` parse one or more `type-path` members separated by `+`, store them in `SpecStatic`, remove `Type::SpecObject`, and remove `spec Name = ...` declaration parsing/AST fields. Update parser diagnostics/raw type display helpers so old prefix-pointer spellings fail cleanly and new spellings are rendered correctly. Add parser integration coverage before crossing into HIR.
2. **Make HIR preserve the structural pointer/spec boundary.** Remove spec-alias fields from HIR. Replace recursive `replace_spec_static` behavior with top-level parameter desugaring: `value: spec A + B` becomes one fresh generic with bounds `[A, B]`; `value: *spec A + B` stays `Pointer(SpecStatic([A, B]))` and creates no synthetic generic. Update every raw-Type visitor for the new member list/removed variant and add HIR tests that lock this boundary down.
3. **Introduce canonical semantic spec shapes in the analyzer.** Add a compact resolved spec application + canonical shape abstraction in `resolved_type.rs`. Add one normalization helper that resolves every raw member to its final spec declaration, normalizes its generic arguments, removes exact duplicate applications, and sorts by fully qualified final spec name plus a canonical normalized-argument key; object-safety validation is layered on when the shape is being formed for a dynamic object. Use this helper everywhere a conjunction becomes semantic so `A + B` and `B + A` cannot diverge later. In `Context::resolve_pointer_type`, convert only an immediate `SpecStatic` pointee to `ResolvedType::SpecObject { shape, mutable }`; keep unsupported bare static-spec diagnostics and ordinary nested pointer behavior intact.
4. **Remove pseudo-spec aliases from semantic declaration/conformance resolution.** Delete parser/HIR/resolved-spec alias/dependency fields and the driver/analyzer dependency-resolution, alias-conformance prohibition, alias-member expansion, and alias-specific cycle diagnostics. Simplify named-spec requirement flattening to one actual declaration. Make generic bound reasoning use the explicit list of bounds already present on generics. Keep ordinary spec resolution/cycle protection that serves non-alias features.
5. **Generalize static conjunction consumers.** Update top-level anonymous spec parameters and spec requirement return processing so the member list is preserved as one conjunction. A requirement implementation's chosen return type must satisfy every bound member; such requirements remain non-object-safe. Ensure ordinary-function `spec ...` returns and other unsupported bare-static positions still reject the conjunction as they reject a singleton today.
6. **Generalize dynamic conformance, dispatch, and casts over a canonical shape.** Add analyzer helpers that resolve each canonical shape member's requirement slots, concatenate sections in canonical order, and expose compile-time section start offsets independently of whether the member has methods. Use them for expected-type coercion, explicit concrete-pointer-to-object casts, dynamic member lookup/ambiguity, and object-to-single-member narrowing. Treat source permutations as identical types rather than casts; reject widening and arbitrary multi-member reconstruction. Keep `.ptr`, `.vtable`, mutability, and two-leaf layout semantics unchanged.
7. **Carry canonical shape identity through mangling and vtable emission.** Extend `omega-mangle`/MIR semantic mangling to represent a canonical dynamic spec shape and display the new syntax in canonical order, preserving singleton encoding where possible and adding an unambiguous multi-member encoding. Extend `vtable_symbol` to identify the whole canonical shape. In LLVM codegen, consume the already-normalized target `SpecObject` shape when emitting the static vtable and replace the slot-vector-only cache key with concrete+canonical-shape/stable-symbol identity. Assert with tests that one concrete type plus `A + B` and the same concrete type plus `B + A` produce/reuse the same vtable symbol/table. Do not move semantic shape resolution into codegen.
8. **Update normative and architectural documentation together with the behavior.** Rewrite `docs/language/specs-and-conformance.md` and `grammar.md` to make conjunction a type-level `spec` form, remove spec aliases, define the new pointer spelling, commutative/idempotent conjunction semantics, canonical final-name ordering, duplicate handling, deterministic vtable sections, narrowing limits, object-safety rules, and static-return conjunction behavior. Update the other verified language/guide examples. In `docs/architecture/parsing-and-hir.md`, record that HIR only desugars top-level static-spec parameters; in `semantic-analysis.md` record both the `Pointer(SpecStatic) -> SpecObject` normalization boundary and canonicalization algorithm; in `abi-and-representation.md` record that canonical semantic dynamic shapes still lower to two words plus one deterministic statically emitted vtable per concrete-type/shape identity.
9. **Migrate existing tests/examples and run the focused-to-full validation ladder.** Replace old `spec *...` spellings in existing successful conformance cases, replace alias-based conjunction tests with direct `spec A + B` / `*spec A + B`, delete tests whose only contract was supporting spec aliases, and retain equivalent coverage for conjunction satisfaction, ambiguity, narrowing, visibility, markers, generics, and object safety using the first-class shape.

  - `compiler/omega-parser/tests/generics.rs` (or a more appropriately named existing parser integration file): accept `spec A + B`, `*spec A + B`, and `*mut spec A + B`; assert the latter two are ordinary `Pointer(SpecStatic(...))` ASTs; reject `spec *A`, `spec *mut A`, and `spec AB = A + B;` with the intended syntax diagnostic.
  - `compiler/omega-hir/tests/lowering.rs`: replace `spec_parameters_are_found_behind_a_pointer`. Prove a top-level `spec A + B` parameter creates exactly one fresh generic with two bounds, separate static-spec parameters remain independent, and `*spec A + B` creates no synthetic generic and survives structurally for semantic analysis.
  - `compiler/omega-driver/tests/conform.rs`: replace alias-based cases with direct conjunctions. Cover successful concrete-pointer coercion only when all members conform; failure when one member is missing; generic spec applications inside a shape; mutable/immutable coercion; methods from each member; same-name dynamic ambiguity; narrowing to each member; rejection of widening; object-safety rejection if any dynamic member is non-object-safe; duplicate-member normalization; `*spec A + B == *spec B + A` semantic equality/coercion behavior; and a zero-method/marker member to prove section offsets do not depend on finding a first method.
  - Add/adjust spec-requirement return tests for `=> spec A + B`: an implementation-selected concrete return satisfying both succeeds, one satisfying only one fails, the containing spec remains non-object-safe, and an ordinary function still cannot expose this static return form.
  - `compiler/omega-mangle/tests/roundtrip.rs`: round-trip singleton and multi-member dynamic shapes, render `*spec` / `*mut spec` in canonical final-name order, assert `A + B` and `B + A` encode to the same semantic/mangled shape, verify generic arguments disambiguate same-name spec applications, and pin legacy singleton bytes/symbols if the current suite exposes a stable-encoding assertion point.
  - Update `tests/t11_specs_and_conformance`, `tests/t13_visibility`, and `tests/t16_marker_types` to the new spelling. Add focused root case `tests/t25_spec_type_syntax/` exercising `spec A + B` static parameter dispatch plus `*spec A + B` coercion/dynamic calls/narrowing through the real parser→HIR→analyzer→MIR→LLVM path.
- **Specification trace:** The root case must directly prove the revised rules in `docs/language/specs-and-conformance.md`: conjunctions are valid directly in static spec type syntax; pointer syntax forms a two-word dynamic object requiring every shape member; conjunction source order is semantically irrelevant; the analyzer canonicalizes by fully resolved final name plus a canonical normalized-argument key; vtable sections follow that canonical shape; and narrowing selects an already-present member without widening. Parser/driver negative tests prove the corresponding `docs/language/grammar.md` removals of spec aliases and prefix-internal `*` syntax.
- **Negative/diagnostic cases:** Assert the reason, not merely failure, for old `spec *S` / `spec *mut S`, old `spec X = A + B`, non-spec members in a conjunction, non-object-safe members under `*spec`, missing conformance for one conjunction member, mutable-object formation from immutable pointers, ambiguous same-name dynamic calls, widening object casts, and invalid ordinary-function static-spec conjunction returns. Do not add a reordering diagnostic: reordered spellings must normalize to the same type.
- **Regression coverage:** Run the existing parser/HIR suites plus `omega-driver` conformance tests, `omega-mangle` round trips, and the existing root spec/visibility/marker cases. Pay particular attention to generic bound conjunctions (`T: A + B`), which must keep their existing behavior while no longer expanding named spec aliases, and to singleton dynamic objects, whose runtime layout/call behavior must be unchanged apart from source spelling.
- **Commands/target coverage:** Use the narrow sequence `cargo test -p omega-parser`, `cargo test -p omega-hir`, `cargo test -p omega-driver`, `cargo test -p omega-mangle` (plus any directly affected MIR/codegen crate tests), then `./bin/test-runner t25_spec_type_syntax t11_specs_and_conformance t13_visibility t16_marker_types` once compiler/runtime artifacts are built, and finally `just test-all`. Because vtable identity/mangling changes cross codegen/linkage, the focused root run must compile, link, and execute successfully; no additional backend or freestanding matrix is required because the object layout/runtime capability boundary is unchanged.
