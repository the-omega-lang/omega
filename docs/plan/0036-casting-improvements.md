# Cast Improvements

## Task Description
- **Deliverable:** extend Omega casts with an explicit `void` discard cast, warn when a non-`void` cast is used as a bare expression statement, and allow bit-preserving conversion between thin raw pointers and function-pointer values (including `foreign(cc)` function types) without allowing direct reinterpretation between distinct function types.
- **Purpose:** give programmers a clean, explicit way to acknowledge intentionally discarded results, make otherwise-useless cast statements visible, and support low-level address-to-callable interop without turning casts into an implicit ABI-adaptation mechanism.
- **Chosen direction:**
  - `<void>expr` is the explicit discard form. It is valid for any expression, evaluates the operand exactly once, produces no value, and does not emit `no_op_cast`; if the operand diverges, the cast remains divergent rather than hiding `never` from reachability/MIR lowering.
  - A source-level cast used as a bare statement warns whenever its resulting value is non-`void`/non-diverging. This is a statement-use rule, not a new general “unused expression” warning.
  - `ResolvedType::Function` may be reinterpreted to/from a **thin raw `ResolvedType::Pointer`** because both are one pointer leaf. Pointer -> function is allowed for Omega and explicit `foreign(cc)` function types. Function -> pointer is allowed only to an immutable `*T`; producing `*mut T` from a function value would manufacture write permission and remains invalid.
  - Function -> function casts are allowed only when the source and destination function types are already identical (therefore merely a `no_op_cast`). Any difference in signature, variadicness, `self` mode, or calling convention is rejected directly. The programmer may explicitly opt into reinterpretation by going through a thin raw pointer first.
  - The cast never creates an ABI thunk/adapter. A pointer cast to `foreign(c) (...) => T` simply acquires that semantic function type; the convention encoded in the destination type controls a later indirect call. Existing foreign-ABI callability checks remain at the declaration/call boundaries where the ABI is actually relied upon.
- **Rejected alternatives:**
  - Do not add function types to the generic numeric/pointer `CastClass`; that would accidentally enable direct function <-> integer casts and arbitrary same-width function <-> function conversions.
  - Do not make calling-convention differences convertible merely because two conventions lower identically on the current target; function-type identity remains target-independent.
  - Do not use a dummy assignment/local to silence discarded-return warnings; `<void>...` is the language-level acknowledgement.
  - Do not widen this task into a general unused-expression warning, parser redesign, ABI implementation, mangling change, or runtime feature.

## Technical Details
- **Initial context boundary:**
  - semantic owner: `compiler/omega-analyzer`;
  - backend consumer: `compiler/omega-codegen/src/llvm/expr.rs`;
  - representation contract: `docs/architecture/abi-and-representation.md`;
  - normative semantics: `docs/language/strings-casts-arrays-and-slices.md`, with the function/calling-convention identity rules in `docs/language/functions.md` and `docs/language/foreign-function-interface.md`;
  - conformance/testing rules: `docs/architecture/testing-and-validation.md` and the root `tests/` packages.
- **Affected files/symbols:**
  - `compiler/omega-analyzer/src/analysis/exprs/operators.rs` — `Analyzer::analyze_cast`, the existing cast classification helpers, and the explicit function/raw-pointer permission checks.
  - `compiler/omega-analyzer/src/checked.rs` — `CastKind`; add an explicit discard kind so downstream phases do not pretend a `void` cast is a numeric/pointer reinterpretation.
  - `compiler/omega-analyzer/src/analysis/stmts.rs` — bare-expression statement warning policy. Detect **source/HIR cast syntax**, not only `CheckedExpr::Cast`: anonymous-enum casts may become `AnonymousEnumWiden`/construction and pointer -> spec-object casts become `SpecCoerce`, but they are still source casts and must obey the same discarded-cast warning rule.
  - `compiler/omega-analyzer/src/error/warning.rs` — add the structured warning for a discarded non-`void` cast result (use a stable suppressible warning name such as `unused_cast_result`), and update `UnusedReturnValue` guidance to recommend `<void>call()` for intentional discard.
  - `compiler/omega-analyzer/src/error/render.rs` — update stale `InvalidCast` guidance to mention `void` discard and thin-raw-pointer <-> function-pointer conversions; give direct distinct-function-type casts targeted help explaining the required raw-pointer bridge. If `CastToMutablePointer` is reused for function -> `*mut T`, make its help describe why a function value cannot grant writable data-pointer access.
  - `compiler/omega-analyzer/src/resolved_type.rs` and `resolved_type/tests.rs` — make `Display for ResolvedType::Function` faithfully include function-type identity that is currently omitted from diagnostic text: `foreign(c)` / `foreign(sysv64)` for non-Omega conventions and the leading `self` form when `self_mode` is present. This is required so rejected casts between semantically distinct function types do not render the source and destination as the same text. Preserve the existing unprefixed spelling for the Omega convention.
  - `compiler/omega-analyzer/src/comp_eval.rs` — handle the new discard cast kind by evaluating the operand for compile-time effects and discarding its value, following the interpreter's existing no-value sentinel convention rather than leaking the operand as the cast result or adding a new `ConstValue` representation in this task.
  - `compiler/omega-codegen/src/llvm/expr.rs` — lower discard by evaluating the base once and returning zero leaves. Restructure the current cast arm so `void` does not index `llvm_leaves(target_type)[0]` (the `void` leaf list is empty). Function/raw-pointer conversion continues through `CastKind::Reinterpret`; LLVM opaque pointer -> opaque pointer requires no ABI or data transformation.
  - `docs/architecture/abi-and-representation.md` — record function values/function pointers as one pointer leaf alongside thin raw pointers, since the new legal reinterpretation relies on this compiler-wide representation invariant.
  - `docs/language/strings-casts-arrays-and-slices.md` — specify the new discard, warning, and function/raw-pointer cast rules. Add only a short cross-reference in `foreign-function-interface.md` if needed to make clear that casts do not convert calling conventions.
- **Interfaces/invariants:**
  - Cast syntax and grammar do not change: existing `<Type>expression` already accepts ordinary and `foreign(cc)` function types, so `omega-parser`/`omega-hir` need no representation change.
  - `<void>expr` evaluates `expr` exactly once and retains its side effects. Its checked result is `void` when the operand completes and remains divergent/`never` when the operand cannot complete, so analyzer reachability and MIR termination stay correct.
  - A `void` discard is semantically intentional and must not itself trigger `NoOpCast`, including `<void>some_void_expression`.
  - A bare source cast with a usable non-`void` result emits the new warning whether its checked representation remains `CheckedExpr::Cast` or is lowered by analysis to another conversion node. Casts consumed by a binding, assignment, return, argument, operator, tail expression, etc. do not warn merely because they are casts.
  - Existing `UnusedReturnValue` behavior remains for a bare non-`void` call; wrapping that call in `<void>` removes the warning because the result is now explicitly consumed/discarded.
  - Only single-leaf thin `ResolvedType::Pointer` participates in the function bridge. Do not treat slices, strings, spec objects, or other fat/special pointer-shaped types as the bridge merely because they contain addresses.
  - Direct function -> integer and integer -> function casts remain invalid. The programmer can explicitly choose function -> raw pointer -> integer (or the reverse) using the already-supported raw-pointer/integer cast if truly required.
  - Do not validate a `foreign(cc)` function pointer's aggregate ABI merely because a raw address is cast to that type. Existing architecture deliberately permits passing/storing such a function pointer; ABI-shape restrictions apply when the non-Omega signature is actually invoked or declared as an ABI boundary.
- **Out of scope:** new calling conventions, function-pointer syntax, method/static function-reference syntax, ABI thunks, runtime checks for invalid/null code addresses, safe-pointer abstractions, general warning-policy redesign, or changes to LLVM's calling-convention mapping.
- **Risks/open questions:** none requiring a new language decision. If implementation evidence shows function values are not one pointer leaf on any supported target, stop rather than introducing target-specific cast behavior; the current `omega_analyzer::layout` contract says `ResolvedType::Function(_)` is one `Leaf::Ptr`.

## Implementation Plan
1. Update the normative cast rules first in `docs/language/strings-casts-arrays-and-slices.md`: define `<void>expr`, exact evaluation/discard/divergence behavior, the bare non-`void` cast-statement warning, thin raw pointer <-> function rules, and the prohibition on direct distinct-function-type casts. Keep calling convention as type identity and point to `foreign-function-interface.md` rather than duplicating its ABI rules.
2. Extend `CastKind` in `compiler/omega-analyzer/src/checked.rs` with an explicit discard operation. In `Analyzer::analyze_cast`, resolve/analyze the operand as today, then handle `void` before the existing mutability/numeric/fat-pointer/spec conversion machinery. Return a discard checked node, using `never` as the outer expression type when the operand is known to diverge and `void` otherwise.
3. In the same cast analyzer, add a dedicated function/raw-pointer classification before the generic `cast_class` fallback: exact function -> same function is `Reinterpret` and continues through existing `NoOpCast`; function -> immutable thin pointer and thin pointer -> function are `Reinterpret`; function -> mutable thin pointer reports the mutability violation; every non-identical function -> function pair and all other function cast combinations report `InvalidCast`. Do not change `ResolvedType::cast_class`.
4. Update statement analysis in `analysis/stmts.rs` so a bare **HIR cast expression** whose checked result is neither `void` nor divergent emits the new structured warning. Keep the direct-call `UnusedReturnValue` check as a separate rule. Update warning rendering/suppression metadata in `error/warning.rs`, and change the old unused-return help from “bind it to a local” to the explicit `<void>...` spelling.
5. Improve cast diagnostics in `error/render.rs`: keep `InvalidCast` as the semantic error, but make its general cast-family note accurate and add targeted help for distinct function -> function casts (“go through a thin raw pointer if this reinterpretation is intentional”). Ensure function -> `*mut T` explains the no-manufactured-mutability rule.
6. Fix `ResolvedType::Function` display in `resolved_type.rs` so it reflects the identity relevant to these diagnostics: non-Omega conventions render with their source spelling (`foreign(c) ...`, `foreign(sysv64) ...`) and `self_mode` renders as the corresponding leading `self`, `mut self`, `*self`, or `*mut self` parameter form. Add focused unit coverage proving otherwise-identical function types that differ by convention or `self_mode` both compare differently and render differently; this makes the new cast diagnostic actionable.
7. Thread discard through consumers without changing MIR shape: `MirCast` already carries `CastKind`. Update `comp_eval.rs` so the operand is evaluated and discarded under compile-time interpretation. Update LLVM cast lowering so discard evaluates `base` exactly once and yields `vec![]` before any target-leaf indexing; leave pointer <-> function reinterpretation on the existing one-leaf `Reinterpret` path.
8. Update `docs/architecture/abi-and-representation.md` to include function values/function pointers in the one-pointer-leaf representation table and state that this representation compatibility permits bit reinterpretation but does not erase semantic function-type/calling-convention identity.
9. Add focused conformance/component coverage, run the smallest relevant cases first, then the full gate. Do not modify parser/HIR/MIR APIs unless a concrete compile failure disproves the verified existing syntax/data flow.

## Testing
- **New/changed cases:**
  - Add a focused root conformance package (next available `tests/t28_...` slot) that defines an ordinary Omega function returning a value, uses `<void>function_call();`, and proves the function still executes (observable side effect/output) while producing no unused-return warning.
  - In the same positive family, round-trip a real Omega function value through `*void` and back to its exact function type, then call it and verify the result. Do the equivalent with an Omega-defined `foreign(c)` function so the indirect call proves the destination function type still drives the foreign calling convention.
  - Add warning coverage for a bare non-`void` cast such as `<i64>returns_i32();`: compilation succeeds, the cast result is discarded, and the expected diagnostic is the new cast-result warning. Prefer a driver component assertion on `AnalysisWarningKind` for stable semantic identity plus a root `expected.stderr` case for rendered language-facing behavior.
  - Add negative conformance/component cases for direct Omega-function -> `foreign(c)` function cast, direct function-signature mismatch, function -> integer, integer -> function, and function -> `*mut void`. Assert `InvalidCast`/mutability reason rather than merely “compile failed”.
  - Add positive semantic coverage that `*void` (and another immutable thin pointee type if useful) -> `foreign(c) (...) => T` is accepted without triggering foreign aggregate-call ABI validation merely by constructing/storing the pointer.
  - Add analyzer unit coverage for function-type `Display` so diagnostics visibly distinguish calling conventions and `self_mode` where those facts differ.
- **Specification trace:** all source-level conformance cases trace to the updated explicit-cast rules in `docs/language/strings-casts-arrays-and-slices.md`; foreign-function cases additionally trace to `docs/language/foreign-function-interface.md`'s rule that calling convention is part of function type identity and only matters as an ABI boundary when called/declared.
- **Negative/diagnostic cases:** verify the direct distinct-function cast diagnostic names both conventions/signatures distinctly and tells the programmer to use the raw-pointer bridge if intentional. Verify `<void>nonvoid_call();` produces neither `unused_return_value` nor `no_op_cast`; verify a non-`void` bare cast produces `unused_cast_result`.
- **Regression coverage:** run existing `t08_strings_casts_arrays_and_slices`, `t19_foreign_function_interface`, `t19b_foreign_abi_errors`, and `t19c_foreign_abi_call_errors` after the focused new cases because the change touches cast legality, function-type formatting, and foreign indirect-call behavior.
- **Commands/target coverage:** run the focused new package(s) with `./bin/test-runner <case> ...` once compiler/runtime artifacts are built, run the relevant analyzer/driver/codegen Rust tests for the structured warning/type-display/lowering contracts, then `just test-all`. No extra cross-target matrix is required because the legal bridge is defined by the shared one-pointer-leaf representation; existing calling-convention availability checks remain responsible for target-specific `foreign(cc)` validity.
