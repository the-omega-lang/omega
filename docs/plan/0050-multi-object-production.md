# Per-source multi-object emission

## Task Description
- **Deliverable:** Change one `omgc` package compilation from producing one native/text output file to producing a deterministic tree of per-source outputs under the directory passed to `-o`. Every physical, source-bearing local `.omg` file emits exactly one artifact with the corresponding relative path and emit-kind extension. The compiler still performs one whole-package discovery/parse/analyze/MIR pipeline per invocation.
- **Purpose:** Make native emission/linkage granularity explicit and predictable: `foo.omg` owns `foo.o`, nested source paths mirror into the output tree, and libraries/build systems can select/link source objects independently. This also removes the architectural assumption that one semantic compilation implies one native object, improves the gap/capability model's linkage granularity, and creates stable emission identities that later parallel codegen and incremental metadata can build on without making source files semantic compilation boundaries.
- **Chosen direction:** Treat **one physical source file -> one emitted object/artifact** as a durable compiler invariant, not an initial heuristic on the way to arbitrary Rust-style CGUs. Keep semantic compilation, optimization information, dependency tracking, caching, and scheduling conceptually separate from native object ownership: future compiler work may operate at function/body or other internal granularities and may import optimization bodies across source boundaries, but it must preserve the one-source/one-object mapping. `omega-driver` continues to own the complete local package and physical source inventory; MIR assigns final linker identity before emission; a new explicit per-source **emission unit** groups the definitions natively owned by one source; `omega-codegen` builds one independent LLVM module/artifact per emission unit.
- **Rejected alternatives:**
  - One independent compiler invocation per source file: rejected because it would lose/rebuild package/module/query context and require separate-compilation metadata merely to recover facts the current driver already owns.
  - Arbitrary compiler-chosen native CGUs / moving definitions between unrelated source-owned objects: rejected deliberately. Omega wants the source/object correlation to expose linkage and native recompilation granularity to the developer. Future optimization/cache/work partitioning may be more sophisticated without changing native ownership.
  - One function/item per native object: rejected for the same reason; finer internal incremental or optimization nodes do not require finer native artifacts.
  - Having `omgc` package outputs into a static archive or invoke a linker: rejected; archive/library/executable construction remains a build-system/linker responsibility.
  - Implementing incremental compilation, cross-source inline importing/LTO, or parallel codegen in this task: rejected as separate features. This task must make those additive later without forcing another ownership/output refactor.
  - Removing section garbage collection as part of this task: rejected. Multiple objects only help when the final linker/build system can omit whole objects (for example through archive extraction or a selective object list); directly passing every emitted object still retains each selected source object, and unreachable functions inside it still need section-level dead stripping. Keep current `--gc-sections` repository links unless a focused linker workflow proves it is unnecessary.

## Technical Details
- **Initial context boundary:** Start in `compiler/omgc` (CLI/output orchestration), `compiler/omega-driver` (local physical source inventory and `CompiledProgram`), `compiler/omega-mir` (lowering/final symbols), and `compiler/omega-codegen` (request/output model and LLVM declaration/definition passes). Read `docs/architecture/compiler-overview.md`, `docs/architecture/module-driver-and-linkage.md`, `docs/architecture/mir-and-codegen.md`, and `docs/architecture/testing-and-validation.md`; update `docs/guide/compiler-cli.md` and runtime/linking docs where their one-object examples become stale. No Omega language-semantics change is intended.
- **Affected files/symbols:**
  - `compiler/omgc/src/cli.rs`: `Args::output_file`, `-o` parsing/help/tests become an output-directory contract.
  - `compiler/omgc/src/app.rs`: preserve one `Driver::compile` + one MIR lowering pipeline; write a vector of emitted artifacts into the requested tree instead of one file.
  - `compiler/omega-driver/src/roots.rs`, `compiler/omega-driver/src/error.rs`, `compiler/omega-driver/src/compile/mod.rs`: expose deterministic metadata for every source-bearing local module, including its logical `ModulePath` and physical path relative to the local package root, alongside the existing semantic emission modules. Namespace-only directories have no emission unit.
  - `compiler/omega-mir/src/mir.rs`, `compiler/omega-mir/src/lower/mod.rs`, `compiler/omega-mir/src/lower/item.rs`: introduce explicit per-source emission/output ownership after semantic lowering, and add the final symbol to `MirDeclaration` so globals, like functions/foreign bindings, no longer need a module path to be re-mangled by LLVM codegen.
  - `compiler/omega-codegen/src/request.rs`, `compiler/omega-codegen/src/lib.rs`: replace the single-output request/result shape with common compilation configuration + a deterministic list of per-source emission units and a result carrying the owning source/emission identity for each artifact.
  - `compiler/omega-codegen/src/llvm/mod.rs`, `llvm/item.rs`, `llvm/function.rs`, `symbol.rs`: build one fresh LLVM `Context`/`Module`/codegen state per emission unit; separate cross-object declaration from owner definition; define globals only in their owning source unit; validate linker-symbol collisions compilation-wide rather than independently per LLVM module.
  - `bin/test-runner`, `justfile`: compile packages/tests into managed output directories, recursively gather the emitted object set in deterministic path order, and retain current `--gc-sections` behavior. Consumers must no longer infer a single `<package>.o`.
  - Documentation: update `ARCHITECTURE.md`, `docs/architecture/compiler-overview.md`, `docs/architecture/mir-and-codegen.md`, `docs/architecture/runtime-and-platform.md`, `docs/architecture/testing-and-validation.md`, `docs/guide/compiler-cli.md`, `docs/guide/core-library.md`, `docs/guide/standard-library.md`, and `docs/guide/platform-glue.md` only where they currently state/illustrate one object per package or make `std.o`/`core.o`-specific GC claims.
- **Interfaces/invariants:**
  - One `omgc` invocation remains one semantic compilation of the complete local package. Every discovered local source is still parsed/checked regardless of imports; extern packages remain separate semantic compilation units.
  - **Every physical source-bearing local `.omg` file owns exactly one emitted artifact.** Do not skip an artifact merely because the source lowers to no retained definitions; an empty/declaration-only source still has its source-correlated output. Do not invent extra native objects that lack a corresponding local source file.
  - Source files define **native emission/linkage granularity only**. They are not analyzer/query boundaries, and this invariant must not be generalized into “source file is the unit of every compiler phase.” Future semantic/MIR dependency nodes, optimization work, cache entries, or scheduling tasks may be finer-grained.
  - Native ownership is distinct from optimization visibility. This task emits only owned definitions, but the APIs must not make it impossible for a future optimizer to provide a source unit with non-owning MIR/IR bodies or summaries (for example an imported `@inline` body) while still emitting only that source's single artifact and retaining the canonical symbol owner elsewhere.
  - Output layout is based on the physical local source path relative to the package root, not declared package/module identity. For example, `root/child.omg` maps to `<out>/child.o`, and `root/sub/sub.omg` maps to `<out>/sub/sub.o`; an explicit `<name>:<dir>` identity override must not rename those filesystem outputs. Replace `.omg` with `.o` (`.obj` for a Windows object target), `.ll`, or `.s` according to `--emit`.
  - `-o` names an output **directory** for every emit mode. `omgc` creates missing parent directories and overwrites artifacts it owns, but must not recursively delete an arbitrary user-supplied directory. Repository/test build recipes should clear their own managed output directories before a non-incremental rebuild so removed sources cannot leave stale artifacts. This keeps cleanup policy outside the compiler and avoids a disruptive change when incremental compilation later retains per-source outputs/caches.
  - Emission-unit enumeration and artifact write order must be deterministic: sort by physical relative source path. Physical relative path is the stable native emission identity and an obvious future cache key; the same source tree/target/options must produce the same identities and paths independent of filesystem/`HashMap` iteration.
  - MIR remains the owner of final linker symbols/linkage. Assigning a definition to its source-owned emission unit must never alter its symbol. In particular, store the global symbol on `MirDeclaration` rather than rebuilding it in `omega-codegen` from a module path.
  - Each LLVM emission unit must be self-contained for codegen but not for linking: cross-unit functions/globals needed by owned MIR are LLVM external declarations, while only the canonical owning unit attaches bodies/initializers and owner linkage/sections. A declaration alone must not create a native relocation/link requirement; only emitted uses do.
  - Build a compilation-wide lightweight declaration/symbol catalog once, then reuse it for each LLVM unit. Do not clone every full MIR body into every unit merely for name/type lookup. Keep the catalog immutable after emission planning so future worker threads can emit independent source objects without shared mutable LLVM/codegen state.
  - Move symbol-collision checking above the per-unit LLVM modules. Two definitions in different source files that force the same linker symbol must still be rejected exactly as when they shared one LLVM module. Gap/foreign declarations are declarations, not competing definitions; existing gap/glue same-symbol behavior remains valid.
  - Constants/vtables/compiler-generated weak ODR data may continue to be materialized in more than one source object when referenced from multiple units; linker coalescing remains their existing contract and does not create additional output objects.
  - Some concrete generic/method/primitive/conformance bodies emitted by this invocation can have semantic ownership in an extern package and therefore no local physical source. Preserve their declaring module path for symbol identity, but attach such generated native definitions to one deterministic existing local emission unit (source-bearing root when present, otherwise lexicographically first local source) rather than creating a synthetic object. Keep this generated-definition attachment policy isolated from MIR symbol identity and from the source/object mapping so future incremental metadata can model generated-body dependencies without changing artifact topology.
  - Splitting the package into one LLVM module per source creates an ordinary cross-source optimization boundary in this task. Do not implement arbitrary native repartitioning to recover it. Future cross-source optimization may use non-owning body/MIR importing, summaries, ThinLTO/LTO, or other metadata strategies while preserving one source -> one object.
  - Preserve freestanding/embedded behavior: emitting several object files must not invoke a linker, archiver, libc, allocator, thread runtime, or filesystem service beyond ordinary compiler output writes.
- **Out of scope:** incremental dependency/fingerprint caches, MIR/semantic metadata serialization, dirty-node/object reuse, parallel worker scheduling, cross-source `@inline` body importing, LTO/ThinLTO, static/shared-library production, linker invocation, automatic archive extraction policy, changing native ownership away from one-source/one-object, and redesigning runtime source layout merely to obtain finer object granularity.
- **Risks/open questions:** If another emitted-definition category has no local physical source owner, do not create a synthetic object or silently change the 1:1 artifact count; attach it through the same explicit generated-definition policy or stop and extend that policy. If existing MIR contains a definition whose final symbol cannot be assigned before emission ownership, stop and extend the MIR-owned identity model rather than reintroducing module-path-dependent mangling inside LLVM.

## Implementation Plan
1. **Make physical source emission identities explicit in the driver.** In `ModuleRoots`, derive a sorted inventory of every source-bearing local `ModuleLocation::own_file` and strip the local package root to obtain a stable physical relative path. Add a small driver-level source/emission metadata type and return it in `CompiledProgram` without changing package-wide parse/check/query behavior. Add focused driver tests for root files, flat children, directory-shaped modules, namespace-only directories, declared-root renaming, and an otherwise-empty source so physical output identity is complete and cannot accidentally become semantic module identity.
2. **Introduce explicit per-source emission ownership after MIR lowering.** Keep lowering each `(ModulePath, CheckedModule)` using its semantic path so functions/methods/foreign items receive the same symbols as today. Add `symbol` to `MirDeclaration` during `lower_declaration`. After lowering, group natively owned MIR definitions by the driver source-emission identity that owns them; attach extern-owned generated bodies through the deterministic existing-source fallback policy above. Keep emission identity/path metadata distinct from `ModulePath`, and name the new abstraction around emission/object ownership (`EmissionUnit`/equivalent), not around an arbitrary future CGU partition heuristic.
3. **Refactor codegen requests/results around source emission units.** Replace `CodegenRequest.modules` + singular `EmitOutput` with a request carrying common target/optimization/emit configuration and an ordered list of per-source emission units; return ordered artifacts tagged with their source-relative output stem. Preserve component tests that construct `CodegenRequest` directly by updating them to the new shape rather than adding a compatibility one-object path. Keep owned-definition input conceptually distinct from any future non-owning optimization input so cross-source body importing can be added without changing artifact ownership.
4. **Build one compilation-wide native declaration/symbol catalog.** Before LLVM emission, flatten final MIR definitions into the lightweight information required for cross-object references (function id/symbol/signature/calling convention; global id/symbol/type; relevant owner linkage metadata) and include analyzer-provided `ExternFunctionRef`s. Move/extend `SymbolRegistry` validation so conflicting definitions are detected across all source objects before any unit is emitted. Keep declaration-vs-definition distinction explicit so gap declarations and matching glue remain legal.
5. **Split LLVM declaration from canonical definition.** Refactor `declare_function_def`/`declare_foreign_function_def` into reusable reference declaration plus owner-definition configuration; a non-owner source unit gets an external declaration, while the owner sets `External`/`WeakODR`, section, naked attributes, and body. Likewise split global declaration from initialization: non-owner units add an external global with the correct type/alignment as needed, owner units alone set section/linkage/initializer. Remove remaining global-symbol derivation from `llvm/item.rs` and consume `MirDeclaration::symbol`.
6. **Emit exactly one LLVM module/artifact per source emission unit.** Change `llvm::generate` so target initialization/common configuration occurs once per request, then each source unit is emitted through a function that creates a fresh LLVM `Context`, `Module`, builder, and local caches, declares the shared catalog, defines only that unit's canonical owned/generated definitions, verifies the module, and produces its object/IR/assembly buffer. Emit even a source unit with no native definitions so the 1:1 mapping remains exact. Keep emission sequential in this task, but make the unit-emission function free of shared mutable LLVM/codegen state so future scheduling can run source-object jobs in parallel.
7. **Change `omgc -o` to directory output.** Rename CLI/app fields and diagnostics from `output_file` to `output_dir`; update help/usage/tests. For each returned artifact, replace the physical source `.omg` extension with the emit extension and join it under `-o`, creating intermediate directories. Reject an existing `-o` path that is a regular file. Reporting must describe a directory/per-source artifact set rather than one object. Do not add implicit linking or archiving.
8. **Migrate repository consumers to object directories.** Give `core`, `std`, `plat`, playground, and each conformance test a dedicated managed output directory; clear those directories in the current non-incremental build/test harness before each compile; recursively enumerate emitted object files in sorted order when invoking `cc`. Retain `-Wl,--gc-sections`. Ensure `OMEGA_ARTIFACTS_DIR` still relocates the whole test/runtime artifact tree cleanly.
9. **Document the permanent source/object contract and the non-contracts around it.** Replace `CompiledProgram -> Vec<MirModule> -> one object` diagrams/examples with `whole semantic package -> per-source emission units -> one artifact per source`. State explicitly in compiler/linkage architecture docs that physical source files define native emission/linkage granularity, but do **not** define semantic-analysis, optimization-information, incremental-dependency/cache, or general compiler-work granularity. Note that future cross-source optimization may import bodies/metadata without changing canonical native ownership. Update runtime docs to stop referring to monolithic `core.o`/`std.o` as the reason GC is load-bearing: direct-object links still use GC for within-object dead code, while archives/selective linking may omit whole source objects. `omgc` itself still does not link or archive.

## Testing
- **New/changed cases:**
  - Add driver/component tests proving stable `ModulePath` + physical relative source inventory, exactly one emission identity for each local `.omg`, no identity for namespace-only directories, and stable output identity under declared package-name overrides.
  - Add MIR tests proving a global's final symbol is assigned before emission ownership and remains independent of physical source/output path; cover generated extern-template attachment without creating an extra unit.
  - Add codegen component coverage with at least two source units where one calls a function and reads/writes a global defined in the other; assert exactly one artifact per source, cross-object references are declarations rather than duplicate definitions, and an empty/declaration-only source still produces its corresponding artifact. Add a cross-unit forced-mangling collision test so moving `SymbolRegistry` upward cannot regress diagnostics.
  - Add `compiler/omgc` CLI/output-layout coverage for `-o <dir>`, nested source trees, directory creation, refusal of a regular-file output path, exact source/artifact count, and per-emit extensions. Include a declared package-name override whose physical root basename differs, proving outputs mirror disk layout rather than logical identity.
  - Add `tests/t36_multi_object` (or the next free conformance case at implementation time) with at least two source files and a nested module; exercise a cross-file function call and shared global so `bin/test-runner` proves real compile -> multiple source-correlated objects -> link -> execute behavior.
  - Add a focused separate-link workflow test/recipe for the original linkage motivation: compile a small library whose unused source file contains an unresolved external/gap dependency, archive the emitted source objects with the system toolchain, and prove a consumer of another source object links without that missing capability. This demonstrates that source-level native granularity enables lazy whole-object selection; keep archive/linker orchestration outside ordinary language conformance if it would complicate every case.
- **Specification trace:** No Omega language rule changes. `docs/language/modules-and-imports.md` remains authoritative for source/module discovery; this task changes compiler artifact partitioning/tooling and architecture only.
- **Negative/diagnostic cases:** `-o` must clearly reject an existing regular-file path; cross-source linker-symbol collisions must retain the existing collision diagnostic intent; no new semantic diagnostics are expected.
- **Regression coverage:** Existing multi-module root tests become broad cross-object coverage once the runner links all emitted source objects. Pay particular attention to generic methods/instantiations, gaps/glue, vtables/spec objects, globals, naked/foreign functions, runtime atomics, declaration-only/gap-only source files, and declared package identity because they exercise cross-object declarations or generated-definition ownership.
- **Commands/target coverage:** Run focused crate/component tests for `omega-driver`, `omega-mir`, `omega-codegen`, and `omgc`; run `./bin/test-runner t35_atomics t36_multi_object` (using the actual new case name); then `just test-all`. Also perform one `--emit=ir` directory-layout check and one non-default object target (prefer `avr-none` or `x86_64-windows`) to verify per-source target-machine emission and object extension/layout without introducing a linker requirement.
