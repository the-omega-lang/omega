# Naked functions

## Task Description
- **Deliverable:** Add `@naked` function definitions whose source body contains exactly one `asm(...) => { ... }` statement and whose generated function has no Omega/LLVM-generated prologue, epilogue, parameter materialization, local frame, implicit return, or other runtime body instructions outside the user-authored inline assembly.
- **Purpose:** Give low-level/embedded Omega code a typed, normally callable ABI entry point whose implementation fully owns the target machine state. The signature remains useful to callers for type checking and the existing ABI, while the callee body stays raw architecture-specific assembly with no hidden setup or teardown.
- **Chosen direction:**
  - `@naked` is a zero-argument function annotation (`@naked` / `@naked()`) and is not part of the function type, overload identity, mangling, or call syntax.
  - A naked function's signature is still lowered through Omega's existing `AbiSignature`/LLVM function-type path. Parameters, receiver, hidden ABI values such as sret, and the declared return type therefore define the caller-facing ABI exactly as they do today, but **none of those LLVM argument values may be referenced by the naked body**.
  - The post-macro-expansion function body must contain exactly one inline-assembly statement and no tail expression. Naked-body validation is semantic, not a new function grammar.
  - `reg(...)` descriptors are forbidden in the naked function's asm. They require evaluating an Omega runtime expression and may force LLVM to synthesize register moves/spills, contradicting nakedness. `const(...)` remains allowed because it is compile-time textual substitution; `clobber(...)` remains allowed as metadata and emits no instruction. A naked asm's clobbers do not redefine the function ABI or excuse the assembly from obeying the current ABI's register-preservation rules.
  - Function parameters are ABI-only inside a naked function. Omega does not create parameter locals/places, does not warn that such parameters are unused, and does not provide an operand-binding shortcut for them. A `$param` in the asm body is therefore only valid if some allowed descriptor actually binds that name; plain target text is still opaque assembler text.
  - The naked asm owns function control flow. Unlike ordinary inline asm, it may contain the target return instruction, loop forever, tail-jump, alter/restore the stack as required by its ABI contract, etc. Omega does not parse the body to prove that it returns or returns the declared value. Non-`void` and `never` naked functions therefore bypass ordinary Omega return-path checking; violating the declared ABI is programmer error in unsafe raw assembly.
  - `@naked` semantically implies LLVM `naked` **and** `noinline`. Reject any simultaneous `@inline` annotation rather than accepting contradictory/redundant directives.
  - Lower a naked function to one LLVM block containing the existing side-effecting inline-asm call followed by IR `unreachable`. LLVM requires a terminator even though the target asm itself owns control flow; `unreachable` must not become a machine instruction. LLVM's `naked` attribute disables prologue/epilogue emission and forbids IR references to function arguments, matching Omega's model.
- **Rejected alternatives:**
  - Do not lower naked functions through the ordinary `MirBody`/`define_function_def` frame path with a boolean guard sprinkled through storage setup. A distinct MIR function-body variant makes “no parameter/local/return machinery” structural and prevents future ordinary-function changes from silently leaking setup into naked functions.
  - Do not allow `reg(...)` even for apparently simple constants or globals: materializing any runtime register operand gives LLVM permission/need to emit instructions around the asm.
  - Do not parse target instructions to verify `ret`, stack restoration, return registers, parameter registers, clobbers, or control flow. Those remain backend/assembly-author concerns.
  - Do not add calling-convention syntax or change Omega's current ABI in this task; custom calling conventions are the planned follow-up feature.

## Technical Details
- **Initial context boundary:**
  - Language: `docs/language/annotations-and-sizeof.md`, `docs/language/functions.md`, `docs/language/inline-assembly.md`, plus `docs/guide/quick-reference.md` for source examples.
  - Architecture: `docs/architecture/mir-and-codegen.md`. `docs/architecture/abi-and-representation.md` is reference-only for confirming that the existing ABI stays untouched; do not redesign ABI/calling conventions here.
  - Frontend/semantic implementation: `compiler/omega-hir/src/lower/item.rs`, `compiler/omega-analyzer/src/annotations.rs`, `compiler/omega-analyzer/src/analysis/items/bodies.rs`, `compiler/omega-analyzer/src/analysis/asm.rs`, `compiler/omega-analyzer/src/checked.rs`, and analyzer diagnostics.
  - Lowering/backend: `compiler/omega-mir/src/mir.rs`, `compiler/omega-mir/src/lower/item.rs`, `compiler/omega-mir/src/lower/function.rs`, `compiler/omega-codegen/src/llvm/function.rs`, and the already-implemented `compiler/omega-codegen/src/llvm/inline_asm.rs`.
- **Affected files/symbols:**
  - `compiler/omega-analyzer/src/annotations.rs`: add a `naked` fact to `ResolvedAnnotations`; recognize `@naked` only on functions/methods; require zero arguments; diagnose coexistence with any `@inline` mode independent of annotation order.
  - `compiler/omega-hir/src/lower/item.rs::lower_function_def` / `prepend_mut_self_shadow`: a source `@naked` function must not receive the normal synthetic `mut self` shadow binding. This is hidden body setup that is meaningless for ABI-only naked parameters and would also destroy the “one asm statement” invariant before analysis. Keep ordinary methods unchanged.
  - `compiler/omega-analyzer/src/analysis/items/bodies.rs::check_function_body`: add the naked path before ordinary block/return analysis. Still validate/construct the declared parameter list and signature, but validate the expanded HIR body as exactly one `HirStmt::InlineAsm` with no tail; do not perform ordinary body return checking or unused-parameter warnings.
  - `compiler/omega-analyzer/src/analysis/asm.rs`: reuse the existing asm descriptor/binding validation with an explicit naked context/policy that rejects every `reg` descriptor before runtime-expression lowering while retaining `const`, `clobber`, `$name`/`$N`, and `$$` behavior. Do not duplicate the binding scanner.
  - `compiler/omega-analyzer/src/error/kind.rs` (and normal diagnostic rendering path): add focused errors for an invalid naked body, a `reg` descriptor in naked asm, and conflicting `@naked`/`@inline`. Reuse `InvalidAnnotationArgs` for `@naked(...)` arguments and `AnnotationNotApplicable` for non-function items.
  - `compiler/omega-analyzer/src/checked.rs::CheckedFunctionDef`: carry `naked: bool`; keep `body: CheckedBlock` so comp-eval/dead-code infrastructure continues to see the checked inline asm normally. A successfully checked naked body is invariantly one `CheckedStmt::InlineAsm` and no tail.
  - `compiler/omega-mir/src/mir.rs`: replace `MirFunctionDef.body: MirBody` with a structural `MirFunctionBody` (for example `Normal(MirBody)` / `Naked(MirInlineAsm)`) and carry no separate runtime-local representation for naked parameters.
  - `compiler/omega-mir/src/lower/item.rs::lower_function`: when `CheckedFunctionDef::naked` is false, preserve the current `FunctionLowerer::lower` path exactly. When true, extract the single checked asm, lower only its compile-time `const`/metadata `clobber` representation into `MirInlineAsm`, and construct `MirFunctionBody::Naked` without invoking `FunctionLowerer` or creating parameter/return locals. Any `Reg` reaching this point is an analyzer invariant violation.
  - `compiler/omega-codegen/src/llvm/function.rs::declare_function_def`: for naked MIR functions, attach LLVM's enum attributes `naked` and `noinline` at function scope using Inkwell's attribute API. Keep the same `llvm_function_type(&function_def.fn_type())`, linkage, symbol, and section path as ordinary functions.
  - `compiler/omega-codegen/src/llvm/function.rs::define_function_def`: split normal and naked definition paths. The naked path creates one LLVM basic block, emits the existing `process_inline_asm` on the `MirInlineAsm`, emits `build_unreachable`, and stops. It must not call `parameter_storage_plan`, `get_params` for values, `locals_layout`, `entry_alloca`, sret handling, `emit_terminator(Return)`, or any other ordinary function-frame machinery.
  - `compiler/omega-codegen/src/llvm/inline_asm.rs`: preserve the existing opaque-template/side-effect/memory/status-clobber behavior. It already supports an asm with zero `reg` operands, so avoid a second naked-only asm implementation; change only what is required to share it cleanly.
- **Interfaces/invariants:**
  - The function's external type and current ABI are unchanged by `@naked`; callers use the same argument/return lowering as an equivalent ordinary function. Custom calling conventions are not introduced here.
  - No LLVM IR instruction in a naked body may consume a function argument or hidden ABI parameter. The only body IR is the inline-asm call plus `unreachable`.
  - No Omega local frame, parameter home, return slot, defer machinery, implicit return, stack protector attribute, or synthetic runtime setup may be created for a naked function.
  - The target asm is still governed by the existing inline-assembly rules for opaque instruction text, target dialect, `$` binding, constant substitution, backend errors, and no optimization/rewrite of the body.
  - Ordinary inline asm keeps its existing “must fall through / restore stack / may not return from the Omega function” contract. Only the sole asm inside a successfully validated `@naked` function is exempt because it is the entire function implementation.
  - `@naked` is enforced, unlike today's advisory `@inline`; it must never produce `inline_not_enforced`.
  - Macros may produce the sole asm statement: validate naked body shape after macro expansion/HIR construction, not by hard-coding a special parser grammar.
- **Out of scope:** custom calling-convention annotations/keywords, exposing argument-register locations to Omega, automatic ABI register names, naked functions with Omega statements/locals/defer/returns, `reg(...)` in naked asm, asm-goto, module/global asm, interrupt-function ABIs, unwind metadata, automatic callee-saved preservation, or architecture-specific instruction validation.
- **Risks/open questions:**
  - No language-design question remains for implementation. If LLVM 21 rejects or emits unavoidable runtime instructions for the minimal `naked + noinline + asm sideeffect + unreachable` shape on any currently supported Omega architecture, stop and report the target-specific LLVM limitation rather than adding architecture-specific Omega hacks. LLVM's current LangRef defines `naked` as disabling prologue/epilogue and forbidding argument IR references, and Clang uses the same inline-asm-plus-`unreachable` shape.

## Implementation Plan
1. **Specify the annotation and naked function contract first.** Update `docs/language/annotations-and-sizeof.md` to recognize zero-argument `@naked`, its `@inline` incompatibility, and function/method applicability. Add the normative naked-body/signature rules to `docs/language/functions.md`. Update `docs/language/inline-assembly.md` with the naked exception to the ordinary asm function contract and the naked descriptor restriction (`reg` forbidden; `const`/`clobber` allowed). Add a compact source example to `docs/guide/quick-reference.md`. Do not add a calling-convention design or an issue entry for that future work.
2. **Resolve `@naked` semantically.** Extend `ResolvedAnnotations`/`resolve` in `compiler/omega-analyzer/src/annotations.rs`; make zero args mandatory and reject any coexisting `@inline` regardless of source order. Propagate `naked` into `CheckedFunctionDef` and every synthetic/test construction that builds one.
3. **Prevent HIR from inventing a naked method body binding.** In `compiler/omega-hir/src/lower/item.rs`, detect the syntactic `naked` annotation when deciding whether to call `prepend_mut_self_shadow`; naked methods keep their receiver in the signature but get no synthetic `self` body shadow. Do not otherwise teach HIR naked semantics.
4. **Add the naked body-analysis path.** In `check_function_body`, validate the post-expansion HIR body before normal statement analysis: exactly one `InlineAsm`, no other statements, no tail. Preserve parameter/signature validation but suppress ordinary unused-parameter analysis and skip `check_function_return`. Analyze the asm with a naked policy that rejects any `reg` descriptor while sharing existing `const`/`clobber` and `$` binding logic. Emit one focused body-shape diagnostic instead of cascading diagnostics from forbidden Omega statements.
5. **Make nakedness structural in MIR.** Introduce `MirFunctionBody::{Normal, Naked}` in `compiler/omega-mir/src/mir.rs`. Keep ordinary lowering untouched; for naked functions, convert the single checked asm directly to `MirInlineAsm` and never instantiate `FunctionLowerer`, parameter locals, defer state, or return slots. Update any MIR consumers/tests to match the new body enum rather than weakening its invariant.
6. **Emit a real LLVM naked function.** In `compiler/omega-codegen/src/llvm/function.rs`, attach `naked` and `noinline` during declaration. In definition, match `MirFunctionBody`: preserve the current normal path byte-for-byte for `Normal`; for `Naked`, create one entry block, emit `process_inline_asm`, then `unreachable`. Reuse the existing LLVM function type so callers still pass/receive values through the current ABI, but never call `get_params()` to materialize them in the naked path.
7. **Document the architecture boundary.** Update `docs/architecture/mir-and-codegen.md` with the `MirFunctionBody` invariant and LLVM lowering shape (`naked noinline`, side-effecting inline asm, `unreachable`, no storage/return lowering). No `AGENTS.md` or skill update is needed: current agent routing already directs annotation semantics to language docs/analyzer and backend emission to MIR/codegen; do not add feature-specific agent instructions.
8. **Run focused validation and then the full gate.** Resolve any compiler construction/test fallout from the new `naked` field/body enum without refactoring unrelated annotation, MIR, ABI, or codegen machinery.

## Testing
- **New/changed cases:**
  - Add `compiler/omega-driver/tests/naked_functions.rs` for semantic/component coverage: zero-arg `@naked` acceptance; non-`void` naked functions accepted without an Omega `return`; parameters retained in the checked/MIR signature but unavailable through `reg`; `const`/`clobber` accepted; empty/multiple/non-asm/tail-expression bodies rejected; `@naked(...)` arguments rejected; any `@inline` coexistence rejected; non-function applicability uses the normal annotation diagnostic; a naked method/receiver (including the existing mutable-self desugaring case) still validates as one raw asm body.
  - In the same driver/MIR-level coverage, inspect the lowered naked function and assert it is `MirFunctionBody::Naked` rather than a normal body with parameter/local slots. This protects the architectural no-materialization invariant independently of LLVM output.
  - Add a codegen-focused test around `omega_codegen::generate` (use a small manually-built naked MIR fixture if that keeps dependencies smaller) and check emitted LLVM IR contains the `naked` and `noinline` function attributes, exactly one side-effecting asm call, and `unreachable`, with no IR use of declared parameters and no `alloca`/ordinary `ret` in that function.
  - For X86-64, emit assembly at both `O0` and `O3` for a distinctive naked body such as `mov eax, 123` + `ret`; inspect the function region rather than whole-file formatting and prove there is no compiler-generated `push`/`pop`, stack adjustment, frame setup, implicit return, or register-move setup around the asm. Directives/alignment and assembler-selected encoding are not body instructions and must not make the test brittle.
  - Add root conformance case `tests/t24_naked_functions/`: call a typed naked function returning a known integer, and call a naked function with ordinary parameters whose x86-64 body manually consumes the current target ABI locations. The program must produce the expected values with no compile warnings on stderr, which also verifies ABI-only parameters are not diagnosed as unused.
- **Specification trace:** root `t24_naked_functions` proves the new `@naked` rules in `docs/language/functions.md` / `docs/language/annotations-and-sizeof.md` and the naked exception in `docs/language/inline-assembly.md`.
- **Negative/diagnostic cases:** explicitly assert the intended `AnalysisErrorKind` for invalid naked body shape, naked `reg`, `@naked` arguments, and `@naked` + `@inline`; do not accept an arbitrary compile failure as coverage.
- **Regression coverage:** rerun existing `compiler/omega-driver/tests/inline_assembly.rs`, annotation tests/conformance (`t15_annotations_and_sizeof`), normal functions (`t05_functions`), and inline assembly (`t23_inline_assembly`) to prove ordinary asm still falls through and ordinary functions still use the existing frame/return path.
- **Commands/target coverage:** run focused Rust tests for the touched crates, `./bin/test-runner t24_naked_functions t23_inline_assembly t15_annotations_and_sizeof t05_functions`, then `just test-all`. Add a backend smoke that emits a minimal target-appropriate naked asm body for each currently supported `Arch` (`X86_64`, `X86`, `Armv7`, `Thumbv7em`, `Aarch64`, `Riscv32`, `Riscv64`); if a target's LLVM backend cannot honor naked emission, surface that limitation instead of weakening the semantics globally.
