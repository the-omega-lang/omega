# Flatten Anonymous Enums and Make Their Origin Explicit

## Task Description
- **Deliverable:** revise the existing anonymous-enum implementation so every anonymous enum is a recursively flattened structural set of member types, while type inference is forbidden from synthesizing a new anonymous enum. An already-established anonymous-enum type may still flow through ordinary expected-type propagation and generic inference.
- **Purpose:** make anonymous enums compose naturally through aliases and generic substitution without turning Omega into a language with inferred union joins. `enum A | enum B | C`, an alias such as `alias AB = enum A | B; enum AB | C`, and a generic substitution that places `AB` as an immediate anonymous-enum member must all become the same `enum A | B | C` type. Conversely, `if cond { A } else { B }` remains an error unless an anonymous enum was already established by an explicit type position such as a local annotation, parameter/return type, alias expansion, or generic instantiation.
- **Chosen direction:** make flattening part of `ResolvedAnonymousEnum` canonicalization: recursively open only immediate anonymous-enum members, then sort by the existing structural type key and deduplicate. Named enums and all other type constructors remain atomic members. Preserve the existing exact-member injection, `u16` tag, refinement, and no anonymous-enum subset/superset conversion rules. For expected-type propagation, fix `match` to consume its surrounding expected type just as `if` already does; do not add anonymous-enum-specific branch inference.
- **Rejected alternatives:** do not flatten in the parser/HIR; do not flatten through pointers, arrays, function types, generic containers, or named enums; do not make aliases nominal flattening barriers; do not infer a least-upper-bound anonymous enum from unrelated branch/arm types; do not try each anonymous member as an inference candidate; do not add implicit anonymous-enum-to-anonymous-enum widening/retagging. Future error-propagation syntax may define an explicit/visible widening operation separately.

## Technical Details
- **Initial context boundary:**
  - semantic owner: `compiler/omega-analyzer`, starting with `src/resolved_type.rs`, `src/context.rs`, `src/analysis/exprs/mod.rs`, and `src/analysis/patterns.rs`;
  - normative docs: `docs/language/enums-and-pattern-matching.md`, `docs/language/control-flow-and-operators.md`, `docs/language/generics.md`, and the anonymous-enum identity paragraph in `docs/language/aliases.md`;
  - durable compiler invariant: `docs/architecture/types-layout-and-const-eval.md`; touch `docs/architecture/symbol-mangling.md` / `abi-and-representation.md` only to clarify that downstream consumers receive the already-flattened canonical leaf list, not to change ownership;
  - conformance: `tests/t27_anonymous_enums`, `tests/t27b_anonymous_enum_errors`, `tests/t04_control_flow`; keep `tests/t27c_anonymous_enum_boundary_errors` as a regression because its boundary rules are unchanged.
- **Affected files/symbols:**
  - `compiler/omega-analyzer/src/resolved_type.rs` — `ResolvedAnonymousEnum::canonicalize`, `members`, `index_of`, and their comments. `canonicalize` becomes the one flatten/dedup/order boundary. Its stored `members` invariant is: no immediate member is `ResolvedType::AnonymousEnum`; every such member has been recursively replaced by its canonical members. A refined anonymous enum, if one ever reaches this helper, is flattened by shape rather than retained as a member because refinement is not type/storage identity.
  - `compiler/omega-analyzer/src/context.rs` — `Context::resolve_anonymous_enum_type` continues to resolve/validate written members independently, then calls canonicalization and applies `ResolvedAnonymousEnum::exceeds_tag_domain` **after flattening**. Do not duplicate recursive flattening here.
  - `compiler/omega-analyzer/src/analysis/exprs/mod.rs` — pass `expected` from `Analyzer::analyze_expr` into `Analyzer::analyze_match` instead of dropping it.
  - `compiler/omega-analyzer/src/analysis/patterns.rs` — thread the match-result expected type through `analyze_match`, `analyze_enum_match`, `analyze_anonymous_enum_match`, and `analyze_value_match`; make `analyze_match_arm_body` analyze/coerce a bare expression against that expected type, while codeblock arms use `analyze_block(..., expected)`. Apply the same expectation to catch-all and `else` bodies. Keep `unify_match_arm_types` as the post-check compatibility step; it must never synthesize a union.
  - `compiler/omega-analyzer/src/resolved_type/tests.rs` — replace the current “nested member is not flattened” contract with recursive-flattening tests and strengthen the tag-domain boundary test so flattening can cause the final member count to exceed `u16` capacity.
  - `compiler/omega-parser/tests/anonymous_enums.rs` — grammar does not change. Keep the right-nested AST test for `enum C | enum A | B`, but update its wording to state that parser nesting is source structure only and semantic resolution flattens it later.
  - No production change is expected in `aliases.rs`, `generics.rs`, `layout.rs`, MIR, codegen, or mangling: alias expansion/generic substitution feed resolved member types into the same canonicalizer, and downstream phases already consume the canonical shape. If implementation work discovers a second production path that constructs a fresh anonymous-enum member list without `ResolvedAnonymousEnum::canonicalize`, route it through the canonicalizer rather than teaching that subsystem a second flattening rule.
- **Interfaces/invariants:**
  - Anonymous enums are structural sets of **leaf member types**. Anonymous-enum boundaries are erased recursively only when they occur as immediate anonymous-enum members.
  - Named enums are nominal/atomic: `enum Named | C` has members `Named` and `C`, regardless of `Named`'s variants.
  - Other constructors are boundaries: if `Inner = enum A | B`, then `enum *Inner | C` has members `*Inner` and `C`; it does not become `*A | *B | C`. The same applies to arrays, function types, and generic arguments.
  - Aliases add no boundary. `alias Inner = enum A | B; alias Outer = enum Inner | C;` resolves to the same type as `enum A | B | C`.
  - Generic substitution re-enters the same resolved canonicalization. If an immediate member parameter resolves to an anonymous enum, its members flatten into the outer shape; duplicates introduced by substitution disappear before tags/layout are assigned.
  - Flatten first, then deterministic structural sort, then exact deduplication. The final canonical list alone drives equality/hash, tags, layout, const values, pattern coverage, and mangling. Downstream phases must not re-sort.
  - A single-member anonymous enum stays an anonymous enum (`enum A != A`); flattening/deduplication never removes the wrapper itself.
  - The `u16` member limit is checked on the final flattened/deduplicated member list.
  - Type inference may **propagate** an anonymous enum that already exists because of an explicit type position/signature/alias/instantiation, including inferring `T = Errors` for `identity<T>(x: T)` when `x` already has explicit type `Errors`. It may not construct/join `A` and `B` into `enum A | B` merely to make an untyped expression type-check.
  - Expected-type checking may inject an exact member into an already-known anonymous enum. This includes branch/arm checking for an explicitly typed `if`/`match`, function returns, parameters, fields/elements, and future `Result<..., enum ...>` payload contexts. This is checking against an existing type, not anonymous-enum inference.
  - Existing conversion rules remain: member -> anonymous enum is explicit checked-tree construction; refined named-enum variants may inject through their parent representation as today; anonymous enum -> different anonymous enum remains rejected even when one canonical member set is a subset of the other.
  - Anonymous-enum match patterns name final canonical leaf members. An alias that itself resolves to an anonymous enum is not a grouped pattern for several leaves after flattening; those leaf types must be matched individually.
  - The previous nested-anonymous-enum source form intentionally changes ABI/layout/mangling because it now denotes a different (flattened) type. Existing already-flat anonymous-enum shapes retain their current canonical ordering/representation. Do not add compatibility encoding for the old nested semantics.
- **Out of scope:** error propagation/`?`-like syntax; implicit subset/superset widening or runtime retagging; anonymous-enum least-upper-bound inference; grouped “match this sub-union” patterns; named-enum flattening; new syntax/parenthesized types; parser grammar changes; C aggregate ABI work; changes to refinement/`&mut`/assignment rules; edits to historical `docs/plan/0032-anonymous-enums.md`.
- **Risks/open questions:** none blocking. The language decisions are settled. If recursive flattening cannot be centralized because a production path constructs anonymous shapes outside `Context::resolve_anonymous_enum_type`/`ResolvedAnonymousEnum::canonicalize`, stop and consolidate that path rather than duplicating normalization.

## Implementation Plan
1. **Make the resolved shape invariant true first.** In `compiler/omega-analyzer/src/resolved_type.rs`, change `ResolvedAnonymousEnum::canonicalize` to recursively collect immediate `ResolvedType::AnonymousEnum` members into one vector, preserving every non-anonymous type atomically, then sort with `type_key::structural_key` and deduplicate. Update the nearby contract comments. Add/adjust `resolved_type/tests.rs` before touching expression analysis: recursive nesting equals the flat spelling; duplicates across nested shapes collapse; a named enum remains one member; a pointer/generic-container member containing an anonymous enum remains one member; the tag-domain check observes the flattened count.
2. **Keep resolution as the single semantic entry point.** In `context.rs`, update `resolve_anonymous_enum_type` comments and verify its current order remains resolve/validate -> canonicalize/flatten -> `exceeds_tag_domain`. Do not put alias- or generic-specific flattening into `aliases.rs` or `generics.rs`; add only the tests needed to prove that their resolved output is normalized by the shared shape constructor.
3. **Propagate explicit expected types through `match`.** Change `Analyzer::analyze_expr` to call `analyze_match(..., expected)`. Thread that expectation through each match analyzer in `analysis/patterns.rs`. For every arm, catch-all, and `else`, analyze the result under the expected type; for a bare arm expression, explicitly run `coerce_to_expected` after `analyze_expr`, matching `analyze_block`'s tail behavior. This allows an explicitly known `enum A | B` to inject `A`/`B` arm results without inventing a union, and fixes the broader inconsistency where `match` currently discards ordinary surrounding expected types.
4. **Do not add anonymous-enum synthesis to inference.** Audit the touched inference paths only far enough to verify the invariant: fresh anonymous shapes are still created by explicit type resolution, not by `if`/`match` branch joining, generic unification, overload resolution, or literal inference. Preserve current `conversion_cost` / `injects_into` exact-member semantics. Add regression tests rather than new inference machinery.
5. **Update language and architecture documentation.** In `enums-and-pattern-matching.md`, replace the “nested member remains nested” rule with recursive flattening and leaf-member matching, state alias/generic-substitution transparency, and add the explicit-origin/no-synthesis rule. In `aliases.md`, say an alias to an anonymous enum does not create a flattening boundary. In `generics.md`, distinguish legal propagation/inference of an already-established anonymous enum (`T = Errors`) from forbidden synthesis of a new anonymous enum. In `control-flow-and-operators.md`, state that a surrounding expected type is used to check value-producing `if` branches and `match` arms, while an untyped branch join does not manufacture an anonymous enum. Update `types-layout-and-const-eval.md` (and the short mangling/ABI wording if needed) so “canonical member list” explicitly means the flattened leaf list consumed downstream.
6. **Revise end-to-end anonymous-enum coverage.** Update `tests/t27_anonymous_enums` so the old nested case now proves flattening: an alias containing another anonymous enum matches/injects through the final leaves, while the named enum member remains atomic. Add an alias/generic-substitution flattening case, an explicitly typed local `if`, and an explicitly expected `match` whose arms return different leaf types. Preserve the existing generic `wrap(boxed.value)` case as evidence that generic inference may carry an already-established anonymous-enum type. Extend the helper module so a nested/aliased spelling in one module agrees with a directly flat spelling in the other on calls/tags/symbols.
7. **Add focused rejection/regression coverage.** In `tests/t27b_anonymous_enum_errors`, add an unannotated `if` (and a `match` if useful for localization) whose branches/arms have different concrete types and assert the normal type-mismatch diagnostic rather than any inferred anonymous enum. Add a pattern case showing that an alias resolving to a flattened sub-anonymous-enum is not itself a member/grouped arm. Keep the existing no subset/superset widening case. In `tests/t04_control_flow`, add one small non-anonymous expected-type `match` case so the newly threaded expected type is intentionally covered as a general control-flow rule rather than an anonymous-enum special case. Keep `t07_enums_and_pattern_matching` and `t27c_anonymous_enum_boundary_errors` in the focused regression run; named-enum/refinement and boundary behavior must not change.
8. **Run the smallest cross-boundary verification and then the full gate.** No MIR/codegen/mangle source change should be necessary: the new shape semantics flow through their existing shared representation. If downstream failures appear, fix assumptions that a canonical anonymous member may itself be an anonymous enum; do not add a second flattening pass downstream.
