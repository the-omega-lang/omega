# Inline assembly

## Task Description
- **Deliverable:** Add statement-level inline assembly to Omega across parser -> HIR -> analyzer -> MIR -> LLVM codegen, using architecture-neutral Omega operand descriptors and an otherwise backend-owned assembly body. Initial source shape:
  ```omega
  asm(
      reg(<expr>),
      reg(<expr>, "<optional physical register>"),
      const(<named comp binding>),
      clobber("<physical register>"),
      ...
  ) => {
      <target assembly using $operand bindings>
  }
  ```
  `asm` is effect-only and produces no Omega value. `reg(expr)` evaluates `expr` by value and exposes that value through exactly one backend register operand. `reg(&x)` / `reg(&mut x)` pass addresses explicitly when assembly needs to touch Omega storage. `const(name)` exposes a named `comp` value for textual immediate use without a runtime register. `clobber("...")` declares additional target registers/state that the body may destroy without receiving a value through them.
- **Purpose:** Provide low-level/embedded code direct inline assembly without importing GCC/Rust `in`/`out` semantics, without teaching Omega architecture-specific instruction grammars, and without hidden runtime support or implicit writeback.
- **Chosen direction:**
  - `asm`, `reg`, `const`, and `clobber` stay contextual rather than becoming globally reserved keywords.
  - The body is **not Omega syntax**. Once the outer asm block is recognized, its contents are forwarded as backend assembly text. Omega comments do not exist inside the body; characters such as `#`, `;`, `//`, register names, instruction mnemonics, and architecture punctuation belong exclusively to the selected assembler syntax.
  - Omega performs only one body-level transformation: operand binding. `$name` refers to an obvious named `reg`/`const` descriptor (`reg(x)`, `reg(&x)`, `const(SIZE)`), and `$N` refers to the zero-based bindable operand position (`reg`/`const`, never `clobber`) for complex expressions that have no usable inferred name. Omega rewrites these source bindings to the LLVM template slots or literal constant text required by codegen; it does not parse instructions.
  - The asm body is **optimization-opaque and semantically sacrosanct**. Omega must never fold, delete, combine, reorder, substitute, vectorize, or otherwise optimize instructions written inside the body. After operand binding, the instruction text is handed to LLVM as one side-effecting inline-asm template. LLVM may optimize surrounding Omega code, but the inline-asm template itself is not an IR instruction stream that LLVM is allowed to optimize instruction-by-instruction.
  - `$$` is the source escape for one literal `$` in final target assembly. Preserve `$$` when constructing LLVM's template because LLVM itself defines `$$` -> literal `$`; do not collapse it prematurely in Omega.
  - Use exactly one assembler dialect per architecture. X86/X86-64 use LLVM Intel dialect only. Do not expose an AT&T/Intel switch. Other architectures use the single syntax selected for that backend/target.
  - `reg(expr)` is a by-value snapshot with **no implicit writeback**. The asm may overwrite the allocated machine register, but the resulting register value is discarded. To mutate an Omega object, assembly must explicitly write through an address such as `reg(&mut x)` (or `reg(&x)`; asm-body mutability is not checked).
  - `reg(expr)` performs no implicit cast to `usize`, no aggregate decomposition, no ABI flattening, and no memory fallback. Preserve the real machine-relevant LLVM type. Uniformly impossible language shapes should be rejected before MIR; final target/register representability is a backend decision.
  - `reg(expr, "...")` supplies an opaque target physical-register name. Omega's frontend does not know that `"rcx"`, `"x0"`, etc. are valid; LLVM/backend validation owns that.
  - Because Omega deliberately has no `in`/`out` syntax, every `reg` must be safe for the body to overwrite. LLVM plain inputs may not be written, so codegen must model each Omega `reg` as a writable synthetic output tied to its input, discard the output, and keep this bookkeeping completely out of Omega semantics.
  - `clobber("...")` is required for physical scratch registers the body modifies **in addition to** registers supplied by `reg`. A `reg(x, "rax")` already tells LLVM that the register carrying `x` may be destroyed; adding `clobber("rax")` for the same register is redundant/conflicting. Omega must not inspect instructions to infer scratch-register usage.
  - Treat every ordinary asm block conservatively as side-effecting and able to read/write arbitrary memory. Emit LLVM side-effect/memory-clobber metadata plus the backend's conservative target status/flags clobbers. This intentionally gives up some optimization freedom because Omega refuses to inspect the body; it must not synthesize language-visible memory operations.
  - Runtime `reg` expressions evaluate exactly once, left-to-right, in descriptor order. `const` and `clobber` descriptors perform no runtime evaluation.
  - Normal Omega checking still applies to expressions **outside** the body: `reg(&mut x)` must itself be legal Omega. The backend body is not checked against Omega mutability. `reg(&x)` and `reg(&mut x)` become equivalent address-valued asm operands for backend purposes. Inline asm never proves definite initialization.
  - Preserve the user's instruction sequence as closely as the target assembler permits. Omega must not synthesize hidden semantic wrappers, output stores, allocations, helper calls, or replacement instruction sequences for the body. LLVM may still insert register copies/spills/reloads **around** the inline asm to satisfy register allocation, fixed-register constraints, clobbers, and surrounding live values. The target assembler may also choose encodings or expand target-defined aliases/pseudo-instructions; therefore the language guarantees preservation of the inline-asm instruction template/semantics, not byte-for-byte machine encoding. Users requiring exact bytes must use whatever raw-data/directive mechanism the selected assembler provides.
- **Rejected alternatives:**
  - GCC/Rust-style `in`/`out`/`inout` and language-level output operands: contrary to Omega's value/address model and would create implicit writeback semantics.
  - Treating `reg` as `usize`-castable: breaks natural floating-point register use and erases useful type information.
  - Plain LLVM input constraints for `reg`: illegal if the body writes the operand register.
  - Automatic instruction/clobber/mutability analysis: would require architecture-specific assembly parsing in Omega and still would not match LLVM's correctness model, which relies on constraints/flags rather than interpreting the template.
  - Clobbering every target register around every asm: safe but would create unnecessary register pressure and surrounding save/reload work, defeating the minimal-overhead goal.
  - Any inline-asm optimization mode or compiler attempt to improve the user's instruction sequence: rejected. Choosing raw architecture-specific assembly is an explicit request to execute that sequence, not an invitation for Omega to optimize it.
  - Omega comments inside asm with escapes for conflicting target syntax: rejected. The body is pure backend assembly instead.
  - Memory descriptors (`memory(x)`) or implicit aggregate splitting in this feature: users pass addresses explicitly; revisit only with a separate design need.

## Technical Details
- **Initial context boundary:**
  - Start with `ARCHITECTURE.md`, `AGENTS.md`, `docs/architecture/parsing-and-hir.md`, `docs/architecture/semantic-analysis.md`, `docs/architecture/mir-and-codegen.md`, and `docs/architecture/testing-and-validation.md`.
  - Normative docs: `docs/language/lexical-structure.md`, `docs/language/grammar.md`, `docs/language/bindings-and-mutability.md`, `docs/language/compile-time-evaluation.md`, plus a new inline-assembly chapter. User-facing examples belong in `docs/guide/quick-reference.md`.
  - Implementation pipeline: `compiler/omega-parser` -> `omega-hir` -> `omega-analyzer` -> `omega-mir` -> `omega-codegen/src/llvm`.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/lexer.rs`: add an opaque raw-asm-body capture path after the contextual `asm(...) => {` shape is committed. The raw capture must preserve bytes/text/newlines and must **not** recognize Omega comments. The outer block delimiter still needs architecture-neutral brace balancing; nested braces are preserved as body text so syntax such as ARM register lists and LLVM-style `${...}` forms do not terminate the block prematurely.
  - `compiler/omega-parser/src/parser/contextual.rs`, `parser/statement.rs`, `ast/statement.rs`, `prelude.rs`, diagnostics/tests: parse the descriptor list (`reg`, `const`, `clobber`) and raw body without interpreting target register strings or instructions.
  - `compiler/omega-parser/src/macros.rs` and `macros/expander.rs`: the raw body is atomic/opaque to Omega macro expansion; normal macros may still affect expressions in `reg(...)` before lowering. `$name`/`$N` inside raw body are asm operand bindings, not macro syntax.
  - `compiler/omega-hir/src/hir.rs` and `lower/statement.rs`: add `HirStmt::InlineAsm` plus source-oriented descriptor/body structures with spans, source order, optional physical-register strings, and raw body text.
  - `compiler/omega-analyzer/src/checked.rs`, `analysis/stmts.rs`, `error/kind.rs`: type-check each `reg` expression normally; reject values that are uniformly not one-register operands (void/never, aggregate/fat language values, etc.) while leaving target-specific legality to codegen. Resolve `const(name)` only to named storage-less `comp` bindings and convert supported scalar constant values to deterministic assembler text. Validate source `$name`/`$N` references without parsing the surrounding instruction text. Preserve `clobber` strings opaquely.
  - `compiler/omega-analyzer/src/comp_eval.rs`: executing an inline-asm statement during `comp` evaluation must fail as an unsupported runtime effect; merely declaring a runtime function containing asm remains legal.
  - `compiler/omega-mir/src/body.rs` and `lower/function.rs`: add an explicit void-typed inline-asm MIR node/payload consistent with the existing `MirBlockData.statements: Vec<MirExprNode>` representation. Carry lowered runtime `reg` expressions, resolved constant text, clobber strings, source binding metadata, raw template, and span. Do not put LLVM constraint letters/register-class decisions into MIR.
  - Add `compiler/omega-codegen/src/llvm/inline_asm.rs` and wire it through `llvm/mod.rs` / `expr.rs`: choose target/type register constraints, construct synthetic writable/tied operands, translate Omega `$name`/`$N` bindings into LLVM template slots or constant text, preserve `$$`, append memory/status/explicit clobbers, choose dialect, create the Inkwell inline-asm value, and emit it with the LLVM 21 indirect-call path.
  - `compiler/omega-codegen/src/llvm/mod.rs::Codegen::finish` and `generate`: object/assembly emission currently uses `expect("... emission cannot fail ...")`. User-authored assembler can legitimately make the integrated assembler reject emission, so convert those paths to `Result` propagation and report backend/user asm errors instead of panicking.
  - Documentation: new `docs/language/inline-assembly.md`; update grammar/lexical cross-references, `docs/architecture/parsing-and-hir.md`, `docs/architecture/mir-and-codegen.md`, and `docs/guide/quick-reference.md`. Agent/skill files do not need changes unless implementation uncovers a genuinely stale workflow/architecture statement.
- **Interfaces/invariants:**
  - The parser owns only the outer Omega construct and binding markers; target assembly semantics never leak into lexer/parser/analyzer.
  - Inside the raw body, no Omega comment stripping or ordinary tokenization occurs. Backend comment syntax is forwarded unchanged.
  - Source placeholder namespace is stable and independent of LLVM constraint numbering. For example, synthetic outputs are ordered before inputs in LLVM, but that order must never change the meaning of Omega `$name` or `$N`.
  - Binding scanning must recognize `$$` before `$name`/`$N` so escaped literal dollars are never interpreted as Omega operands.
  - `const(NAME)` is textual compile-time substitution, not a hidden runtime argument. If target syntax needs an immediate prefix, users write it in target syntax around the binding (for example target-specific `#$NAME`).
  - `reg` preserves the expression's actual scalar/pointer-like LLVM type. The LLVM backend owns the mapping from `(Omega target, LLVM operand type)` to an appropriate target register constraint; do not assume generic `r` is correct for floating point.
  - Every `reg` is conservatively writable. Lower each to an early-clobber synthetic output tied to the corresponding input so LLVM cannot allocate another independent input into a register that the asm may destroy before reading it. Discard all synthetic outputs; never store them back to Omega bindings.
  - Explicit `clobber` entries are pure machine-state declarations: no input value, no output value, no generated initialization instruction. They must appear after LLVM outputs/inputs in the final constraint string as required by LLVM.
  - Every asm is marked side-effecting and conservatively memory-clobbering. Future `nomem`, `readonly`, `pure`, `preserves_flags`, or similar optimization promises are separate language-design work.
  - `reg(&x)` versus `reg(&mut x)` has no backend mutability difference. Do not infer that either one initializes storage, and do not warn because body text appears to write through an immutable pointer.
  - The ordinary function contract survives the asm block: it must fall through normally, restore the stack pointer before leaving the block, and may not secretly return, unwind, or jump into Omega CFG. Internal target-local branches/labels are allowed as backend text. Naked functions/asm-goto are separate features.
  - LLVM/Inkwell facts the implementation may rely on: inline asm is a template plus constraint string/flags; `$N` substitutes operand slots; `$$` emits one literal `$`; outputs precede inputs and clobbers; an input may only be written when tied to an output; Inkwell 0.10 with Omega's `llvm21-1` feature exposes `Context::create_inline_asm(...)` and the LLVM 15+ indirect-call builder path.
- **Out of scope:**
  - Naked functions/prologue suppression, permanent stack-pointer ownership, asm-goto, language-visible asm results, module/global asm, arbitrary unwind/return semantics.
  - Multiple dialects per architecture; x86 AT&T syntax.
  - Memory operands, automatic operand decomposition, instruction parsing, automatic scratch-register inference.
  - Optimizer options that weaken or reinterpret the exact-body rule; target-feature selection.
- **Risks/open questions:**
  - The original request's rule **4** was truncated (`"If there is ..."`). Do not invent a requirement for it; if the missing rule is later recovered and changes semantics, revise the plan before implementation completion.
  - Raw-body delimiting intentionally treats braces structurally without understanding target comments/strings. Nested balanced braces are fine and required for some assembly syntaxes. If a target assembler construct genuinely requires an unmatched brace in raw source, that would need a separate delimiter/escaping decision rather than architecture-specific parsing in Omega.

## Implementation Plan
1. **Write the normative contract first.** Add `docs/language/inline-assembly.md` and update grammar/lexical docs with statement-only `asm(...) => {}`, descriptors, source `$name`/`$N` bindings, `$$`, pure-backend body semantics (no Omega comments), the exact-body/no-optimization rule, by-value/no-writeback rules, register representability, mutability boundary, clobbers, one dialect per architecture, side-effect model, stack/control-flow restrictions, and compile-time prohibition. Clearly distinguish 'instruction template is preserved' from an impossible promise of exact surrounding code or exact machine-byte encoding.
2. **Implement opaque body capture and AST parsing.** In `omega-parser`, recognize the contextual asm statement, parse only its descriptor list with normal Omega grammar, then capture the body raw until the matching outer brace using architecture-neutral brace depth. Preserve target comment characters and punctuation exactly. Add AST structures and diagnostics for malformed descriptors, unmatched outer delimiters, and invalid binding marker syntax detectable without parsing assembly.
3. **Lock down macro behavior.** Keep raw asm body text atomic through parser macro expansion/reparse; allow normal macro expansion in `reg(...)` expressions. Add tests proving target punctuation/comments survive unchanged and `$...` markers are not interpreted as macro syntax.
4. **Lower source structure into HIR.** Add inline-asm HIR nodes preserving raw text, source order, descriptor spans, optional fixed-register strings, and source binding identities without target knowledge.
5. **Analyze descriptors and source bindings.** Type-check `reg` expressions normally; resolve/evaluate named `comp` constants once; reject uniformly impossible register operand shapes; validate `$name`/`$N` references and ambiguous inferred names; preserve physical register/clobber strings opaquely. Do not analyze instructions, mutability effects, or initialization effects. Reject executed asm in `comp` evaluation.
6. **Lower a backend-neutral MIR asm node.** Evaluate each runtime `reg` operand exactly once and left-to-right, carry its resolved type/value plus source binding identity; carry pre-rendered const values and clobbers without runtime work; keep the raw template and span. No LLVM constraint decisions in MIR.
7. **Implement the source-template binder in LLVM codegen.** Scan only Omega binding markers: leave `$$` unchanged; replace `$name`/Omega `$N` referring to `reg` with the eventual LLVM template slot; replace bindings referring to `const` with the pre-rendered scalar literal text. Everything else is copied byte-for-byte. Do not parse mnemonics, target comments, registers, addressing modes, or instruction punctuation.
8. **Implement LLVM constraints/call lowering without exposing the body to optimization.** For each `reg`, choose a backend register class from target + LLVM type unless a physical register string was requested; construct an early-clobber synthetic output tied to the real input; order LLVM constraints as outputs -> inputs -> clobbers; discard return value(s). Add `sideeffect`, conservative memory/status clobbers, explicit `clobber("...")`, `alignstack = false`, `can_throw = false`, and Intel dialect on X86/X86-64. Use Inkwell 0.10 `create_inline_asm` + `build_indirect_call` for LLVM 21. Do not attach purity/read-only/speculation metadata and do not lower the asm text into ordinary LLVM IR operations that optimizer passes could rewrite.
9. **Centralize backend register policy.** In the new LLVM asm module, cover current `Arch` targets (`X86_64`, `X86`, `Armv7`, `Thumbv7em`, `Aarch64`, `Riscv32`, `Riscv64`) for Omega's supported scalar/pointer types. Return a useful backend error when the type cannot occupy one legal register on the selected target/features. Never silently cast through `usize`, split a value, or fall back to memory.
10. **Make assembler failures recoverable.** Change `Codegen::finish`/`generate` to propagate object/assembly emission failures. Invalid instruction syntax, unsupported instructions, bad explicit register names, impossible constraints, or backend assembler rejection must become normal compiler errors tied to the asm span where practical, not panics.
11. **Finish architecture/guide documentation.** Document the opaque-body/parser boundary and LLVM tied-register/clobber invariant in the relevant architecture docs, and add a concise x86-64 Intel example to the quick reference. Do not edit agent skills merely to mention the feature; update them only if their actual architecture/workflow guidance became stale.

## Testing
- **New/changed cases:**
  - Parser tests: contextual `asm`; all descriptor forms; optional trailing statement semicolon consistent with block statements; raw body preservation; target comments such as `# ...` preserved rather than stripped; target punctuation unknown to normal Omega lexer; balanced nested braces; malformed outer delimiters; `$name`, `$N`, `$$` marker recognition; macros around descriptors with opaque body preservation.
  - HIR/analyzer tests: spans/source order preserved; scalar integer/pointer/`f32`/`f64` `reg` acceptance; obvious aggregate/fat-value rejection; named `comp` constants accepted and non-`comp`/unsupported constants rejected; complex expressions usable through positional `$N`; unknown/ambiguous bindings diagnosed; `&x`/`&mut x` receive no asm-body mutability analysis; no initialization inference.
  - MIR tests: each runtime `reg` evaluated once left-to-right; no implicit assignment/writeback; `const`/`clobber` generate no runtime expression; raw body/binding metadata survives lowering.
  - LLVM/codegen tests: generated IR has exactly one side-effecting inline-asm call with tied early-clobber register operands, conservative memory/status clobbers, explicit physical-register/clobber constraints, and Intel dialect on x86/x86-64; output values are discarded; FP operands select FP-capable target classes rather than `usize` conversion; source `$name`/`$N` resolve correctly despite LLVM's synthetic output/input numbering; `$$10` reaches final assembly as `$10`; target comment syntax such as AArch64 `#42` is preserved; invalid asm/registers return `Err` rather than panic. Add optimized-codegen checks showing a distinctive multi-instruction asm sequence remains present and in-order at the highest supported optimization level. Do not compare exact surrounding instructions or exact bytes because register allocation and assembler encoding remain backend responsibilities.
  - Add root conformance case `tests/t23_inline_assembly/` (current suite ends at `t22_program_entry_point`) with a host x86-64 Intel program equivalent to:
