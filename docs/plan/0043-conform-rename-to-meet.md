# Replace `conform ... to ...` with `meet ... for ...`

## Task Description
- **Deliverable:** replace Omega's source-level conformance declaration syntax from `conform Target to Spec { ... }` to `meet Spec for Target { ... }`, including blanket conformances as `meet<T: Bound> Spec for T { ... }`. Update the parser, active Omega source, tests, diagnostics that print source syntax, and current documentation so the repository consistently accepts and documents only the new spelling.
- **Purpose:** keep the semantic concept of **conformance** while avoiding awkward connector collisions such as `conform String to ToIterator<char>`, `... to WithCapacity`, and `... to AsBytes`. Putting the spec before the connector gives the intended readable forms `meet ToIterator<char> for String`, `meet WithCapacity for Type`, and `meet AsBytes for Type` without changing conformance semantics.
- **Chosen direction:**
  - `meet` is the new contextual declaration keyword, matching the old `conform` treatment rather than becoming a globally reserved lexer keyword. It must remain usable as an ordinary identifier when the conformance-item shape does not follow.
  - Reuse the existing reserved `for` token as the connector; do not add a second contextual spelling for it.
  - Keep generic parameters immediately after the declaration keyword: `meet<T: Numeric> Sum for T`. The first type after the generic list is the spec; the type after `for` is the target.
  - Preserve **conformance/conform/conforming** as the semantic/documentation vocabulary. `meet` is surface syntax, not a request to rename the language concept to "meeting" or to rename compiler concepts such as `ConformStmt`, `HirConformDef`, `HirItem::Conform`, or the driver's `conformances` subsystem.
  - This is a breaking syntax replacement, not an alias or transition period: the old `conform Target to Spec` grammar is removed.
- **Rejected alternatives:** do not introduce `impl`, `satisfy`, or `grant`; the surface design is already settled. Do not preserve both `conform ... to ...` and `meet ... for ...`, because duplicate spellings would leave permanent grammar/API debt and defeat the syntax cleanup.

## Technical Details
- **Initial context boundary:**
  - Parser ownership: `compiler/omega-parser/src/parser/{contextual.rs,item.rs,item/definitions.rs}`, `compiler/omega-parser/src/tests.rs`, and the parser AST in `compiler/omega-parser/src/ast/item.rs` only to verify that no representation change is needed.
  - Normative syntax: `docs/language/{lexical-structure.md,grammar.md,specs-and-conformance.md}`.
  - User-facing syntax/examples: `docs/guide/quick-reference.md` plus active docs found by searching for source examples or syntax-specific references to ``conform``.
  - Repository source/test migration: `.omg` files under `runtime/` and `tests/`, plus Rust tests/diagnostics that embed Omega source text.
  - Test-layer guidance: `docs/architecture/testing-and-validation.md`.
- **Affected files/symbols:**
  - `compiler/omega-parser/src/parser/contextual.rs`: replace contextual `CONFORM` with `MEET`. Remove contextual `TO`, whose only grammar use is the old conformance connector. Do not add `FOR`: `for` already lexes as `TokenKind::For` because of loop syntax.
  - `compiler/omega-parser/src/parser/item.rs`: route a top-level contextual `meet` item using the same guarded type-start lookahead that currently protects contextual `conform`. Preserve the contextual-keyword commit rule so `meet := ...`, `meet() => ...`, and other non-conformance identifier uses are not stolen by the grammar.
  - `compiler/omega-parser/src/parser/item/definitions.rs::parse_conform_def`: consume contextual `meet`, parse optional declaration generics, parse the **spec** type first, require `TokenKind::For`, then parse the **target** type. Construct the existing `ConformStmt { target, spec, ... }` by semantic field name; source order must not leak into downstream representation.
  - `compiler/omega-parser/src/ast/item.rs::ConformStmt` and `compiler/omega-hir::{src/hir.rs,src/lower/item.rs}`: no structural or naming change is expected. The AST/HIR already carry `target` and `spec` as semantic fields, so lowering and every analyzer/driver consumer should remain untouched.
  - `compiler/omega-parser/src/tests.rs`: rewrite current conformance parser fixtures to the new order/connector; add direct coverage that parsed `spec` and `target` land in the correct fields; update contextual-word coverage from `conform`-as-syntax to `meet`-as-syntax; update the removed-syntax/connector diagnostic expectations to require `for` instead of `to`.
  - `compiler/omega-analyzer/src/error/render.rs`: update only user-visible strings that prescribe or name the old source spelling. In particular, syntax help such as ``conform <source> to ToIterator<T>`` must become ``meet ToIterator<T> for <source>``. Where diagnostics currently use `conform` as a noun/keyword (for example "this conform" or "a `conform` block"), prefer semantic wording such as "this conformance" / "a conformance block" rather than introducing "meeting" terminology. Semantic verb uses such as "conform the element type to ..." may remain when they are not source-code instructions.
  - Active Omega source under `runtime/`: migrate every conformance declaration, including macro-generated declarations in primitive/runtime macros. Macro-expansion machinery itself should not change: it continues to operate on `Item::Conform` after the expanded tokens are reparsed.
  - Active root language tests under `tests/`: migrate every conformance declaration to `meet Spec for Target`. `tests/t11_specs_and_conformance` remains the principal end-to-end conformance case; `tests/t01_lexical_structure` should exercise `meet` as an ordinary identifier outside its contextual grammar position.
  - Compiler test source strings under `compiler/omega-driver/tests/`, `compiler/omega-codegen/tests/`, and other active test files found by search: mechanically migrate embedded Omega declarations while preserving each test's semantic purpose. Keep semantic test/module names such as `conform.rs` unless they explicitly claim to name the keyword rather than the concept.
  - Current documentation: update the conformance EBNF to `"meet", [ generic-parameters ], type, "for", type`; replace `conform`/`to` with `meet` in source examples and syntax-specific prose; update the contextual-keyword list to contain `meet` and no longer list `conform`/`to`; keep chapter titles and semantic prose centered on **conformance**. Update current issue/guide examples that would otherwise teach invalid syntax. Do not rewrite historical files under `docs/plan/`.
  - Source comments that literally identify the old keyword (for example comments listing unnamed item spellings) should be corrected to `meet` or to semantic "conformance" wording. Do not perform a general terminology rename across implementation internals.
- **Interfaces/invariants:**
  - Conformance semantics are unchanged: ownership/orphan rules, duplicate detection, blanket specificity, entailment, requirement matching, visibility inheritance, static dispatch, dynamic spec objects, and code generation must observe the same `target`/`spec` relationship as before.
  - The semantic relation remains `Target` conforms to `Spec`; only source order is reversed. The parser must therefore map `meet Spec for Target` back into the existing `target` and `spec` fields correctly.
  - Generic conformance syntax is `meet<T: Bound> Spec for Target`, preserving the existing placement of declaration generics immediately after the contextual item keyword.
  - `meet` remains contextual, not globally reserved. No `TokenKind::Meet` or `FIXED_TOKENS` entry should be introduced. `for` remains the already-reserved `TokenKind::For`.
  - The new syntax must work cleanly with connector-like spec names, especially `ToIterator<T>`, `With...`, and `As...`; this is the motivating grammar property and deserves explicit parser coverage.
  - Macro token trees may emit the new syntax, but there is no new macro-specific conformance mechanism and no change to `Item::Conform` expansion handling.
  - Existing source spans/item spans and downstream HIR contracts remain unchanged unless compilation exposes a concrete parser-only span bug; do not widen the task preemptively.
- **Out of scope:** renaming `ConformStmt`/`HirConformDef`/`HirItem::Conform`, renaming `compiler/omega-driver/src/conformances`, changing conformance semantics, changing spec syntax or spec-object syntax, changing `for` loop lexing, making `meet` a hard keyword, adding a deprecation/compatibility parser for old syntax, redesigning syntax highlighting for contextual keywords, or rewriting historical `docs/plan/` records.
- **Risks/open questions:** no language-design question is left to the implementer. If changing only the parse boundary unexpectedly requires downstream target/spec reordering, stop and report the concrete dependency rather than renaming or reshaping semantic representations to mirror source order.

## Implementation Plan
1. **Change only the conformance parse boundary.** In `parser/contextual.rs`, replace `CONFORM`/`TO` with `MEET`; in `parser/item.rs`, use contextual `meet` for top-level conformance routing; in `parse_conform_def`, parse `[generics] -> spec -> for -> target -> body` and populate the existing `ConformStmt` semantic fields. Use `p.expect(&TokenKind::For, "'for'")` for the connector rather than creating a contextual `for` helper.
2. **Lock the grammar behavior with parser tests before touching semantics.** Rewrite the existing conformance fixtures and add assertions for a concrete declaration and a blanket declaration that prove the spec/target order is mapped correctly. Include a connector-name case such as `meet ToIterator<char> for String { ... }`, keep `meet` usable as an identifier where the item shape does not match, and assert that `meet Spec to Type` reports an expected `for` connector. Assert the removed `conform Target to Spec` form no longer parses as a conformance declaration.
3. **Migrate all active Omega source and embedded source fixtures.** Search the non-historical tree for conformance declarations and convert `conform[<G...>] Target to Spec` to `meet[<G...>] Spec for Target`, including `runtime/core`, `runtime/std`, root `tests/`, driver/codegen/parser source strings, generated `format!` snippets, and macro bodies. Preserve semantics and test intent; this is an order-aware rewrite, not a blind keyword substitution.
4. **Update user-facing diagnostics that would teach stale syntax.** Change concrete source suggestions to the new `meet Spec for Target` order and change keyword-as-noun phrases to "conformance" where appropriate. Leave semantic error types, variants, and conform/conformance terminology intact.
5. **Update the normative language specification.** In `lexical-structure.md`, replace contextual `conform to` entries with `meet` while leaving reserved `for` where it already is. In `grammar.md`, change the conformance production and syntax-specific prose. In `specs-and-conformance.md`, rewrite code examples and declaration spellings to `meet`, while retaining the chapter name and semantic language of conformance/conforming.
6. **Update current guides/issues/examples and stale keyword comments.** Migrate `docs/guide/quick-reference.md`, console/runtime examples, visibility/macros/examples, and current `docs/issues/` snippets that contain old source syntax or call a block ``conform`` as a keyword. Keep historical `docs/plan/` untouched and avoid a repository-wide internal rename.
7. **Run focused then full verification and sweep for stale active syntax.** Run parser tests first, then the focused root conformance/lexical cases, then `just test-all`. Finish with a non-historical search that confirms no active `.omg`, compiler source string, diagnostic suggestion, or current documentation still presents `conform Target to Spec` as valid syntax.

## Testing
- **New/changed cases:**
  - Parser unit/component coverage for `meet Animal for Dog { ... }` and `meet<T: Animal> Tagged for T { ... }`, with explicit AST assertions that `spec == Animal/Tagged` and `target == Dog/T` rather than relying only on `Item::Conform(_)`.
  - Parser coverage for the motivating names: at least one generic connector-like spec such as `meet ToIterator<char> for String { ... }`; optionally include `WithCapacity`/`AsBytes` in the same focused test if it stays concise.
  - Contextual-keyword coverage proving `meet` still works as a binding/function name outside the conformance-item shape. `conform` and `to` remain ordinary identifiers naturally once their contextual grammar roles are removed.
  - Negative parser coverage that `meet Spec to Type` expects `for`, and that the removed `conform Type to Spec` syntax is not accepted as a conformance declaration.
  - Migrate `tests/t11_specs_and_conformance` to exercise concrete, blanket, generic-spec, default-method, static-dispatch, and dynamic-dispatch behavior through the new syntax without changing expected runtime behavior.
  - Update `tests/t01_lexical_structure` so the normative contextual-keyword example includes `meet` as an identifier; adjust its expected output only if the arithmetic/output fixture changes.
  - Existing driver conformance tests remain the semantic regression suite after their embedded source is migrated; no new analyzer/HIR/codegen semantic tests should be needed for a syntax-only change.
- **Specification trace:** `docs/language/grammar.md` owns the new `meet [generics] Spec for Target` production; `docs/language/lexical-structure.md` owns `meet` being contextual and `for` remaining reserved; `docs/language/specs-and-conformance.md` continues to own the unchanged semantic meaning of a conformance declaration. Root `t11_specs_and_conformance` is the end-to-end executable evidence for that rule.
- **Negative/diagnostic cases:** parser diagnostics should name the missing connector as `for`; no diagnostic/help text should recommend the removed `conform ... to ...` source form. Existing semantic conformance diagnostics should remain otherwise unchanged.
- **Regression coverage:** run `cargo test -p omega-parser`, then the existing `omega-driver` conformance-focused tests after fixture migration, then focused `./bin/test-runner t01_lexical_structure t11_specs_and_conformance` once compiler/runtime artifacts are built. Because runtime source itself contains conformance declarations, the normal full gate is important even though semantics did not change.
- **Commands/target coverage:** finish with `just test-all`. No backend-, ABI-, cross-target-, or hardware-specific matrix is required; this change is entirely frontend syntax plus repository-source migration.
