# Optional Explicit Generic Arguments on Function Calls

## Task Description
- **Deliverable:** Add expression syntax and semantic support for optionally explicit generic type arguments on generic function calls, e.g. `ptr_cast<u32>(ptr)`, where written arguments bind the declaration's generic parameters positionally from left to right and any remaining parameters are resolved by the existing call-inference/default machinery.
- **Purpose:** Let callers pin the generic choices they care about without spelling every generic argument, while keeping Omega's existing inference, monomorphization, bounds, aliases, visibility, and diagnostics model. Also make `<...>` vs comparison parsing deterministic in the user-specified contexts instead of producing comparison/chaining errors for intended generic application.
- **Chosen direction:** Reuse the existing `ExprPath { generic_args, args_at }` representation and generic-call inference pipeline. Extend expression-path generic-argument commitment in the parser; in semantic analysis, treat a terminal callee generic list as an explicit positional prefix, resolve those types first, seed them into the existing substitution map, then let expected-result/default/argument inference fill only the remaining generics. Explicit bindings are never overwritten. Concrete instantiation still goes through the existing resolver so defaults, bounds, visibility, aliases, and monomorphization remain single-sourced.
- **Rejected alternatives:** Do not add Rust-style `::<...>`/turbofish syntax, a separate generic-call AST node, or a second inference engine. Do not reinterpret a syntactically committed generic application as comparisons after semantic lookup fails. Do not broaden this task into new inference for partial generic **function values** or currently unsupported independent generic member/static-function cases; only calls gain partial-prefix inference, while non-call generic paths keep their existing exact/defaulted semantic rules.

## Technical Details
- **Initial context boundary:**
  - Parser: `compiler/omega-parser/src/parser/expression.rs`, `compiler/omega-parser/src/parser/expression/tests.rs`, and the expression/path rules in `docs/language/grammar.md`.
  - Semantic analysis: `compiler/omega-analyzer/src/analysis/calls/{mod.rs,generic.rs}`, `compiler/omega-analyzer/src/analysis/mod.rs`, and the existing expression-path helpers in `compiler/omega-analyzer/src/analysis/paths.rs`.
  - Generic contracts: `compiler/omega-analyzer/src/generics.rs`, `compiler/omega-analyzer/src/resolver.rs`, and `compiler/omega-driver/src/items/resolution.rs` only as reference points for existing substitution/default/bound/arity behavior; no driver query redesign is expected.
  - Normative docs: `docs/language/generics.md`, `docs/language/functions.md`, and `docs/language/grammar.md`; architecture ownership remains as documented in `docs/architecture/{parsing-and-hir,semantic-analysis,testing-and-validation}.md`.
- **Affected files/symbols:**
  - `omega-parser::parser::expression::{parse_expr_path, try_parse_generic_args, parse_comparison}`: broaden the speculative `<type, ...>` commitment rule without weakening `ChainedComparison` recovery.
  - `omega_parser::ast::identifier::ExprPath`: already carries the generic list and the segment it applies to; keep this representation unchanged so HIR lowering remains unchanged (`omega-hir` reuses the parser type).
  - `omega-analyzer::analysis::calls::mod.rs::callee_path`: it currently returns only `ExprPath::plain()`, which intentionally hides generic arguments. Refactor/add a callee-path accessor that can expose the full `ExprPath` to the generic-call interceptor while plain-call/overload paths keep their existing requirements.
  - `omega-analyzer::analysis::calls::generic::{resolve_generic_call, finish_generic_call, seed_from_expected}`: recognize an explicit generic list on the terminal function segment, resolve it through `resolve_generic_arg_list`, validate that its length does not exceed `GenericSignature::generics`, and seed the positional prefix before expected-result inference.
  - `omega-analyzer::analysis::mod.rs::infer_generic_args`: keep its left-to-right argument walk; it already accepts a seed substitution and therefore should not need a second explicit-argument API.
  - `omega-analyzer::analysis::paths::{resolve_generic_arg_list, generic_prefix_absolute}`: reuse these for source-context type resolution and canonical/authorized path resolution so `module::f<T>()`, imported generic functions, aliases, anchored paths, macro origin, and visibility do not get a parallel lookup path.
  - `omega-analyzer::generics::{unify_generic_type, resolve_inferred_type_args}` and `omega-driver::items::resolution::pad_generic_defaults`: preserve their existing contracts. `unify_generic_type` is first-binding-wins (`or_insert`), which is suitable once explicit bindings are seeded first; resolver instantiation remains the owner of final defaults/bounds and generic item arity.
- **Interfaces/invariants:**
  - Written generic arguments are a positional prefix: for `<A, B, C>`, `f<X>` fixes only `A = X`; `f<X, Y>` fixes `A = X, B = Y`. No skipping/reordering/named generic arguments.
  - Explicit bindings have highest authority. Build the substitution in this order: explicit prefix first; expected return type may fill only unbound generics; the existing left-to-right argument/default logic may fill only what is still unbound. Never overwrite an explicit binding to make another constraint fit.
  - Conflicts are rejected by the ordinary concrete semantic checks rather than by silently changing the explicit type: argument checking must report an incompatible argument; outer expected-type checking must reject an incompatible result; resolver instantiation must reject failed bounds. Add tests for all three so this is an enforced invariant rather than an accidental consequence of seed ordering.
  - Supplying more explicit type arguments than `GenericSignature::generics.len()` is an immediate arity error using the existing `ResolveError::GenericArgCountMismatch` diagnostic family (expected declaration arity, found explicit count). Fewer is legal for a call even when the missing generics have no defaults, because inference gets a chance before final `UnresolvedGenericParam` handling.
  - Existing generic defaults keep their documented call-inference priority for **unbound** remainder parameters. This feature raises explicit arguments above the current expected/default/argument rules; it does not otherwise redesign defaults.
  - The final concrete call must still resolve through `ModuleResolver::resolve_item` with the complete inferred prefix/result. That preserves generic-bound validation, canonical item keys, monomorphization ownership, and visibility/alias authorization.
  - Generic arguments written on a nonterminal owner segment keep their current meaning, e.g. `Cell<i32>::self::get(...)` continues to instantiate the owner before ordinary member-call analysis. The new partial-call inference applies when the generic list belongs to the terminal generic function being called, e.g. `module::ptr_cast<u32>(ptr)`.
  - A generic list committed by syntax is never retroactively parsed as `<`/`>` comparison based on name/type resolution. In particular, `a<b>(c)` is syntactically a generic call attempt; semantic failure stays a generic/name/callee error.
  - Parser commitment precedence is syntactic:
    - keep the existing path-resolution commitments (`...<T>::...` and generic struct-literal paths);
    - commit before a call suffix `(`, so `f<T>(...)` is generic application;
    - commit when the generic-applied path ends at an expression boundary (at minimum `;`, `,`, `)`, `]`, `}`, and EOF), enabling `&foo<T>;`, `take(foo<T>)`, and `[foo<T>, bar<T>]`;
    - preserve rollback when the token after `>` continues as a fresh operand rather than ending/continuing the generic path. Thus `a < b > c` remains two comparison operators and reaches the existing non-associative/chained-comparison diagnostic.
    - Keep this rule centralized beside `try_parse_generic_args`; do not scatter angle-bracket heuristics through comparison parsing.
  - Audit the already-existing type-position path (`parse_named_type` -> `Context::resolve_generic_type` -> driver `pad_generic_defaults`) only to confirm the same positional/too-many invariants remain sound. Do not add type-position inference: omitted type arguments continue to require defaults or another existing construct-specific inference path.
- **Out of scope:** New syntax for named/out-of-order generics; generic argument placeholders; inference for a partial generic function value such as `f<A>` with no call unless already supported elsewhere; redesign of generic aggregate inference; generic-overload redesign; adding support for independent generic member/static functions that current call resolution cannot already instantiate; MIR/codegen/ABI changes.
- **Risks/open questions:** None requiring a language decision if the rules above are followed. If implementation discovers that a currently supported generic callable category cannot be represented by the terminal `ExprPath` rule without changing its existing semantics (especially overloaded or independently generic members), stop and report it as a pre-existing capability boundary rather than silently expanding this task.

## Implementation Plan
1. **Specify the new language rule before changing semantics.** Update `docs/language/generics.md` and `docs/language/functions.md` to replace the current “ordinary calls infer; no explicit turbofish-style syntax” statement with Omega's `f<T, ...>(...)` explicit-prefix rule: positional left-to-right binding, inferred/defaulted remainder, explicit authority, and too-many rejection. Update `docs/language/grammar.md` so expression-path generic arguments explicitly commit for path continuation, call suffixes, and expression boundaries, while `a < b > c` remains a chained comparison. Keep the spelling described as explicit generic arguments/diamond syntax, not Rust turbofish (`::<...>` is still not Omega syntax).
2. **Extend parser commitment at the existing speculative generic-argument boundary.** In `parser/expression.rs`, keep `try_parse_generic_args` transactional (`mark`/`reset`) and expand only its post-`>` commit predicate. Add a small local predicate for the allowed continuation/boundary tokens rather than teaching `parse_comparison` about generics. Ensure a successful call commitment leaves `(` for `parse_postfix_loop` so the existing `parse_call` path builds the same `FunctionCall` AST as any other call.
3. **Lock the disambiguation contract with parser tests.** In `parser/expression/tests.rs` and/or the existing parser test module, assert AST shape for `f<i32>()`, `module::f<i32>(x)`, `&foo<i32>;`, and `[foo<i32>, bar<i32>]`; include a nested type argument such as `f<Pair<i32, u32>>()` to exercise close-angle handling. Preserve `generic_args_do_not_steal_comparisons`, and add the exact `a < b > c` case asserting `ParseErrorKind::ChainedComparison`. Also assert that `a<b>(c)` commits as a generic call attempt, proving semantic validity never controls parsing.
4. **Expose the full callee expression path only to generic-call resolution.** Refactor `calls/mod.rs::callee_path` (or add a sibling helper) so `resolve_generic_call` can inspect `ExprPath::generic_args/args_at`, while overload and ordinary routes can continue requiring a plain path where appropriate. Do not change HIR or the general place representation.
5. **Resolve explicit terminal function arguments and canonicalize the function access through existing path helpers.** In `calls/generic.rs::resolve_generic_call`, distinguish: no explicit list (current inference path), explicit list on the terminal function segment (new path), and generic arguments on an earlier owner/type segment (decline so existing generic-place/type-member behavior handles it). For the new path, use `resolve_generic_arg_list` to resolve each written type in the caller's source/macro context and `generic_prefix_absolute`/existing alias resolution to preserve import authorization and module qualification before asking for `GenericSignature`.
6. **Seed call inference with the explicit positional prefix.** Before expected-result inference, reject `explicit_args.len() > sig.generics.len()` with `GenericArgCountMismatch`. Zip the explicit resolved types with the first generic identifiers into the seed substitution. Then unify the expected return type into that same map so `unify_generic_type` can fill only absent entries. Pass the resulting seed into the unchanged left-to-right `infer_generic_args`; resolve the remainder with `resolve_inferred_type_args`, then use the existing concrete `resolve_item` + `coerce_call_arguments` path. Do not special-case conflicts by mutating the explicit seed.
7. **Verify explicit authority and existing resolver ownership.** Add focused analyzer/driver tests showing: a partially explicit call infers the remainder; full explicit and fully inferred calls still work; `<A, B>` binds `f<X>` to `A`, not `B`; an argument incompatible with an explicit type fails; an expected return type incompatible with an explicit type fails rather than changing it; an explicit type failing a generic bound is rejected by the normal bound path; too many explicit arguments reports the existing arity diagnostic; and an uninferable remainder still reports `UnresolvedGenericParam`. Include at least one imported/aliased generic function call with explicit arguments to guard the `ItemAccess` authorization/canonicalization invariant.
8. **Audit type-position generic application without widening scope.** Confirm through existing tests/code that `parse_named_type`, `Context::resolve_generic_type`, and `Driver::pad_generic_defaults` already bind supplied arguments positionally, reject too many, and apply only trailing defaults. Add a narrowly focused regression test only if that audit exposes a real mismatch; otherwise leave the implementation unchanged and rely on existing type/alias/default coverage.
9. **Add end-to-end language conformance.** Extend `tests/t10_generics/` with successful explicit-prefix calls that execute and prove left-to-right partial inference (including the motivating pointer-cast shape or an equally direct typed result), plus at least one fully explicit generic function value at an expression boundary if semantically valid. Add a focused negative sibling such as `tests/t10b_explicit_generic_errors/` for too many type arguments and explicit-authority conflicts, with exact `expected.stderr`. Keep parser-only ambiguity cases in parser tests when they do not need semantic/runtime behavior.

## Testing
- **New/changed cases:**
  - `compiler/omega-parser/src/parser/expression/tests.rs`: call commitment, module-qualified call, expression-boundary function references/array elements, nested generic arguments, and comparison rollback/chaining.
  - `compiler/omega-driver/tests/` (place generic-call semantic cases in the nearest existing suite, with alias-specific authorization regression in `aliases.rs` when appropriate): partial prefix inference, left-to-right binding, explicit-vs-argument/result conflicts, bound failure, too many arguments, unresolved remainder, alias/import path preservation.
  - Root `tests/t10_generics/`: positive executable syntax/semantics. Add `tests/t10b_explicit_generic_errors/` (or the next locally consistent negative name) for exact user-facing rejection behavior.
- **Specification trace:** Positive conformance must prove the new `docs/language/generics.md` rule that explicit arguments form a left-to-right positional prefix and the remainder is inferred/defaulted. Negative conformance must prove explicit authority and over-arity rejection. Parser tests must prove the updated `docs/language/grammar.md` disambiguation rule, especially that `f<T>()`/boundary forms commit while `a < b > c` still reaches the non-associative comparison rule.
- **Negative/diagnostic cases:** Assert the intended diagnostic kind, not merely failure: `ArgumentTypeMismatch` (or the established outer expected-type mismatch at that context) for explicit conflicts, `ResolveError::GenericArgCountMismatch` for over-arity, normal spec/bound failure for an invalid explicit type, and `UnresolvedGenericParam` for a missing uninferable remainder. Preserve `ParseErrorKind::ChainedComparison` for `a < b > c`.
- **Regression coverage:** Existing generic inference/default/expected-result cases in `compiler/omega-driver/tests/conform.rs`, alias generic-call coverage in `compiler/omega-driver/tests/aliases.rs`, parser generic-path tests, root `t10_generics`, `t12_modules_and_imports`, `t26_aliases`, and `t29_type_function_namespaces`. Explicit owner paths such as `Cell<i32>::self::get(...)` must remain unchanged.
- **Commands/target coverage:** Run focused `cargo test -p omega-parser` expression tests and the affected `omega-driver` integration tests; build the normal artifacts and run `./bin/test-runner t10_generics t10b_explicit_generic_errors` (using the actual chosen negative case name); finish with `just test-all`. No backend/hosted/freestanding matrix is needed: the feature changes parsing and semantic instantiation selection only, with no MIR, ABI, runtime, or codegen contract change.
