# Implement Rust-like Shadowing

## Task Description
- **Deliverable:** implement lexical shadowing for Omega local bindings, allow explicit module/import names to hide ambient `core` prelude names, keep explicit module-scope bindings non-shadowable, and reserve primitive type spellings from module/path/type-parameter rebinding.
- **Purpose:** allow code to deliberately narrow privileges and refine values over time (`mut x` -> immutable `x`, or `T` -> `U`) without assignment-specific machinery, while keeping global/module code predictable and primitive spellings unambiguous.
- **Chosen direction:**
  - A local declaration is a **fresh binding**. Its initializer is analyzed before the new binding becomes visible, so `x := x` reads the previous binding and then shadows it. Type, mutability, and runtime-vs-`comp` storage may change subject to their ordinary rules. There is no special storage reuse or copy-elision guarantee; ordinary Omega value semantics apply.
  - Sequential runtime locals and local `comp` bindings may shadow an earlier binding with the same hygienic `(Ident, Origin)` in the same lexical block. The older declaration remains semantically alive/bookkept by its own `HirId`, but later source cannot recover it by name. Inner-scope shadowing continues to reveal the outer binding when the inner scope ends.
  - Duplicate parameters and other declaration sets that require unique names remain errors. Macro hygiene remains intact: a macro-origin name must not shadow/capture a caller-origin name merely because the spelling matches.
  - Local value bindings may shadow module globals/functions/imported values; existing local-first value/call lookup already provides this precedence. Shadowing does not merge language namespaces: a local value name does not replace a type spelling.
  - Module scope is **not sequentially shadowable**. In a given existing namespace, explicit declarations/aliases/import bindings compete and collisions remain redeclarations; function overloads remain the existing deliberate exception. Ambient exposed `core` names are fallback bindings and may be hidden by an explicit declaration, alias, or import in the corresponding namespace.
  - The primitive spellings `void`, `never`, `bool`, `char`, integer/float primitives, and `str` are reserved from rebinding where they would become module/path/type names: module/package identities, ordinary module-scope declaration/alias/import names, and generic type parameters. Do not turn them into lexer keywords: local value bindings, fields/variants/members, macro names, and other distinct namespaces remain governed by their existing rules. `primitive i32 { ... }` / `primitive str { ... }` extension blocks remain legal because they extend the builtin rather than declare a competing name.
- **Rejected alternatives:**
  - Do not mutate the old binding in place or special-case `x := x` to reuse storage; that would make binding identity and cost depend on spelling and would interact badly with aliases/pointers/defer/state tracking.
  - Do not exempt local `comp` bindings from shadowing. The current `panic$` repeated-`comp` guard is a workaround for missing optional/arity-constrained macro parameters, not a language rule worth preserving.
  - Do not allow explicit globals/imports to shadow one another by source order. Only ambient fallback names and outer lexical scopes are shadowable.
  - Do not make primitive names global reserved tokens; enforce the restriction at semantic/module-name binding boundaries instead.

## Technical Details
- **Initial context boundary:**
  - `compiler/omega-analyzer/src/context.rs`, `analysis/mod.rs`, `analysis/stmts.rs`, and the local value/call lookup paths under `analysis/places/roots.rs` / `analysis/calls/`.
  - `compiler/omega-driver/src/modules.rs` for module indexing/import/macro environments, `fs_resolve.rs`/`roots.rs` for module identities, and `aliases.rs` for alias-owned generic placeholders.
  - Normative docs: `docs/language/bindings-and-mutability.md`, `modules-and-imports.md`, `types-and-primitives.md`, and `compile-time-evaluation.md`; consult `docs/language/macros.md` only for the ambient-macro/import fallout. Use `docs/architecture/semantic-analysis.md`, `module-driver-and-linkage.md`, and `testing-and-validation.md` as implementation/test references.
- **Affected files/symbols:**
  - `omega-analyzer::context::LexicalScope`: `declared_variables` currently stores only one `VarBinding` per `(Ident, Origin)`. Replace that representation with one that preserves **every declaration in source order** while maintaining an efficient latest-binding lookup per hygienic name. `bindings()` must still enumerate every binding so unused/unnecessary-`mut` diagnostics are produced per declaration in deterministic source order.
  - `Context::{find_variable, variable_mut, binding_mut, declare, similar_variable_name}`: lookups/mutations must select the latest visible binding; `binding_mut(HirId)` must still work after shadowing and must preserve the existing narrowed-binding behavior that can reuse an original `decl_id` in a nested refinement scope.
  - `Analyzer::{declare_binding, declare_comp_binding, declare_binding_impl}` plus statement analysis in `analysis/stmts.rs`: distinguish **shadowable local declaration** from **unique declaration**. Ordinary statement locals and local `comp` walruses use the shadowable path; parameters and analyzer-side global/foreign declarations retain uniqueness. Both typed-initializer and `:=` paths already analyze the initializer before declaration and must keep that ordering.
  - `warn_unused_bindings`: no semantic weakening. A shadowed declaration still receives its own unused/unnecessary-`mut` warning based on its own `HirId` state. The privilege-drop idiom naturally marks the old binding used through the new initializer.
  - `analysis/places/roots.rs` and `analysis/calls/{generic,overload}.rs`: no new precedence mechanism should be needed; they already test `Context::find_variable` before module/import/overload lookup. Add regression coverage proving a local can hide a global/function/import without changing these resolver contracts unless a test exposes a real hole.
  - `omega-mir/src/lower/function.rs` / `lower/place.rs`: expected **no code change**. MIR maps locals by declaration `HirId`, so fresh shadow declarations already become distinct `LocalId`s. Treat any proposal to key MIR locals by spelling or reuse a local for self-shadowing as a design regression.
  - `omega-driver::modules::{index_items,index_imports}`: imports currently live in a separate `ModuleIndex::imports` table and therefore can collide with ordinary items/aliases. Introduce a shared explicit-module-name claim/validation path so declarations, aliases, and imports in the same ordinary module namespace cannot shadow each other. Preserve source-order diagnostics (the later explicit claim is the redeclaration) even though import target resolution still runs after the partial module index is published, and preserve function-overload grouping as the only same-name ordinary-item exception.
  - `omega-driver::modules::macro_env` and raw macro binding helpers: ambient `core` macros are also fallback names. A valid explicit imported macro must replace the ambient entry, just as a local macro definition already does. Do not let an explicit imported/local macro binding silently shadow another explicit binding in the macro namespace; preserve the existing separate macro namespace rather than conflating macro names with ordinary item names.
  - `omega-analyzer::context::BUILTIN_TYPE_NAMES` / `omega-analyzer::lib`: keep the actual builtin-type list distinct from a shared predicate/set for **reserved language type spellings** that additionally includes `str`. Reuse that predicate from analyzer and driver instead of scattering `BUILTIN_TYPE_NAMES || name == "str"` checks.
  - `Analyzer::new_in`: generic type parameters must reject every reserved type spelling, including `str`, without relying only on `Context`'s currently-installed scalar types.
  - `omega-driver::aliases::compute_alias`: alias-owned generic placeholders are validated symbolically outside the normal analyzer generic-registration path; explicitly reject reserved/duplicate generic parameter names there before treating them as placeholders. Keep primitive **targets** such as `alias Count = i32` legal; only the newly-bound name/parameter is restricted.
  - `runtime/core/primitives/bool.omg` and `char.omg`: core's own module identities become illegal under the reservation rule, so both files must be renamed (`booleans.omg` / `chars.omg`) and the `core::primitives::*` paths in `docs/guide/core-library.md` updated with them. Nothing imports these modules by path, so the rename is contained.
  - `omega-driver::fs_resolve::is_valid_module_name` (and its callers/tests in `roots.rs`): reject reserved type spellings as module/package identities as well as the existing navigation spellings, because `i32::...`/`str::...` must continue to unambiguously denote the language type namespace rather than a package/module segment. Update the `InvalidModuleName` diagnostic/help so it no longer claims only `root`/`self`/`super` are excluded.
  - `omega-analyzer::error::{kind,render}`: add a precise reserved-type-name diagnostic for declaration/import/generic binding sites rather than pretending a builtin has a source redeclaration span. Also revise the generic `Redeclaration` note: “a name can only be declared once per scope” becomes false once same-block locals may shadow; phrase it in terms of the declaration context requiring uniqueness or omit the universal note.
  - `runtime/core/panic.omg`, `docs/issues/language-limitations.md`, `docs/guide/core-library.md`, and `tests/t33b_panic_handler_errors`: local `comp` shadowing makes `PANIC_TAKES_AT_MOST_ONE_MESSAGE` cease to be an arity guard. Do not preserve that hack with a shadowing exception. Remove/neutralize the misleading guard and update the existing macro limitation/test expectation to state that structural zero-or-one macro arity remains separate follow-up debt. Do not implement optional macro parameters in this task.
- **Interfaces/invariants:**
  - Every source declaration keeps a unique HIR identity; shadowing changes name lookup only, not checked/MIR identity.
  - Initializers resolve in the environment immediately **before** their declaration. An uninitialized declaration shadows from the declaration onward.
  - No implicit move/freeze/storage-reuse semantics are introduced. If ordinary Omega value initialization copies a large aggregate, shadowing does not promise otherwise.
  - `(Ident, Origin)` remains the lexical hygiene key. Same spelling with a different macro origin is not a shadow relation.
  - Ambient `core` resolution remains fallback-only. Explicit bindings do not mutate or remove the underlying core declaration; qualified `core::...` remains available where visibility permits.
  - Explicit module collision validation must not alter overload identity, visibility, alias transparency, import-use tracking, separate compilation, or resolution determinism.
  - Primitive reservation is a name-binding rule, not a lexer/type-layout/ABI change.
- **Out of scope:** ownership/move semantics, guaranteed copy elision for `x := x`, destructors/drop timing, optional macro parameters or macro arity constraints, renaming imports, new namespace categories, changing function overload rules, MIR/codegen optimization, and a general resolver refactor.
- **Risks/open questions:** no semantic decisions remain open, but step 5 is evaluated against every module in the repository: tightening explicit module-scope collisions and reserving primitive spellings can invalidate existing `runtime/` code. Run `just test-all` immediately after step 5 and fix the offending runtime module rather than weakening the rule. The implementation must stop rather than invent a special rule if preserving an unrelated test requires distinguishing shadowing by type/mutability/spelling; the settled model is fresh lexical bindings plus ordinary semantics.

## Implementation Plan
1. **Specify the language rule first.** Add a “Shadowing” section to `docs/language/bindings-and-mutability.md` covering fresh identity, initializer-before-binding visibility, same-block/inner-block behavior, type/mutability changes, local-over-module precedence, no escape to the old same-block binding, and ordinary value cost. Add the local-`comp` rule/cross-reference in `compile-time-evaluation.md`. Update `modules-and-imports.md` to distinguish explicit module-name collisions from shadowable ambient `core` fallback names, including imported macros. Update `types-and-primitives.md` with the reserved-spelling boundary and explicitly state that primitive extension blocks are unaffected.
2. **Make lexical scopes retain shadow history.** Refactor `LexicalScope` in `context.rs` to store declarations in deterministic declaration order plus a latest-binding index keyed by `(Ident, Origin)`. Provide separate insertion semantics for “push a new shadow” and “require uniqueness”; update lookup/mutation/similarity helpers accordingly. Add focused `context` Rust tests proving latest lookup, restoration after `leave_scope`, preservation/enumeration of both same-block declarations, and `binding_mut` behavior by `HirId`.
3. **Enable shadowing only at local declaration sites.** Thread the insertion policy through `Analyzer` declaration helpers. `HirStmt::Declaration`, `DeclarationWithInit`, runtime `:=`, and local `comp name := ...` must push a new binding; parameters and analyzer-owned global/foreign declarations keep unique insertion. Keep initializer analysis before insertion. Update the redeclaration diagnostic wording so remaining uniqueness errors are accurate.
4. **Centralize reserved type spellings.** Add/export one analyzer-owned predicate or constant set containing the scalar/builtin type names plus `str`; switch existing alias primitive recognition to use it where appropriate without changing which primitive type syntaxes are legal. Reject those spellings for generic parameters in `Analyzer::new_in` and for alias-owned generic parameters in `Driver::compute_alias`, with a dedicated diagnostic.
5. **Protect the module/path namespace.** Reuse the reserved-name predicate in module/package identity validation and in module indexing. Refactor `index_items`/`index_imports` around a shared explicit-name claim table (or equivalent) that scans source order, reports the later declaration/import/alias as a collision, leaves overload-vs-overload legal, and prevents an invalid import from becoming the effective binding. Reject reserved spellings for ordinary module declarations, aliases, and imports before they can enter the index. Keep import target resolution as the existing second phase after index publication.
6. **Make ambient macro shadowing follow the same fallback rule.** In `macro_env`, distinguish ambient prelude entries from explicit imported/local macro bindings: imports may replace an ambient `core` macro, but two explicit bindings in the macro namespace must diagnose rather than silently win by insertion order. Preserve macro-definition hygiene/visibility and the separate macro namespace; adjust `bind_macro_aliases` only as needed to keep explicit macro alias collisions consistent.
7. **Accept the `panic$` guard fallout without contaminating shadowing.** Remove the repeated-`comp` declaration as an arity mechanism from `runtime/core/panic.omg` (or otherwise make clear it is no longer enforcing anything), remove the corresponding expected redeclaration from `t33b_panic_handler_errors`, and update the existing macro limitation/core guide text to record that zero-or-one macro arity needs structural macro support. Do not add a replacement sentinel or a `comp` shadowing exception.
8. **Add end-to-end conformance coverage.** Extend the bindings suite for same-block runtime/`comp` shadowing, type change, mutability drop, outer-scope restoration, and local-over-global/import/function precedence. Extend modules/aliases coverage for local declaration/import shadowing of ambient `core::result::Result` while qualified `core::result::Result` remains reachable. Extend macro coverage so an imported macro with the same invocation name as an ambient core macro wins. Add negative coverage for explicit module import/declaration collisions and reserved primitive/module/generic names. Keep cases focused enough that each expected diagnostic proves one documented rule.

Runtime output should prove the newest binding is selected and the outer binding reappears only after leaving an inner scope.
  - Add a focused negative bindings case (for example `t03b_shadowing_errors`) that proves the post-shadow immutable binding cannot be written and that duplicate parameters remain a redeclaration error; assert exact diagnostics.

  - `tests/t18_macros`: import a helper macro using the same name as an exposed ambient `core` macro and prove invocation selects the imported definition; add explicit-vs-explicit macro collision coverage at the narrowest layer that can assert the correct diagnostic.
  - `tests/t02_types_and_primitives` plus the existing reserved-module-name coverage (`t12c` or a focused sibling): reject representative primitive/`str` spellings as module-scope declarations/aliases/imports, generic parameters, and module/package identities; retain positive primitive extension coverage.

- **Macro hygiene:** add `compiler/omega-driver/tests/macro_hygiene.rs` coverage that a macro repetition may declare the same local in every expansion -- that is the behavior the removed `panic$` guard depended on, and `macro_locals_do_not_capture_substituted_arguments` remains the guard that a macro-origin declaration still does not capture a caller-origin name.
- **Regression coverage:** add analyzer `context` unit tests for binding-stack bookkeeping and driver/component tests around `is_valid_module_name` / module indexing if end-to-end cases cannot isolate source-order behavior. Existing alias, macro, module-resolution, generic, refinement, unused-variable, and panic tests are high-value regressions because they exercise the same maps/origins.
