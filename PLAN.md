# Panic on illegal runtime control flow

## Task Description

- **Deliverable:** compiler-generated calls to `core::panic::PanicHandler::panic` for four cases: invalid enum tags during `match`, invalid source tags during anonymous-enum widening, invalid `Option`/`Result` tags during `?`, and ordinary return from a call whose Omega return type is `never`.
- **Purpose:** make these violated runtime invariants fail at the operation that relies on them, instead of invoking LLVM undefined behavior or interpreting an invalid tag as a valid alternative.
- **Chosen direction:** always-on checks, using the existing panic gap and `PanicInfo` ABI. User-written enum-match `else` covers only the remaining legal variants. Compiler-generated panic is a distinct final failure path. The handler is the trusted terminal operation; its call may still end with LLVM `unreachable`.
- **Rejected alternatives:** blanket replacement of every MIR `Unreachable`; a debug-only/sanitizer mode; a trap instead of the panic gap; a second panic ABI or runtime registry; unrestricted enum `else` accepting invalid tags.
- **Settled scope:** the user explicitly deferred bool/char validity and all broader validity checks. This plan does not promise detection of every illegal machine state.

## Technical Details

### Initial context boundary

Start with `compiler/omega-analyzer/src/analysis/patterns.rs`, `compiler/omega-analyzer/src/checked.rs`, and `compiler/omega-mir/src/lower/function/`. Use `docs/language/enums-and-pattern-matching.md`, the `?` section of `docs/language/control-flow-and-operators.md`, the `never` section of `docs/language/types-and-primitives.md`, and `docs/architecture/mir-and-codegen.md`.

The concrete cross-boundary dependencies are panic declaration/source-location resolution in `omega-driver`, native call emission in `omega-codegen`, and the existing contract in `runtime/core/panic.omg`. Use `docs/architecture/runtime-and-platform.md` for that contract and `docs/architecture/testing-and-validation.md` for verification. Read `docs/guide/quick-reference.md` before writing Omega fixtures. Parser/HIR syntax and enum layout do not change.

### Required semantics

1. **Named and anonymous enum matches:** explicit arms and `..` keep their existing coverage rules. Lower a reachable `else` to checks for the remaining legal variants, just as enum `..` already does. An unmatched raw tag must reach panic even when source contains `else`. Include matches through pointers. Preserve sparse, explicit, signed, and non-default-width named-enum tags; do not mistake variant indices for tag values.
2. **Dead enum `else`:** when earlier arms, including a legal `..`, cover the declared domain, emit the existing `unreachable_code` warning at the `else` block. Check its source independently for ordinary errors, but exclude its result from match type/divergence joins and omit its body from emitted control flow. A different result type in this dead block does not invalidate the reachable match. A redundant `..` remains an error. Do not add new refinement of bindings inside `else`.
3. **Anonymous-enum widening:** unknown source tags panic before destination construction or payload reads. Cover both `CheckedAnonymousEnumWiden` and widening replayed from `CheckedCoercionStep::WidenAnonymousEnum`, including `?` error conversions. Ordinary widening from a refined member is not a new tag-dispatch operation and remains outside this check.
4. **Try:** branch explicitly on both analyzer-resolved success and failure tags. Any third tag panics before either payload projection, error coercion, or return/defer path. Legal failure propagation still runs registered defers as today.
5. **Never calls:** a returning call with an Omega `never` result must immediately panic at its call site. Cover free/foreign functions, methods, gap calls, function-pointer calls, and spec dynamic calls, including calls nested in other expressions. This checks actual calls, not every expression whose type is `never`.
6. **Trusted endpoint:** calls statically identified as the canonical `PanicHandler::panic` gap operation, including compiler-generated calls and `panic$` expansion, terminate without a further unexpected-return check. Identify the gap declaration by resolved identity, never by a user-controlled function name. Arbitrary indirect calls retain their guard. Do not exempt the whole handler implementation from other checks. A handler that returns violates this remaining trusted contract.
7. **Panic behavior:** construct stack-local `PanicInfo`, call the existing handler with its address, then terminate. No allocation, formatting, unwinding, or execution of the caller's defers on the panic path. Use fixed messages: `invalid enum tag in match`, `invalid enum tag in anonymous-enum widening`, `invalid enum tag in try operator`, and `never-returning call returned`. Report the originating operation's file/line/column, not a compiler helper's location.
8. **Linkage:** platforms practically need the panic gap wherever emitted checks reference it. Add no mandatory-glue validation, unconditional startup call, or fabricated reference to force linkage. Missing glue remains an ordinary linker failure. Checks may disappear when actual value/control-flow facts prove them unnecessary; merely assuming that a typed enum is valid or that a `never` declaration is truthful is insufficient.

### Implementation ownership and interfaces

- `analysis/patterns.rs::{analyze_enum_match, analyze_anonymous_enum_match}` owns legal coverage and dead-`else` diagnostics. Represent a reachable enum `else` as a conditional checked arm over the remaining tags. Keep an explicit checked remainder policy distinguishing illegal enum tags from ordinary value-match lowering; do not globally change the shared `lower_match_chain` base case.
- `checked.rs::CheckedTrySource` currently stores `success_tag` but only the failure **variant index**. Add the resolved failure tag in `analysis/exprs/try_operator.rs::fallible_facts`; MIR must consume it rather than reconstructing it. Update the corresponding compile-time consumer mechanically without introducing runtime panic calls into compile-time evaluation.
- Add a small preparation step for runtime checks over the final checked function bodies, owned by the analyzer and orchestrated by the driver before final diagnostics/extern collection. It identifies only the four requested operations, including synthetic calls and coercion replay, and supplies each affected function with resolved panic support and source-site metadata. Proposed metadata belongs on `CheckedFunctionDef`; share the support descriptor across functions rather than repeatedly storing whole declarations. This avoids four independent panic resolvers and keeps MIR independent of name resolution.
- Resolve canonical `core::panic::PanicInfo` and the `PanicHandler::panic` signature through the existing resolver. Validate the pointer parameter, `never` result, and required field names/types once; carry resolved declaration/type/field facts downstream. Compiler access to the shared gap member is narrowly privileged; ordinary source visibility stays unchanged. Resolve support only when a runtime check needs it. Missing or incompatible core support is a normal source-located compiler diagnostic, never a Rust panic or silent fallback.
- Relevant orchestration is `compiler/omega-driver/src/compile/mod.rs`; `compile/output.rs::collect_extern_functions` already catalogs gap functions with glued symbol policy. Ensure the generated reference is included before this catalog is finalized. Follow existing pending-body/diagnostic ordering if resolution adds dependencies. Do not hard-code a mangled symbol or add backend name lookup.
- Source metadata comes from the driver's retained sources (`modules.rs`, `resolver.rs::function_source`) and `omega_diagnostics::SourceFile::line_col`. Resolve locations before MIR, preserving the defining source for generic bodies and existing macro call-site span conventions. Key metadata by the originating expression identity; coercion-generated checks inherit the consuming operation's site. New support/metadata types and the preparation helper are proposed additions, not existing APIs.
- `omega-mir/src/lower/item.rs` passes the prepared function metadata into `FunctionLowerer`. One MIR helper constructs the ordinary struct/address/call expressions and terminates with `Unreachable`. No new platform intrinsic or backend-specific panic lowering is needed. Preserve the public `lower_program` inputs if carrying the metadata with checked functions suffices.
- `lower/function/control_flow.rs::{lower_match_chain, lower_anonymous_enum_widen, lower_try_into, apply_coercion}` emits the guards using already-resolved facts. Sample each dispatch operand/tag once; preserve the original binding storage used for arm refinement.
- `lower/function/expr.rs` must emit a `never` call and its unexpected-return panic at the actual evaluation point. Stop parent lowering after that path terminates. Materialize already-evaluated sibling computations when needed to preserve effects and evaluation order; do not emit later arguments, an enclosing call, an assignment, or payload use after it. Handle `FunctionCall` and `DynamicCall` together. Limit this work to the ordering necessary for these terminating checks rather than redesigning MIR into a general SSA expression IR.
- `omega-codegen/src/llvm/{expr.rs,function.rs}` consumes ordinary calls and CFG. Keep the ABI's existing void-shaped native return for `never`. Do not attach/infer non-return assumptions solely from the Omega declaration, or let recognized foreign builtin semantics erase the unexpected-return guard. Prevent such builtin inference for guarded calls where necessary. Actual visible bodies may prove non-return independently. LLVM `unreachable` and `noreturn` are assumptions, not runtime checks: see the [LLVM language reference](https://llvm.org/docs/LangRef.html#unreachable-instruction) and [function attributes](https://llvm.org/docs/LangRef.html#function-attributes).

### Unreachable inventory and limits

Keep structural `Unreachable` terminators for predecessor-free merge blocks, exits from non-breaking loops, and the continuation after the trusted panic call. Naked bodies remain raw assembly with no inserted frame/body instructions; an ordinary Omega caller of a naked `never` function still gets a return guard. Rust `unreachable!`/assertions for malformed compiler representations remain compiler-internal checks.

Scalar/value matches, bool/char representation checks, bounds, arithmetic preconditions, general enum loads/copies, refined payload revalidation, and memory/alias/lifetime validation are out of scope. In particular, matching `e.tag` remains an integer match, without enum-domain provenance. Invalid pointers may fault before a tag is readable; the guarantee concerns an operation reached with readable storage and an invalid tag or an unexpectedly returning call. Corrupted control flow, invalid call ABI, and a returning panic handler are not made recoverable.

Escalate if implementation requires a different panic ABI, blanket source visibility bypass, a change to enum representation, or expansion into the deferred validity checks. Routine metadata/helper organization is an implementation choice within the ownership above.

## Implementation Plan

1. **Define the checked contract and panic preparation.** Add the enum-remainder distinction, the failure tag for `CheckedTrySource`, and the prepared function support/site metadata. Implement the preparation/binding step with normal diagnostics and existing gap catalog/mangling. Update affected checked-tree consumers and component fixtures; register real core where checks now require it. Preserve compiler-only tests that have no runtime-check sites and intentionally lack core.
2. **Implement the shared MIR panic emitter.** Generate `PanicInfo` and the canonical gap call using resolved layout and ABI facts. Add focused tests for the fixed message, actual source site, one handler call, and terminal `Unreachable`. Establish canonical handler recognition before adding `never` guards, so generated and source-written panics cannot instrument themselves recursively.
3. **Change enum match lowering.** Bound explicit `else` to remaining variants, warn/check/discard a dead `else`, and panic at the illegal remainder. Preserve scalar-match lowering. Verify named and anonymous enums, pointers, noncontiguous tags, and reachable result/divergence typing.
4. **Guard widening and try.** Replace widening's unmatched-tag `Unreachable`, guard both `?` tags before payload access, and thread panic support through coercion replay. Preserve evaluation count, valid payloads, tag remapping, and valid failure defers.
5. **Guard unexpected returns.** Handle both ordinary and dynamic `never` calls at their evaluation points, preserve preceding effects, and terminate enclosing expression lowering. Check call emission/optimization assumptions, including the trusted gap exception and calls to naked functions. Classify the remaining MIR `Unreachable` sites rather than replacing them indiscriminately.
6. **Update the owning documentation and run the gates.** In `docs/language/enums-and-pattern-matching.md`, specify invalid-tag panic, legal-only enum `else`, dead-`else` warning/type treatment, and widening behavior. In `docs/language/control-flow-and-operators.md`, specify invalid `?` tags and the distinction between panic and legal failure/defer propagation. In `docs/language/types-and-primitives.md`, replace the foreign-`never` invalid-return statement with the guarded-call behavior and trusted-handler boundary. Clarify the ordinary-caller guard in `docs/language/functions.md`'s naked contract. Update `docs/architecture/mir-and-codegen.md` and `runtime-and-platform.md` for ownership, locations, checks, and implicit gap references. Adjust `runtime/core/panic.omg`'s contract comments without changing its ABI or duplicating the design there. Bool/char issues remain deferred; do not mark them resolved.

## Testing

- **Analyzer/driver components:** assert bounded enum `else` conditions; `unreachable_code` kind and location for dead `else` after explicit coverage and after `..`; different dead-branch result type excluded from joins; ordinary errors inside dead code still rejected; missing coverage and redundant `..` retain their diagnostics. Verify both try tags, source provenance for generic/macro sites, canonical handler identity versus unrelated same-named functions, and missing/malformed core support diagnostics. Successful-compile warnings need component assertions: root runner expectation files do not capture them.
- **MIR/codegen components:** assert branch edges reach the handler before payload reads and before any parent computation after an unexpectedly returning call. Test `never` as a statement, return/tail, nested argument, and dynamic call, with preceding and following effects. Assert one evaluation of dispatch operands and call operands. Structural unreachable blocks and the trusted handler continuation must stay uninstrumented. Exercise the normal declaration catalog, glued symbol policy, and native call ABI.
- **New conformance packages:** create separate direct-child `tests/<case>/` packages for terminating paths (names to be chosen during implementation): invalid named-enum match without `else`; invalid named and anonymous matches with reachable `else`; exhaustive match with a dead side-effecting `else`; invalid enum `..`; invalid anonymous-enum widening; invalid `Option` and invalid `Result` through `?`; widening of a malformed anonymous error payload during legal `Result::Err` propagation; and unexpected foreign/function-pointer `never` returns. Include an executable dynamic-call return violation using a fixture with the correct vtable and call ABI. Use initialized, sufficiently sized/aligned storage with a deliberately corrupted tag, preferably filled by a separately compiled freestanding C helper. Do not use a random address or uninitialized memory as evidence. A returning C helper must be an ordinary `void` function in its own compilation, with no C non-return annotation; Omega declares the mismatched `never` contract under test.
- **Panic assertions:** exact `expected.stderr` and `expected.status` (`134` with the hosted handler), plus `expected.stdout` markers proving no user `else`, payload-dependent effect, later sibling, or panic-path defer ran. Cover all four fixed messages and source locations. Include legal remaining variants reaching `else`, valid remapping, and legal `?` failure executing defers, so unconditional panic cannot satisfy the tests.
- **Specification trace:** match/widening tests prove `enums-and-pattern-matching.md`; try/defer tests prove `control-flow-and-operators.md`; unexpected-return tests prove `types-and-primitives.md` and the ordinary-caller part of `functions.md`. This is runtime language conformance, not only MIR shape testing.
- **Optimization/linkage:** compile and execute representative invalid-tag and returning-foreign-call cases at both `-O0` and `-O3` through the existing CLI/codegen options; add a focused harness if the root runner does not expose optimization selection. Use opaque external input so the optimizer cannot replace the test with a constant. Separately compile/link a package with generated checks and the existing hosted/custom panic glue; show that missing glue fails at link with the expected handler symbol and that no compile-time platform enforcement was added. Account for generated panic references in platform fixtures that deliberately link only selected runtime objects; provide minimal test glue where those checks can remain live.
- **Regression commands:** run focused owning-crate tests (`cargo test -p omega-analyzer`, `cargo test -p omega-driver`, `cargo test -p omega-mir`, `cargo test -p omega-codegen`, narrowed initially as appropriate). After artifacts are rebuilt, run the new cases plus `./bin/test-runner t07_enums_and_pattern_matching t27_anonymous_enums t32_try_operator t32b_try_operator_errors t33_panic_handler t33b_panic_handler_errors`. Finish with `just test-all` and `just check-platform` because generated calls affect runtime linkage across targets. Cross-target checks are compile/link evidence only where execution is unavailable; report skips honestly.
